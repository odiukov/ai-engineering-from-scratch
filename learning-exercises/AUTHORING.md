# Как устроен набор упражнений к уроку

Спецификация для того, кто добавляет новый урок. Держись её буквально —
инструменты (`watch.sh`, `compare.py`, `make_template.py`, скилл
`/check-code`) рассчитывают именно на эту раскладку.

## Каталог

```
learning-exercises/pNN-lNN-<slug>/
  solution.py           пишешь руками: docstring + реализация
  test_exercise.py      пишешь руками
  bench.py              пишешь руками: BENCH = {имя функции: кортеж аргументов}
  pytest.ini            копия одной строкой, см. ниже
  exercise.template.py  НЕ пишешь — генерится из solution.py
  exercise.py           НЕ коммитится — личный файл учащегося
```

`<slug>` совпадает с именем каталога урока в `phases/`. Например
`phases/01-math-foundations/06-probability-and-distributions/` даёт
`p01-l06-probability-and-distributions`.

## solution.py

Первая непустая строка docstring модуля — чистый заголовок урока
по-русски, дальше через тире слово «эталон». `make_template.py` режет
именно по этому суффиксу.

```python
"""
Вероятность и распределения — эталон.

Открывай ПОСЛЕ своих зелёных тестов.
"""
```

Дальше 5–8 функций. У каждой — docstring, который целиком уедет в
заготовку, поэтому он пишется для того, кто ещё НЕ решил задачу:

- одна строка что функция делает;
- 2–3 примера `вызов  ->  результат` с реальными числами;
- где уместно — подсказка про ловушку (переполнение, деление на ноль,
  порядок аргументов), но **не решение**;
- где уместно — одна строка зачем это в AI.

Тело функции — рабочий код с комментариями «почему так, а не иначе»:
что ради скорости, что ради читаемости, какая сложность. Эти комментарии в
заготовку не попадают, их учащийся увидит только когда откроет эталон.

Только стандартная библиотека — `math`, `random`, `itertools`. Никаких
numpy: смысл упражнений в том, чтобы собрать руками.

Функции упорядочены по нарастанию, поздние опираются на ранние и вызывают
их, а не копируют формулу заново.

## test_exercise.py

```python
"""Тесты к уроку «<название>». Правь exercise.py."""

import pytest

from exercise import fn_a, fn_b   # импорт из exercise, НЕ из solution

APPROX = lambda x: pytest.approx(x, abs=1e-9)
```

Правила:

- 3–6 тестов на функцию, 15–35 на урок;
- **имя теста называет проверяемое свойство**
  (`test_projection_residual_is_perpendicular`), потому что имя — первая
  подсказка учащемуся, когда тест краснеет;
- проверяй не только арифметику, но и смысловые свойства: что косинус не
  зависит от длины, что матрица ранга 1 склеивает два разных входа, что
  остаток проекции перпендикулярен;
- каждая ловушка из docstring должна иметь свой тест;
- `pytest.approx` **не умеет вложенные списки**. Матрицы сравнивай через
  локальный хелпер `flat(M)`, разворачивающий их в плоский список;
- у углов и всего, что идёт через `acos`, допуск не жёстче `1e-5`.

## bench.py

```python
"""Входные данные для замера скорости."""

import random

random.seed(0)          # обязательно: замер должен быть воспроизводим

_data = [...]

BENCH = {"fn_a": (_data,), "fn_b": (_data, 3)}
```

Размер данных подбирается так, чтобы наивная квадратичная реализация была
заметно медленнее хорошей, но один вызов укладывался в десятки
миллисекунд. Аргументы — всегда кортеж, даже для одного.

## pytest.ini

```ini
[pytest]
addopts = -q --no-header
testpaths = .
```

## Обязательная проверка перед сдачей

```bash
cd learning-exercises/<slug>
cp solution.py exercise.py
python3 -m pytest -q                      # обязано быть 100% зелёным
cd ../.. && python3 learning-exercises/make_template.py <slug>
cp learning-exercises/<slug>/exercise.template.py \
   learning-exercises/<slug>/exercise.py
cd learning-exercises/<slug> && python3 -m pytest -q   # обязано быть красным
```

Оба прогона обязательны. Зелёный на эталоне доказывает, что задача
решаема; красный на заготовке — что учащемуся есть что делать. Набор, не
прошедший обе проверки, не готов.
