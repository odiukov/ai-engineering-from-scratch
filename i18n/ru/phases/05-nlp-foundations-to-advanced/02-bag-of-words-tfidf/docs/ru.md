# Bag of words, TF-IDF и представление текста

> Сначала считай, думай потом. В 2026 году TF-IDF всё ещё обыгрывает embeddings на чётко поставленных задачах.

**Type:** Build
**Languages:** Python

## The Problem

Модели нужны числа. У вас строки.

Любой NLP-конвейер отвечает на один и тот же вопрос. Как превратить поток tokens переменной длины в вектор фиксированного размера, который переварит классификатор. Первый ответ, до которого дошла отрасль, был самым тупым из работающих. Посчитать слова. Сделать вектор.

Этот вектор вытянул на себе больше продакшен-NLP, чем любая модель embeddings. Спам-фильтры, тематические классификаторы, поиск аномалий в логах, ранжирование в поиске (до BM25), первая волна анализа тональности, первое десятилетие академических NLP-бенчмарков. Практики 2026 года по-прежнему хватаются за него первым делом на узких задачах классификации. Он быстрый, интерпретируемый и часто неотличим по качеству от модели embeddings на 400 миллионов параметров — там, где важно само наличие слова.

Этот урок строит bag of words, а затем TF-IDF с нуля. Потом показывает, как то же самое делает scikit-learn в три строки. А потом называет тот способ сломаться, ради которого и приходится идти за embeddings.

> 🎒 **На пальцах.** Bag of words — это как описать книгу списком «сколько раз какое слово встретилось». Порядок теряется полностью: «собака укусила человека» и «человек укусил собаку» дают один и тот же вектор. Звучит как безнадёжная потеря — но для вопроса «это спам?» наличия слов «выигрыш» и «перевод» хватает с запасом.

## The Concept

**Bag of Words (BoW)** выбрасывает порядок. Для каждого документа считаем, сколько раз встретилось каждое слово словаря. Длина вектора равна размеру словаря. Позиция `i` — это счётчик слова `i`.

> 🎒 **На пальцах.** Если словарь состоит из 5 слов, каждый документ становится вектором из 5 чисел — независимо от того, 3 в нём слова или 300. Именно эта фиксированная длина и нужна классификатору: он умеет принимать ровно 5 входов, а не «сколько получится».

**TF-IDF** перевзвешивает BoW. Слово, которое есть в каждом документе, неинформативно — значит, уменьшаем его вес. Слово, редкое по корпусу, но частое в конкретном документе, — это сигнал, значит, вес увеличиваем.

```
TF-IDF(w, d) = TF(w, d) * IDF(w)
             = count(w in d) / |d| * log(N / df(w))
```

Здесь `TF` — частота термина в документе, `df` — документная частота (в скольких документах слово встречается), `N` — общее число документов. Логарифм не даёт весу вездесущих слов уходить в бесконечность.

> 🎒 **На пальцах.** Считаем на пальцах для корпуса из 5 документов. Слово встретилось в 1 документе из 5: IDF = log(5/1) ≈ 1.61. Слово встретилось во всех 5: log(5/5) = 0, вес обнуляется полностью. Слово в 3 документах: log(5/3) ≈ 0.51. Чем шире слово разбрелось по корпусу, тем тише его голос.

Ключевое свойство: оба подхода дают разреженные векторы с интерпретируемыми осями. Можно посмотреть на веса обученного классификатора и прочитать, какие именно слова толкают документ к каждому классу. С 768-мерным embedding от BERT так не выйдет.

> 🎒 **На пальцах.** Интерпретируемость тут буквальная. Обучили спам-фильтр — открыли веса — увидели, что ось «выигрыш» имеет коэффициент +2.3, а ось «отчёт» −1.1. Можно показать это аудитору. В 768-мерном embedding ось номер 412 не значит ничего, что можно произнести словами.

## Build It

### Step 1: build the vocabulary

```python
def build_vocab(docs):
    vocab = {}
    for doc in docs:
        for token in doc:
            if token not in vocab:
                vocab[token] = len(vocab)
    return vocab
```

Вход: список токенизированных документов (подойдёт любой словесный токенизатор; `code/main.py` в этом уроке использует упрощённый вариант с приведением к нижнему регистру). Выход: словарь `{слово: индекс}`. Порядок вставки стабилен, поэтому индекс 0 достаётся первому слову первого документа. Соглашения бывают разные; scikit-learn сортирует по алфавиту.

> 🎒 **На пальцах.** Словарь — это гардеробные номерки. Первое увиденное слово получает номерок 0, второе — 1, и так далее. Для двух документов `[["cat","sat","on","mat"], ["cat","cat","ran"]]` уникальных слов пять, значит номерки от 0 до 4 и длина каждого вектора — 5.

### Step 2: bag of words

```python
def bag_of_words(docs, vocab):
    matrix = [[0] * len(vocab) for _ in docs]
    for i, doc in enumerate(docs):
        for token in doc:
            if token in vocab:
                matrix[i][vocab[token]] += 1
    return matrix
```

```python
>>> docs = [["cat", "sat", "on", "mat"], ["cat", "cat", "ran"]]
>>> vocab = build_vocab(docs)
>>> bag_of_words(docs, vocab)
[[1, 1, 1, 1, 0], [2, 0, 0, 0, 1]]
```

Строки — документы. Столбцы — индексы словаря. Ячейка `[i][j]` отвечает на вопрос «сколько раз слово `j` встретилось в документе `i`». В документе 1 слово `cat` стоит дважды, потому что так и есть. В документе 0 слова `ran` ноль раз, потому что его там нет.

> 🎒 **На пальцах.** Прочитайте вторую строку матрицы вслух: `[2, 0, 0, 0, 1]` — это «cat дважды, sat ноль, on ноль, mat ноль, ran один раз». Заметьте, что документ из 3 слов и документ из 4 слов дали векторы одинаковой длины 5. Из 10 ячеек матрицы 6 — нули; на реальном словаре в 30 000 слов нулей будет 99.9%.

### Step 3: term frequency and document frequency

```python
import math


def term_frequency(doc_bow, doc_length):
    return [c / doc_length if doc_length else 0 for c in doc_bow]


def document_frequency(bow_matrix):
    df = [0] * len(bow_matrix[0])
    for row in bow_matrix:
        for j, count in enumerate(row):
            if count > 0:
                df[j] += 1
    return df


def inverse_document_frequency(df, n_docs):
    return [math.log((n_docs + 1) / (d + 1)) + 1 for d in df]
```

Два приёма сглаживания, которые стоит назвать вслух. Дробь `(n+1)/(d+1)` спасает от `log(x/0)`. Хвостовая `+1` гарантирует, что у слова, встречающегося во всех документах, IDF равен 1, а не 0 — это совпадает с поведением scikit-learn по умолчанию. Другие реализации используют голый `log(N/df)`. Работают оба; сглаженный дружелюбнее.

> 🎒 **На пальцах.** Сравните две формулы на 3 документах и слове, которое есть во всех трёх. Голая формула: log(3/3) = 0 — слово исчезает бесследно. Сглаженная: log(4/4) + 1 = 1 — слово остаётся с весом, равным своей частоте. Разница важна, когда весь документ состоит из частых слов: в первом случае его вектор станет нулевым, и делить на норму будет не на что.

### Step 4: TF-IDF

```python
def tfidf(bow_matrix):
    n_docs = len(bow_matrix)
    df = document_frequency(bow_matrix)
    idf = inverse_document_frequency(df, n_docs)
    out = []
    for row in bow_matrix:
        length = sum(row)
        tf = term_frequency(row, length)
        out.append([tf_j * idf_j for tf_j, idf_j in zip(tf, idf)])
    return out
```

```python
>>> docs = [
...     ["the", "cat", "sat"],
...     ["the", "dog", "sat"],
...     ["the", "cat", "ran"],
... ]
>>> vocab = build_vocab(docs)
>>> bow = bag_of_words(docs, vocab)
>>> tfidf(bow)
```

Три документа, пять слов словаря (`the`, `cat`, `sat`, `dog`, `ran`). `the` есть во всех трёх, поэтому его IDF низкий. `dog` есть в одном, поэтому его IDF высокий. Векторы разреженные (большинство значений мелкие), а различающие слова выпирают.

> 🎒 **На пальцах.** Посчитаем вручную по сглаженной формуле. `the`: df = 3, IDF = log(4/4) + 1 = 1.00. `cat`: df = 2, IDF = log(4/3) + 1 ≈ 1.29. `dog`: df = 1, IDF = log(4/2) + 1 ≈ 1.69. В документе «the dog sat» каждое слово встречается 1 раз при длине 3, то есть TF = 0.333 у всех. Итог: `the` получает 0.333, а `dog` — 0.564. Одна и та же частота, вес почти вдвое больше — ровно потому, что `dog` редкий.

### Step 5: L2-normalize rows

```python
def l2_normalize(matrix):
    out = []
    for row in matrix:
        norm = math.sqrt(sum(x * x for x in row))
        out.append([x / norm if norm else 0 for x in row])
    return out
```

Без нормализации длинный документ получает вектор большей длины и начинает доминировать в оценках похожести. L2-нормализация загоняет каждый документ на единичную гиперсферу. Косинусная близость между строками теперь — просто скалярное произведение.

> 🎒 **На пальцах.** Возьмите строку `[0.333, 0.333, 0.333, 0, 0]`. Её норма = √(0.333² × 3) = √0.333 ≈ 0.577. Делим каждое число на 0.577 и получаем `[0.577, 0.577, 0.577, 0, 0]` с длиной ровно 1. Теперь документ из 3 слов и документ из 300 слов лежат на одной сфере, и сравнивать их честно. Косинусная близость: 1 — направления совпали, 0 — общих слов нет.

## Use It

scikit-learn поставляет боевую версию.

```python
from sklearn.feature_extraction.text import CountVectorizer, TfidfVectorizer

docs = ["the cat sat on the mat", "the dog sat on the mat", "the cat ran"]

bow_vectorizer = CountVectorizer()
bow = bow_vectorizer.fit_transform(docs)
print(bow_vectorizer.get_feature_names_out())
print(bow.toarray())

tfidf_vectorizer = TfidfVectorizer()
tfidf = tfidf_vectorizer.fit_transform(docs)
print(tfidf.toarray().round(3))
```

`CountVectorizer` за один вызов делает и токенизацию, и словарь, и BoW. `TfidfVectorizer` добавляет взвешивание по IDF и L2-нормализацию. Оба возвращают разреженные матрицы. Для 100 тысяч документов плотная версия в память не влезет; держите разреженность до последнего, пока классификатор не потребует плотную.

> 🎒 **На пальцах.** Прикиньте память. 100 000 документов на словаре в 50 000 слов — это 5 миллиардов ячеек, по 8 байт каждая, то есть 40 гигабайт в плотном виде. Но реально заполнено около 0.1% ячеек, поэтому разреженное хранение съест десятки мегабайт. Один вызов `.toarray()` не в том месте — и процесс убивает OOM.

Ручки, которые меняют всё:

| Arg | Effect |
|-----|--------|
| `ngram_range=(1, 2)` | Добавить биграммы. Обычно поднимает качество классификации. |
| `min_df=2` | Выбросить слова, встречающиеся менее чем в 2 документах. Подрезает словарь на шумных данных. |
| `max_df=0.95` | Выбросить слова, встречающиеся более чем в 95% документов. Приближённо заменяет удаление stop words без жёсткого списка. |
| `stop_words="english"` | Встроенный список stop words из scikit-learn. Зависит от задачи — анализ тональности отрицания выбрасывать *не должен*. |
| `sublinear_tf=True` | Использовать `1 + log(tf)` вместо голого `tf`. Помогает, когда термин повторяется в одном документе много раз. |

> 🎒 **На пальцах.** `ngram_range=(1, 2)` кажется мелочью, но словарь от неё раздувается в 5-20 раз: к 50 000 одиночных слов добавляются сотни тысяч пар. Зато появляется признак `not good` как единая ось — именно та, которой BoW из одиночных слов катастрофически не хватает. `min_df=2` тут же вычищает биграммы-однодневки и возвращает словарь к вменяемому размеру.

### When TF-IDF still wins (as of 2026)

- Детекция спама, разметка тем, флаги аномалий в логах. Важно наличие слова, а не смысловые оттенки.
- Мало данных (сотни размеченных примеров). У связки TF-IDF плюс логистическая регрессия нет стоимости предобучения.
- Везде, где важна задержка. TF-IDF плюс линейная модель отвечают за микросекунды. Прогон документа через трансформер стоит 10-100 мс.
- Системы, обязанные объяснять свои предсказания. Смотрим коэффициенты классификатора. Топ положительных слов и есть причина.

> 🎒 **На пальцах.** Разрыв по задержке измеряется не процентами, а порядками. 10 мс против 10 микросекунд — это в 1000 раз. Если ваш сервис обрабатывает 5000 запросов в секунду, TF-IDF уложится в один процессор, а трансформеру понадобится ферма с GPU. Иногда «старый метод» выигрывает не точностью, а счётом за электричество.

### When TF-IDF fails

Слепота к смыслу. Возьмите два документа:

- "The movie was not good at all."
- "The movie was excellent."

Один отзыв отрицательный. Второй положительный. Их пересечение по TF-IDF — ровно `{the, movie, was}`. Классификатор на bag of words вынужден запомнить, что слово `not` рядом с `good` переворачивает метку. Он может этому научиться при достаточных данных, но никогда так изящно, как модель, понимающая синтаксис.

> 🎒 **На пальцах.** Пересчитайте пересечение: 3 общих слова из 7 и 4 соответственно — и все 3 общих слова абсолютно бесполезны, потому что `the`, `movie`, `was` есть в каждом отзыве и их IDF почти нулевой. Различающих слов у одного `not`, `good`, `at`, `all`, у другого `excellent`. Модель обязана сама догадаться, что `not` управляет `good`, хотя между ними в векторе нет никакой связи вообще.

Второй способ сломаться: слова вне словаря на инференсе. Модель BoW, обученная на отзывах IMDb, понятия не имеет, что делать с `Zoomer-approved`, если этот token не встречался при обучении. Subword-embeddings (урок 04) с этим справляются. TF-IDF — нет.

> 🎒 **На пальцах.** Словарь фиксируется в момент `fit` и после этого не растёт. Пришло новое слово — оно просто выпадает из вектора, как будто его не было. Отзыв «Zoomer-approved masterpiece» из 3 слов превращается в вектор с одним ненулевым числом. Двух третей сигнала как не бывало.

### Hybrid: TF-IDF weighted embeddings

Прагматичный дефолт 2026 года для классификации на средних данных: использовать веса TF-IDF как внимание поверх word embeddings.

```python
def tfidf_weighted_embedding(doc, tfidf_scores, embedding_table, dim):
    vec = [0.0] * dim
    total_weight = 0.0
    for token in doc:
        if token not in embedding_table or token not in tfidf_scores:
            continue
        weight = tfidf_scores[token]
        emb = embedding_table[token]
        for i in range(dim):
            vec[i] += weight * emb[i]
        total_weight += weight
    if total_weight == 0:
        return vec
    return [v / total_weight for v in vec]
```

Смысловая ёмкость берётся из embeddings, акцент на редких словах — из TF-IDF. Классификатор учится на усреднённом векторе. На тональности, темах и намерениях эта связка обгоняет каждый из подходов по отдельности примерно до 50 тысяч размеченных примеров.

> 🎒 **На пальцах.** Обычное усреднение embeddings даёт каждому слову вес 1: в отзыве «the movie was excellent» слово `the` тянет ровно столько же, сколько `excellent`. Здесь `the` приходит с весом около 1.0, а `excellent` — около 1.69, то есть влияет почти вдвое сильнее. Деление на `total_weight` в конце возвращает результат к масштабу обычного среднего.

## Key Terms

| Term | What people say | What it actually means |
|------|-----------------|-----------------------|
| BoW | «Вектор частот слов» | Счётчики слов словаря в одном документе. Порядок выбрасывается. |
| TF | «Частота термина» | Сколько раз слово встретилось в документе, при желании поделённое на длину документа. |
| DF | «Документная частота» | Число документов, где слово встречается хотя бы раз. |
| IDF | «Обратная документная частота» | Сглаженный `log(N / df)`. Занижает вес слов, которые есть везде. |
| Sparse vector | «Почти одни нули» | Словарь обычно на 10-100 тысяч слов; в любом отдельном документе почти всех их нет. |
| Cosine similarity | «Угол между векторами» | Скалярное произведение L2-нормализованных векторов. 1 — совпадают, 0 — ортогональны. |
