# Библиотеки навыков и обучение длиною в жизнь (Voyager)

> Voyager (Wang et al., TMLR 2024) считает навыком исполняемый код. У навыков есть имена, их можно находить, складывать друг с друга и дорабатывать по обратной связи от среды. Это референсная архитектура для навыков Claude Agent SDK, для skillkit и для всего паттерна «библиотека навыков» образца 2026 года.

**Type:** Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 07 (MemGPT), Phase 14 · 08 (Letta Blocks)
**Time:** ~75 minutes

## Learning Objectives

- Назвать три компонента Voyager — автоматическую программу обучения, библиотеку навыков, итеративный промптинг — и роль каждого.
- Объяснить, почему Voyager делает пространством действий код, а не примитивные команды.
- Реализовать библиотеку навыков на стандартной библиотеке: регистрация, поиск, композиция и доработка по ошибкам.
- Переложить паттерн Voyager на навыки Claude Agent SDK 2026 года и экосистему skillkit.

## The Problem

Агенты, которые в каждой сессии собирают каждую способность с нуля, делают три вещи неправильно:

1. **Waste tokens.** Каждая задача заново вытягивает из модели одно и то же рассуждение.
2. **Lose progress.** Поправка, выученная в сессии A, не переезжает в сессию B.
3. **Fail on long-horizon composition.** Сложным задачам нужны иерархии способностей; одним промптом их не выразить.

Ответ Voyager: считать каждую переиспользуемую способность именованным куском кода, который лежит в библиотеке, находится по похожести, складывается с другими навыками и дорабатывается по обратной связи от запуска.

> 🎒 **На пальцах.** Прикиньте цену пункта 1 в токенах. Если объяснение «как правильно писать миграцию» занимает 1 500 токенов и всплывает в каждой из 20 сессий за неделю — это 30 000 токенов за одно и то же рассуждение. Записать один раз в файл — как записать рецепт вместо того, чтобы каждый раз звонить бабушке.

## The Concept

### Three components

Voyager (arXiv:2305.16291) строит агента вокруг трёх штук:

1. **Automatic curriculum.** Движимый любопытством генератор выбирает следующую задачу, глядя на текущий набор навыков агента и состояние среды. Исследование идёт снизу вверх.
2. **Skill library.** Каждый навык — это исполняемый код. Новый навык добавляется, когда задача удалась. Навыки находятся по похожести запроса на описание.
3. **Iterative prompting mechanism.** При провале агент получает ошибки исполнения, обратную связь от среды и результат самопроверки, а затем переписывает навык.

Замер в Minecraft (Wang et al., 2024): в 3,3 раза больше уникальных предметов, в 8,5 раза быстрее каменные инструменты, в 6,4 раза быстрее железные, в 2,3 раза дальше проход по карте, чем у базовых решений. Цифры именно про Minecraft, но паттерн переносится.

> 🎒 **На пальцах.** Разложите три компонента по вопросам: curriculum спрашивает «что делать дальше», skill library — «что я уже умею», iterative prompting — «что делать, когда не вышло». Уберите любой — и агент либо топчется на месте, либо забывает, либо ломается на первой ошибке.

### Action space = code

Большинство агентов выдаёт примитивные команды. Voyager выдаёт функции на JavaScript. Навык выглядит так:

```
async function craftIronPickaxe(bot) {
  await mineIron(bot, 3);
  await mineStick(bot, 2);
  await placeCraftingTable(bot);
  await craft(bot, 'iron_pickaxe');
}
```

Собран из подчинённых навыков. Хранится с ключом по описанию и эмбеддингу. Достаётся как программа, а не как промпт.

Это и есть навык Claude Agent SDK 2026 года: именованный кусок кода плюс инструкции, которые агент подгружает по требованию.

> 🎒 **На пальцах.** Посчитайте вызовы в блоке выше: `craftIronPickaxe` — это четыре строки, за которыми стоят четыре уже отлаженных навыка. Примитивными командами тот же результат — это десятки шагов «подойди, копни, положи». Один навык поверх четырёх — как макрос в редакторе: нажали одну кнопку, отработало двадцать действий.

### Skill retrieval

Новая задача: «сделать алмазную кирку». Агент:

1. Считает эмбеддинг описания задачи.
2. Спрашивает у библиотеки навыков top-k похожих.
3. Достаёт `craftIronPickaxe`, `mineDiamond`, `placeCraftingTable` и прочее.
4. Собирает новый навык из найденных примитивов плюс новая логика.

Именно этот паттерн реализуют ресурсы MCP (Phase 13) и навыки Agent SDK: поиск по поверхности знаний или кода, суженный до текущей задачи.

> 🎒 **На пальцах.** Ключевое слово в шаге 2 — top-k. Библиотека может содержать 300 навыков, но в промпт уедут только три-пять самых похожих. Это как поиск по кулинарной книге: вы не читаете все 300 рецептов, вы находите три про кирку и смотрите только их.

### Iterative refinement

Цикл обратной связи Voyager:

1. Агент пишет навык.
2. Навык запускается в среде.
3. Возвращается один из трёх сигналов: `success`, `error` (со стек-трейсом), `self-verification failure`.
4. Агент переписывает навык, используя сигнал как контекст.
5. Цикл повторяется до успеха или до лимита раундов.

Это Self-Refine (Lesson 05), приложенный к генерации кода с проверкой, заземлённой на среде. CRITIC (Lesson 05) — тот же паттерн, только проверяющим выступают внешние инструменты.

> 🎒 **На пальцах.** Обратите внимание, что сигналов ровно три, а не «получилось / не получилось». `error` даёт стек-трейс — модель видит, какая строка упала. `self-verification failure` значит «код отработал, но результат не тот». Первое чинится точечно, второе требует переписать логику; смешивать их в одно «не вышло» — терять половину информации.

### Curriculum and exploration

Модуль программы обучения в Voyager предлагает задачи вида «построй укрытие у озера», исходя из того, что у агента уже есть и чего он ещё не делал. Генератор смотрит на состояние среды плюс инвентарь навыков и берёт задачу чуть выше текущего уровня — это и есть золотая середина исследования.

Для продакшен-агентов это превращается в оператор «чего не хватает»: с учётом текущей библиотеки навыков и предметной области — какие навыки мы ещё не покрыли? Команды обычно делают это руками, в формате ревью программы обучения.

> 🎒 **На пальцах.** «Чуть выше текущего уровня» — это про сложность в самую точку. Задача из уже освоенного не даёт новых навыков, задача на десять шагов вперёд провалится и ничему не научит. Как в спортзале: вес берут такой, чтобы последнее повторение давалось с трудом, а не тот, который вообще не поднимается.

### Where this pattern goes wrong

- **Skill library rot.** Один и тот же навык добавлен 10 раз с чуть разными описаниями. Добавьте дедупликацию при записи; поиск должен возвращать только один.
- **Composed-skill drift.** Родительский навык зависит от дочернего, а дочерний переписали. Версионируйте навыки: родитель, прибитый к v1, не должен волшебно подхватить v3.
- **Retrieval quality.** Векторный поиск по описаниям навыков вырождается, когда библиотека переваливает за пару сотен. Подпирайте фильтрами по тегам и жёсткими ограничениями («только навыки с `category=tooling`»).

```figure
voyager-skills
```

> 🎒 **На пальцах.** Второй пункт — самая коварная беда. Вы улучшили дочерний навык, все тесты дочернего зелёные, а десяток родительских навыков тихо начали вести себя иначе. Как поменять размер шестерёнки в середине механизма: сама шестерёнка идеальна, а часы врут.

## Build It

`code/main.py` реализует библиотеку навыков на стандартной библиотеке:

- `Skill` — имя, описание, код (строкой), версия, теги, зависимости.
- `SkillLibrary` — регистрация, поиск (по пересечению токенов), композиция (топологическая сортировка зависимостей) и доработка (поднятие версии при обновлении).
- Сценарный агент, который регистрирует три примитивных навыка, собирает из них четвёртый, натыкается на провал и дорабатывает.

Запуск:

```
python3 code/main.py
```

В логе видно записи в библиотеку, поиск, композицию, упавший запуск и доработку до v2 — весь цикл Voyager от начала до конца.

> 🎒 **На пальцах.** Заметьте, что поиск тут по пересечению токенов, а не по эмбеддингам. На трёх навыках разницы вы не увидите: запрос «craft iron pickaxe» и так найдёт `craftIronPickaxe` по общим словам. Эмбеддинги начинают выигрывать, когда запрос звучит «нужен инструмент покрепче» — общих слов нет вообще.

## Use It

- **Claude Agent SDK skills** (Anthropic) — референс 2026 года: у каждого навыка есть описание, код и инструкции; грузится по требованию в ходе сессии агента.
- **skillkit** (npm: skillkit) — управление навыками сразу для 32+ ИИ-агентов для кода.
- **Custom skill libraries** — предметные библиотеки (SQL-навыки для дата-агентов, Terraform-навыки для инфраструктурных). Паттерн Voyager хорошо масштабируется вниз.
- **OpenAI Agents SDK `tools`** — самый нижний уровень; каждый инструмент — это навык-малютка.

> 🎒 **На пальцах.** Последний пункт полезно проговорить: инструмент — это навык из одного шага. Как только вам понадобилось «сначала дёрни этот инструмент, потом тот, а если пусто — третий», у вас на руках навык, и хранить его надо отдельно от инструментов.

## Ship It

`outputs/skill-skill-library.md` генерирует библиотеку навыков в форме Voyager: регистрация, поиск, версионирование и доработка сразу подключены, под любой целевой рантайм.

> 🎒 **На пальцах.** Обратите внимание на слова «под любой целевой рантайм». Четыре механизма — регистрация, поиск, версии, доработка — не зависят от того, где живёт агент. Это как каркас полки: одна и та же конструкция подойдёт и для книг, и для инструментов.

## Exercises

1. Добавьте в `compose()` детектор циклов в зависимостях. Что произойдёт, если навык A зависит от B, а B от A? Ошибка или предупреждение?
2. Реализуйте прибивание версий по каждому навыку. Когда родительский навык собран из дочернего `crafting@1`, доработка до `crafting@2` не должна молча обновить родителя.
3. Замените поиск по пересечению токенов на эмбеддинги sentence-transformers (или на BM25 средствами стандартной библиотеки). Измерьте retrieval@5 на игрушечной библиотеке из 50 навыков.
4. Добавьте агента-«программу обучения»: по текущей библиотеке и описанию предметной области он предлагает 5 недостающих навыков. Зовите его раз в неделю.
5. Прочитайте документацию по навыкам Claude Agent SDK. Перенесите игрушечную библиотеку на схему навыков SDK. Что изменится в обнаружимости?

> 🎒 **На пальцах.** Третье задание меряет то, что обычно обсуждают на глазок. retrieval@5 на 50 навыках — это простой вопрос: попал ли нужный навык в первую пятёрку? Пересечение токенов обычно даёт около 0,6, эмбеддинги — около 0,9; на 50 навыках это разница между «каждый третий поиск мимо» и «почти всегда в цель».

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Skill | «Переиспользуемая способность» | Именованный кусок кода плюс описание, находится по похожести |
| Skill library | «Память агента о том, как делать» | Долговременное хранилище навыков с поиском и композицией |
| Curriculum | «Генератор задач» | Постановщик целей снизу вверх, движимый текущим пробелом в способностях |
| Composition | «DAG навыков» | Навыки вызывают навыки; перед запуском сортируются топологически |
| Iterative refinement | «Самоисправляющийся цикл» | Обратная связь среды, ошибки и самопроверка заворачиваются в следующую версию |
| Action-space-as-code | «Программные действия» | Выдавать функции, а не примитивные команды, ради растянутого во времени поведения |
| Dedup on write | «Схлопывание навыков» | Почти одинаковые описания сводятся к одному каноническому навыку |

> 🎒 **На пальцах.** Сравните первые две строки таблицы. Skill — это один файл, Skill library — это папка плюс поиск по ней. Без второго первое превращается в свалку: 200 навыков без поиска ничем не лучше нуля навыков, потому что агент их просто не найдёт.
