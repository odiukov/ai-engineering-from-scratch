# Харнесс как библиотека — субагенты и хранилище сессий

> Харнесс, который можно импортировать: встроенные инструменты, субагенты для изоляции контекста, хуки, передача трассы по W3C, сохранение сессий. Claude Agent SDK — образцовый пример: это харнесс Claude Code в виде библиотеки. А Claude Managed Agents — хостируемая альтернатива для долгой асинхронной работы.

**Type:** Learn + Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 01 (Agent Loop), Phase 14 · 10 (Skill Libraries)
**Time:** ~75 minutes

## Learning Objectives

- Объяснить разницу между Anthropic Client SDK (сырое API) и Claude Agent SDK (форма харнесса).
- Описать субагентов — распараллеливание и изоляцию контекста — и понимать, когда за ними тянуться.
- Назвать поверхность хранилища сессий в Python SDK (`append`, `load`, `list_sessions`, `delete`, `list_subkeys`) и роль `--session-mirror`.
- Собрать харнесс на стандартной библиотеке со встроенными инструментами, запуском субагентов с изолированным контекстом, хуками жизненного цикла и хранилищем сессий.

## The Problem

Сырое API языковой модели даёт вам один запрос-ответ. Продакшен-агенту нужны выполнение инструментов, MCP-серверы, хуки жизненного цикла, запуск субагентов, сохранение сессий, передача трассы. Claude Agent SDK отдаёт всю эту форму библиотекой — тот же харнесс, на котором работает Claude Code, только открытый для ваших собственных агентов.

> 🎒 **На пальцах.** Сырое API — это как один телефонный звонок: спросили, получили ответ, положили трубку. Харнесс — это уже офис вокруг телефона: картотека, папки с файлами, помощники, журнал звонков. Agent SDK продаёт вам офис, а не телефон.

## The Concept

### Client SDK vs Agent SDK

- **Client SDK (`anthropic`).** Сырое Messages API. Цикл, инструменты и состояние — на вас.
- **Agent SDK (`claude-agent-sdk`).** Встроенное выполнение инструментов, подключения к MCP, хуки, запуск субагентов, хранилище сессий. Цикл Claude Code в виде библиотеки.

> 🎒 **На пальцах.** Разница измеряется строками кода: цикл агента с инструментами на клиентском SDK — это 150-300 строк, которые вы будете отлаживать неделю. На Agent SDK те же возможности — это конфиг и несколько вызовов. Платите вы тем, что цикл теперь чужой и правится не так, как вам хочется.

### Built-in tools

SDK приносит из коробки 10+ инструментов: чтение и запись файлов, шелл, grep, glob, загрузка веб-страниц и другие. Свои инструменты регистрируются через стандартный интерфейс схемы инструмента.

> 🎒 **На пальцах.** Это те самые десять инструментов, которые вы бы всё равно написали первыми в любом кодовом агенте. Каждый из них — это не только функция, но и описание схемы, обработка ошибок и защита от выхода за пределы каталога. Готовый `read_file` экономит не десять строк, а полдня возни с граничными случаями.

### Subagents

Anthropic описывает две задачи субагентов:

1. **Parallelization.** Выполнять независимую работу одновременно. «Найди тестовый файл для каждого из этих 20 модулей» — это 20 параллельных задач субагентам.
2. **Context isolation.** У субагента своё окно контекста; оркестратору возвращается только результат. Бюджет оркестратора остаётся целым.

Недавние добавления в Python SDK: `list_subagents()` и `get_subagent_messages()` для чтения стенограмм субагентов.

> 🎒 **На пальцах.** Посчитайте вторую задачу на цифрах. Каждый из 20 поисков прочитает по 3 000 токенов мусора — это 60 000 токенов, а окно у оркестратора всё равно кончится. С субагентами оркестратор получает 20 строк по 30 токенов, то есть 600 вместо 60 000. Это как отправить 20 помощников в архив и получить от каждого записку, а не 20 коробок с документами.

### Session store

Паритет протокола с TypeScript:

- `append(session_id, message)` — добавить ход.
- `load(session_id)` — восстановить диалог.
- `list_sessions()` — перечислить сессии.
- `delete(session_id)` — с каскадным удалением сессий субагентов.
- `list_subkeys(session_id)` — перечислить ключи субагентов.

`--session-mirror` (флаг CLI) зеркалит стенограмму во внешний файл прямо по ходу стриминга — удобно для отладки.

> 🎒 **На пальцах.** Обратите внимание на слово «каскадным» у `delete`: у сессии есть дети, и без каскада вы удалите родителя, а стенограммы субагентов останутся в базе сиротами. Как удаление папки, которое не забывает про вложенные файлы.

### Hooks

Хуки жизненного цикла, которые можно зарегистрировать:

- `PreToolUse`, `PostToolUse` — пропускать или аудировать вызовы инструментов.
- `SessionStart`, `SessionEnd` — подготовка и уборка.
- `UserPromptSubmit` — вмешаться во ввод пользователя до того, как его увидит модель.
- `PreCompact` — сработать перед сжатием контекста.
- `Stop` — уборка при выходе агента.
- `Notification` — оповещения по побочному каналу.

Хуки — это то, чем pro-workflow (см. учебный план Phase 14) и похожие системы добавляют сквозное поведение.

> 🎒 **На пальцах.** Хук `PreToolUse` — самый ценный из списка: это единственная точка, где вы можете сказать «нет» до того, как агент выполнит `rm -rf`. Все остальные хуки — про удобство, а этот про безопасность. Как предохранитель на станке: он не делает работу, он не даёт отрезать палец.

### W3C trace context

Спаны OTel, активные на стороне вызывающего кода, доезжают в подпроцесс CLI через заголовки W3C trace context. Вся многопроцессная трасса собирается в вашем бэкенде в одну трассу.

> 🎒 **На пальцах.** Без этого вы получите две несвязанные трассы: одна от своего сервиса, другая от CLI, и склеивать их придётся по времени на глазок. Заголовок W3C — это просто строка с идентификатором родителя, которая едет через границу процесса, как номер накладной при передаче груза.

### Claude Managed Agents

Хостируемая альтернатива (бета-заголовок `managed-agents-2026-04-01`). Долгая асинхронная работа, встроенное кэширование промптов, встроенное сжатие контекста. Меняете контроль на управляемую инфраструктуру.

> 🎒 **На пальцах.** Слово «долгая» тут важно: если агент работает 40 минут, ваш собственный процесс должен эти 40 минут жить, не падать и не терять состояние. У хостируемого варианта эта проблема чужая. Как своя котельная против центрального отопления: своя гибче, но чинить её вам.

### Where this pattern goes wrong

- **Subagent over-spawn.** Запуск 100 субагентов на 100 крошечных задач. Накладные расходы съедают весь выигрыш. Группируйте задачи.
- **Hook creep.** Каждая команда добавляет свои хуки, время старта распухает. Пересматривайте хуки раз в квартал.
- **Session bloat.** Сессии накапливаются, объём растёт. Пользуйтесь `list_sessions` плюс политикой устаревания.

```figure
ae-subagent-isolation
```

> 🎒 **На пальцах.** Прикиньте первый пункт: запуск субагента стоит своего системного промпта — скажем, 1 500 токенов. Для задачи на 50 токенов это 30-кратные накладные. Сто таких задач в пяти субагентах по двадцать штук — 7 500 токенов вместо 150 000.

## Build It

`code/main.py` воспроизводит форму SDK на стандартной библиотеке:

- `Tool`, `ToolRegistry` со встроенными `read_file`, `write_file`, `list_dir`.
- `Subagent` — приватный контекст, изолированный прогон, возврат результатов.
- `SessionStore` — операции append, load, list, delete, list_subkeys.
- `Hooks` — `pre_tool_use`, `post_tool_use`, `session_start`, `session_end`.
- Демо: главный агент запускает 3 субагента параллельно (каждый изолирован), собирает результаты, сохраняет сессию.

Запуск:

```
python3 code/main.py
```

Трасса показывает изоляцию контекста субагентов (размер контекста оркестратора остаётся ограниченным), срабатывание хуков и сохранение сессии.

> 🎒 **На пальцах.** Главное, за чем стоит следить в выводе, — размер контекста оркестратора. Три субагента отработали, каждый прочитал свои файлы, а у оркестратора выросло всего на три строки. Именно эта цифра и есть весь смысл субагентов.

## Use It

- **Claude Agent SDK** — для продуктов вокруг Claude, которым нужна форма харнесса Claude Code.
- **Claude Managed Agents** — для хостируемой долгой асинхронной работы.
- **OpenAI Agents SDK** (Lesson 16) — тот же подход в исполнении OpenAI.
- **LangGraph + custom tools** — если вместо харнесса вам нужен конечный автомат в форме графа.

> 🎒 **На пальцах.** Разница между первой и четвёртой строкой — это разница между «дай мне рабочего агента» и «дай мне управлять переходами». Agent SDK решает, что делать дальше, силами модели. LangGraph заставляет вас нарисовать это заранее. Выбирайте по тому, насколько предсказуемым обязан быть прогон.

## Exercises

1. Напишите запускатор субагентов, который разбивает 20 задач на группы по 5 параллельных субагентов. Замерьте размер контекста оркестратора против варианта «по субагенту на задачу».
2. Реализуйте хук `PreToolUse`, который ограничивает частоту вызовов `write_file` (5 в минуту на сессию). Проследите поведение по трассе.
3. Подключите `list_subkeys`, чтобы нарисовать дерево субагентов. Как выглядит глубокая вложенность?
4. Перенесите игрушку на настоящий пакет `claude-agent-sdk` для Python. Что меняется в регистрации инструментов?
5. Прочитайте документацию Claude Managed Agents. В какой момент вы бы перешли со своего хостинга на управляемый?

> 🎒 **На пальцах.** Второе задание учит главному приёму защиты. Лимит «5 записей в минуту» не мешает нормальному агенту, зато мгновенно останавливает того, кто вошёл в цикл и пишет один и тот же файл двести раз. Это как ограничитель скорости: обычной езде не мешает, а от заноса спасает.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Agent SDK | «Claude Code как библиотека» | Форма харнесса: инструменты, MCP, хуки, субагенты, хранилище сессий |
| Subagent | «Дочерний агент» | Отдельный контекст, свой бюджет; наверх всплывают только результаты |
| Session store | «База диалогов» | Сохранять, загружать, перечислять и удалять ходы с каскадом на субагентов |
| Hook | «Колбэк жизненного цикла» | До и после инструмента, сессия, отправка промпта, сжатие, остановка |
| W3C trace context | «Трасса через процессы» | Родительский спан доезжает в подпроцесс CLI |
| Managed Agents | «Хостируемый харнесс» | Долгая асинхронная работа на инфраструктуре Anthropic |
| `--session-mirror` | «Зеркало стенограммы» | Пишет ходы сессии во внешний файл по мере стриминга |
| MCP server | «Поверхность инструментов» | Внешний источник инструментов и ресурсов, подключённый к агенту |

> 🎒 **На пальцах.** Сравните строки Subagent и Hook: это два разных ответа на слово «контроль». Субагент ограничивает, сколько агент видит. Хук ограничивает, что агент может сделать. Первое про токены, второе про безопасность, и путать их дорого.
