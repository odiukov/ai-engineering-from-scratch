# Планирование через HTN и эволюционный поиск

> Символьное планирование берёт случаи, где план должен быть доказуемо верным. Эволюционный поиск по коду берёт случаи, где функцию приспособленности можно проверить машиной. ChatHTN (2025) и AlphaEvolve (2025) показывают, что даёт каждый из подходов в паре с LLM.

**Type:** Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 14 · 02 (ReWOO and Plan-and-Execute)
**Time:** ~75 minutes

## Learning Objectives

- Объяснить иерархические сети задач: задачи, методы, операторы, предусловия, эффекты.
- Описать гибридный цикл ChatHTN — символьный поиск с декомпозицией через LLM как аварийный вариант.
- Объяснить эволюционный цикл AlphaEvolve и почему он работает только с программным оценщиком.
- Реализовать игрушечный HTN-планировщик и игрушечный эволюционный поиск на стандартной библиотеке.

## The Problem

ReWOO (Lesson 02), Plan-and-Execute и ReAct закрывают большую часть агентного планирования. Два случая они закрывают плохо:

1. **Plans with provable correctness.** Расписания, прокладка маршрутов самолётов, комплаенс-процессы — план обязан быть корректным по построению. Гладкий план от LLM, который иногда галлюцинирует шаг, тут не годится.
2. **Optimizations with a machine-checkable fitness function.** Умножение матриц, эвристики планирования, проходы компилятора — цель не «верный план», а «лучший план».

HTN-планирование и AlphaEvolve решают две разные задачи. И то и другое использует LLM как усилитель, а не как замену.

> 🎒 **На пальцах.** Разница между двумя пунктами — это разница между «нельзя ошибиться» и «хочется получше». В расписании смен один нарушенный запрет — уже брак, сколько бы всё остальное ни было хорошо. В оптимизации компилятора любой рабочий вариант годится, вопрос лишь в том, насколько он быстрый.

## The Concept

### Hierarchical Task Networks

HTN — это:

- **Tasks** — составные (их надо разложить) и примитивные (их можно выполнить напрямую).
- **Methods** — способы разложить составную задачу на подзадачи, с предусловиями.
- **Operators** — примитивные действия с предусловиями и эффектами.
- **State** — набор фактов.

Планирование: имея целевую задачу и начальное состояние, найти такое разложение на примитивные операторы, чтобы предусловия каждого выполнялись по порядку.

HTN старше языковых моделей и до сих пор остаётся эталоном для доказуемо верных планов.

> 🎒 **На пальцах.** Четыре понятия проще увидеть на кухне. Task — «приготовить ужин», method — «ужин = сварить макароны плюс сделать соус», operator — «включить плиту» с предусловием «плита свободна» и эффектом «плита горит», state — что сейчас есть в холодильнике. Планировщик просто разворачивает первое в третье, пока не останется одних конкретных действий.

### ChatHTN (Gopalakrishnan et al., 2025)

ChatHTN (arXiv:2505.11814) перемежает символьный HTN с запросами к LLM:

1. Попробовать разложить текущую составную задачу имеющимися методами.
2. Если ни один метод не подошёл, спросить у LLM: «как бы ты разложил `task` в состоянии `s`?»
3. Перевести ответ LLM в кандидатные подзадачи.
4. Проверить их по схеме операторов; невалидные декомпозиции отбросить.
5. Уйти в рекурсию.

Главное утверждение статьи: любой полученный план доказуемо корректен, потому что подсказки LLM входят только как кандидатные декомпозиции и никогда не правят план напрямую. За корректность отвечает символьный слой; LLM лишь расширяет библиотеку методов.

Онлайновое обучение методам (OpenReview `gwYEDY9j2x`, продолжение 2025 года) добавляет обучаемый компонент, который обобщает выданные LLM декомпозиции регрессией — и урезает частоту обращений к LLM до 75%.

> 🎒 **На пальцах.** Вся хитрость в шаге 4. LLM тут работает как стажёр, который предлагает варианты, а проверяет их строгий инспектор со списком правил. Стажёр может нафантазировать что угодно — в план попадёт только то, что прошло проверку по схеме, поэтому гарантия корректности не страдает.

### AlphaEvolve (Novikov et al., 2025)

AlphaEvolve (arXiv:2506.13131, DeepMind, июнь 2025) — совсем другой зверь: эволюционный поиск по коду, которым дирижирует ансамбль Gemini 2.0 Flash/Pro.

Цикл:

1. Начать с программы-затравки плюс программный оценщик (возвращает балл приспособленности).
2. Ансамбль LLM предлагает мутации.
3. Прогнать мутации через оценщик.
4. Оставить лучшие; мутировать снова.

Опубликованные победы:

- Первое за 56 лет улучшение метода Штрассена для умножения комплексных матриц 4x4 (48 скалярных умножений).
- 0,7% вычислительных мощностей Google, возвращённых благодаря эвристике планирования в Borg.
- Ускорение FlashAttention на 32% на фронтирной нагрузке.

Жёсткое ограничение: функция приспособленности обязана проверяться машиной. Эволюционный поиск по текстовым ответам не сходится.

> 🎒 **На пальцах.** Заметьте, что в цикле нет ни одного места, где кто-то решает «стало лучше» на глазок — это делает шаг 3 числом. Первая строка побед показывает масштаб: 56 лет люди не могли улучшить алгоритм, а поиск с числовой проверкой смог. Как селекция растений: вы не понимаете биохимию, вы просто оставляете те кусты, у которых урожай взвесился больше.

### When to use which

| Problem class | Use | Why |
|---------------|-----|-----|
| Расписание с жёсткими ограничениями | HTN + ChatHTN | Доказуемая корректность |
| Оптимизация компилятора | AlphaEvolve | Приспособленность проверяется машиной |
| Выполнение многошаговой задачи | ReAct / ReWOO | LLM в цикле, формальных гарантий нет |
| Улучшение кода при наличии тестов | AlphaEvolve | Тесты и есть оценщик |
| Автоматизация, ограниченная политиками | HTN | Предусловия кодируют политику |

> 🎒 **На пальцах.** Колонка Why сводится к одному вопросу: чем вы проверяете результат. Есть список запретов — HTN. Есть число или тесты — AlphaEvolve. Нет ни того ни другого — остаётся ReAct, и живите с тем, что гарантий нет. Третья строка честно признаёт это словами «формальных гарантий нет».

### Where this pattern goes wrong

- **HTN without operators.** Без схем предусловий и эффектов утверждение о корректности рассыпается. Формула ChatHTN «LLM предлагает декомпозицию» требует, чтобы схема умела отбрасывать неверные ходы.
- **AlphaEvolve without a real evaluator.** «Спроси у LLM, стало ли лучше» — это не функция приспособленности. Оценщик обязан быть детерминированным и быстрым.
- **Over-engineering.** Большинству агентных задач не нужно ни то ни другое. Сначала тянитесь к ReAct или ReWOO.

```figure
htn-tree-expand
```

> 🎒 **На пальцах.** Слово «детерминированный» во втором пункте не для красоты. Если оценщик на одном и том же коде выдаёт то 0,8, то 0,9, отбор начинает выбирать шум вместо улучшений. Это как взвешивать урожай на весах, которые врут на килограмм: селекция пойдёт, но не туда.

## Build It

`code/main.py` реализует две игрушки:

- HTN-планировщик на стандартной библиотеке: операторы, методы, предусловия, эффекты и `LLMFallback`, который включается, когда ни один метод не подошёл к составной задаче. «LLM» тут — сценарный декомпозер, чтобы планировщик работал офлайн.
- Эволюционный поиск на стандартной библиотеке по арифметическим программам: наращивать выражения, чей результат минимизирует `|f(x) - target|` на тестовом наборе. Оценщик детерминированный.

> 🎒 **На пальцах.** Вторая игрушка — это вся идея AlphaEvolve в миниатюре. Оценщик считает `|f(x) - target|`: у выражения-победителя эта сумма ближе к нулю, у остальных больше. Никакой LLM не нужен, чтобы понять, кто лучше, — достаточно вычитания. Как соревнование по прыжкам: спорить не о чем, рулетка всё показала.

Запуск:

```
python3 code/main.py
```

В логе видно, как HTN-планировщик раскладывает составную задачу (с уходом в LLM-фолбэк посреди плана) и как эволюционный цикл сходится к целевому выражению.

> 🎒 **На пальцах.** Обратите внимание, что «LLM» в этой игрушке — сценарный декомпозер. Это очень полезный приём для учёбы: цикл планировщика вы отлаживаете за секунды и без единого запроса в сеть, а модель подключите потом на готовый каркас. Как учиться водить на пустой парковке.

## Use It

- **HTN planners** — `pyhop`, `SHOP3` или свой собственный, чтобы прошивать политики предметной области.
- **ChatHTN** — исследовательский код; сам паттерн (символьный поиск плюс LLM как фолбэк) чисто переносится на любой HTN-планировщик.
- **AlphaEvolve** — статья DeepMind; паттерн (ансамбль плюс оценщик) воспроизводим. Начинают появляться OpenEvolve и похожие форки с открытым кодом.
- **Agent frameworks** — ни один пока не даёт HTN или AlphaEvolve как первоклассную возможность. Собирайте это как субагента или как фонового воркера.

> 🎒 **На пальцах.** Последний пункт стоит прочитать буквально: готового решения в фреймворках нет, значит писать придётся самому. Хорошая новость в том, что HTN-планировщик — это сотни строк, а не тысячи, и в `code/main.py` он весь перед вами.

## Ship It

`outputs/skill-hybrid-planner.md` генерирует каркас гибридного планировщика (HTN или эволюционного), в котором роль LLM явно ограничена.

> 🎒 **На пальцах.** Слова «роль LLM явно ограничена» — это и есть главный урок этого урока. В ChatHTN модель предлагает, но не утверждает; в AlphaEvolve мутирует, но не оценивает. Право сказать «годится» всегда остаётся у кода.

## Exercises

1. Расширьте HTN-планировщик бэктрекингом: когда постусловие оператора не сработало в рантайме, откатитесь и попробуйте следующий метод.
2. Добавьте в ChatHTN кэш методов от LLM: когда LLM разложила задачу `T` в паттерне состояния `P`, сохраните результат. При следующем вызове сначала проверяйте библиотеку методов.
3. Замените оценщик эволюционного поиска на настоящий набор тестов. Выведите функцию сортировки, проходящую 20 тест-кейсов; отчитайтесь, за сколько поколений сошлось.
4. Прочитайте заметки о проектировании оценщика в AlphaEvolve. Спроектируйте оценщик для интересной вам области (оптимизация SQL-запросов, минимизация тест-сьюта, YAML деплоя).
5. Скомбинируйте: HTN раскладывает составную задачу на подзадачи, а эволюционный поиск улучшает примитивный оператор каждой подзадачи. Где это сияет, а где переусложнение?

> 🎒 **На пальцах.** Второе задание даёт самый быстрый выигрыш. Если из 100 декомпозиций 75 повторяются, кэш убирает 75 запросов к LLM: при цене 2 цента за запрос это 1,5 доллара за прогон и, что важнее, 75 задержек по две секунды. Ровно об этом и статья про онлайновое обучение методам с её «до 75%».

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| HTN | «Иерархический планировщик» | Декомпозиция задач с операторами, предусловиями и эффектами |
| Method | «Правило декомпозиции» | Способ разбить составную задачу на подзадачи |
| Operator | «Примитивное действие» | Конкретный шаг с предусловием и эффектом |
| ChatHTN | «LLM плюс HTN» | Символьный планировщик спрашивает LLM, когда ни один метод не подошёл |
| AlphaEvolve | «Эволюционный поиск по коду» | Ансамбль LLM мутирует код; отбор делает детерминированный оценщик |
| Fitness function | «Оценщик» | Детерминированный, проверяемый машиной балл по выходу |
| Online method learning | «Кэш декомпозиций от LLM» | Сохранять и обобщать планы от LLM, чтобы урезать стоимость запросов |

> 🎒 **На пальцах.** Сравните Method и Operator — это две ступеньки одной лестницы. Method всё ещё абстрактен («ужин = макароны плюс соус»), Operator уже конкретен («включить плиту»). Планировщик спускается по методам, пока не останутся только операторы, — и вот тогда план можно выполнять.
