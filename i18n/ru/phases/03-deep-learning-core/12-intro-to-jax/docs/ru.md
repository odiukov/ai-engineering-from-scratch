# Введение в JAX

> PyTorch меняет тензоры на месте. TensorFlow строит графы. JAX компилирует чистые функции. Последнее меняет само мышление о глубоком обучении.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 03 Lessons 01-10, basic NumPy
**Time:** ~90 minutes

## Learning Objectives

- Писать код нейросетей на чистых функциях с помощью функционального API JAX (jax.numpy, jax.grad, jax.jit, jax.vmap)
- Объяснить ключевое различие между eager-мутациями PyTorch и функциональной моделью компиляции JAX
- Применять jit-компиляцию и векторизацию через vmap для ускорения циклов обучения по сравнению с наивным Python
- Обучить простую сеть на JAX и сравнить явное управление состоянием с объектным подходом PyTorch

> 🎒 **На пальцах.** PyTorch — это «объект помнит свои веса и сам себя правит». JAX — это «функция ничего не помнит, все веса вы передаёте ей руками». Звучит как лишняя работа, но именно за это компилятор платит ускорением в десятки раз. Как рецепт, где все ингредиенты выписаны в начале: по нему можно готовить на любой кухне и в любом количестве.

## The Problem

Вы умеете строить нейросети в PyTorch. Описываете `nn.Module`, вызываете `.backward()`, делаете шаг оптимизатора. Это работает. Так делают миллионы людей.

Но у PyTorch есть ограничение, зашитое в его ДНК: он выполняет операции жадно, по одной, из Python. Каждое `tensor + tensor` — отдельный запуск ядра. Каждый шаг обучения заново интерпретирует один и тот же код Python. Это нормально до тех пор, пока не нужно обучить модель на 540 миллиардов параметров на 2048 TPU. Тогда накладные расходы вас убивают.

Google DeepMind обучает Gemini на JAX. Anthropic обучала Claude на JAX. Это не мелкие эксперименты — это крупнейшие запуски обучения нейросетей на Земле. Они выбрали JAX, потому что он относится к вашему циклу обучения как к компилируемой программе, а не как к последовательности вызовов Python.

JAX — это NumPy с тремя суперспособностями: автоматическое дифференцирование, JIT-компиляция в XLA и автоматическая векторизация. Вы пишете функцию, обрабатывающую один пример. JAX выдаёт вам функцию, которая обрабатывает целый батч, считает градиенты, компилируется в машинный код и работает на нескольких устройствах. И всё это без изменения исходной функции.

> 🎒 **На пальцах.** Представьте кассира, который для каждого товара заново читает инструкцию «как пробить товар». На пяти покупках незаметно, на пяти тысячах — катастрофа. JAX один раз переводит инструкцию в действия и дальше просто их повторяет. При 2048 устройствах эта разница и определяет, обучится модель за месяц или за год.

## The Concept

### The JAX Philosophy

JAX — функциональный фреймворк. Никаких классов, изменяемого состояния и метода `.backward()`. Вместо этого:

| PyTorch | JAX |
|---------|-----|
| Класс `nn.Module` с состоянием | Чистая функция: `f(params, x) -> y` |
| `loss.backward()` | `jax.grad(loss_fn)(params, x, y)` |
| Eager-выполнение | JIT-компиляция через XLA |
| Ручной цикл `for x in batch:` | Автовекторизация `jax.vmap(f)` |
| `DataParallel` / `FSDP` | Автопараллелизм `jax.pmap(f)` |
| Изменяемый `model.parameters()` | Неизменяемый pytree из массивов |

Это не вопрос вкуса. Это требование компилятора. JIT-компиляция требует чистых функций — одни и те же входы всегда дают один и тот же выход, никаких побочных эффектов. Именно это ограничение делает возможным ускорение в 100 раз.

> 🎒 **На пальцах.** «Чистая функция» — как автомат с газировкой: бросил ту же монету, нажал ту же кнопку, получил ту же газировку. Никакой памяти о прошлых покупателях, никакого настроения. Компилятор может изучить такой автомат один раз и дальше не проверять его каждый раз заново — отсюда и обещанные 100 раз.

### jax.numpy: The Familiar Surface

JAX переписывает API NumPy для ускорителей:

```python
import jax.numpy as jnp

a = jnp.array([1.0, 2.0, 3.0])
b = jnp.array([4.0, 5.0, 6.0])
c = jnp.dot(a, b)
```

Те же имена функций. Те же правила broadcasting. Та же семантика срезов. Но массивы живут на GPU/TPU, и каждая операция отслеживается компилятором.

Одно критическое отличие: массивы JAX неизменяемы. Никаких `a[0] = 5`. Вместо этого: `a = a.at[0].set(5)`. Неделю это кажется неудобным, потом щёлкает — именно неизменяемость делает преобразования `grad`, `jit` и `vmap` совместимыми друг с другом.

> 🎒 **На пальцах.** Неизменяемость — как учебник из библиотеки: писать в нём нельзя, но можно сделать копию нужной страницы и правки внести уже в неё. `a.at[0].set(5)` не меняет старый массив, а возвращает новый. Кажется расточительным, зато никто не может испортить исходник у вас за спиной, и компилятор точно знает, что где лежит.

### jax.grad: Functional Autodiff

PyTorch прикрепляет градиенты к тензорам (`.grad`). JAX прикрепляет градиенты к функциям.

```python
import jax

def f(x):
    return x ** 2

df = jax.grad(f)
df(3.0)
```

`jax.grad` берёт функцию и возвращает новую функцию, которая считает градиент. Никакого вызова `.backward()`. Никакого графа вычислений, хранящегося на тензорах. Градиент — просто ещё одна функция, которую можно вызвать, скомпоновать или скомпилировать через JIT.

> 🎒 **На пальцах.** Проверьте в уме: у функции x² производная равна 2x, значит `df(3.0)` вернёт 6.0. Заметьте, что вы вызвали `df` как обычную функцию — никакого `.backward()`, никакого спрятанного состояния. `jax.grad` работает как станок, в который кладут одну функцию, а забирают другую.

Это компонуется как угодно:

```python
d2f = jax.grad(jax.grad(f))
d2f(3.0)
```

Вторые производные. Третьи. Якобианы. Гессианы. Всё через композицию `grad`. PyTorch тоже так умеет (`torch.autograd.functional.hessian`), но там это приделано сбоку. В JAX это фундамент.

Ограничение: `grad` работает только с чистыми функциями. Никаких print внутри (они срабатывают на трассировке, а не на выполнении). Никаких изменений внешнего состояния. Никакой генерации случайных чисел без явного управления ключами.

> 🎒 **На пальцах.** Раз производная x² равна 2x, то производная от 2x равна просто 2 — значит `d2f(3.0)` даст 2.0 при любом аргументе. Проверить можно на бумаге за пять секунд, и JAX выдаст ровно это. Так и убеждаются, что композиция `grad(grad(f))` не магия, а обычная математика.

### jit: Compile to XLA

```python
@jax.jit
def train_step(params, x, y):
    loss = loss_fn(params, x, y)
    return loss

fast_step = jax.jit(train_step)
```

При первом вызове JAX трассирует функцию — записывает, какие операции происходят, не выполняя их. Затем передаёт эту запись в XLA (Accelerated Linear Algebra), компилятор Google для TPU и GPU. XLA сливает операции, убирает лишние копирования памяти и порождает оптимизированный машинный код.

Последующие вызовы вообще не заходят в Python. Скомпилированный код работает на ускорителе со скоростью C++.

Когда JIT помогает:
- Шаги обучения (одно и то же вычисление повторяется тысячи раз)
- Инференс (одна модель, разные входы)
- Любая функция, вызываемая больше одного раза со входами похожей формы

Когда JIT мешает:
- Функции с управляющими конструкциями Python, зависящими от значений (`if x > 0`, где x — трассируемый массив)
- Одноразовые вычисления (компиляция дороже самого счёта)
- Отладка (трассировка скрывает реальное выполнение)

Ограничение на управляющие конструкции реально. `jax.lax.cond` заменяет `if/else`. `jax.lax.scan` заменяет циклы `for`. Это не опция — это цена компиляции.

> 🎒 **На пальцах.** Трассировка — как когда вы один раз проходите маршрут с блокнотом и записываете: «250 шагов прямо, направо, 40 шагов». Дальше можно идти по записи, не разглядывая улицы. Первый проход медленный, все следующие — быстрые. Поэтому первая эпоха обучения на JAX всегда заметно дольше остальных. И там же прячется подвох: записывая маршрут, вы не знаете, будет ли на перекрёстке зелёный свет, — поэтому строчку «если зелёный, иди» записать нельзя. Ровно так и `if x > 0` не работает внутри jit.

### vmap: Automatic Vectorization

Вы пишете функцию, обрабатывающую один пример:

```python
def predict(params, x):
    return jnp.dot(params['w'], x) + params['b']
```

`vmap` поднимает её до обработки целого батча:

```python
batch_predict = jax.vmap(predict, in_axes=(None, 0))
```

`in_axes=(None, 0)` означает: не батчить `params` (они общие), батчить по оси 0 у `x`. Никакого ручного цикла `for`. Никаких reshape. Никакого протаскивания batch-измерения. JAX сам разбирается с ним и векторизует всё вычисление.

Это не синтаксический сахар. `vmap` порождает слитый векторизованный код, работающий в 10-100 раз быстрее цикла Python. И он комбинируется с `jit` и `grad`:

```python
per_example_grads = jax.vmap(jax.grad(loss_fn), in_axes=(None, 0, 0))
```

Градиенты по каждому примеру отдельно. Одной строкой. В PyTorch это почти невозможно без костылей.

> 🎒 **На пальцах.** `in_axes=(None, 0)` читается так: первый аргумент один на всех, второй у каждого свой. Как в школьной столовой: рецепт супа общий (None), а тарелка у каждого своя (0). Если у вас 128 картинок, `vmap` не прогоняет функцию 128 раз подряд — он превращает её в одну операцию сразу над всеми 128, что на GPU считается за то же время, что и над одной.

### pmap: Data Parallelism Across Devices

```python
parallel_step = jax.pmap(train_step, axis_name='devices')
```

`pmap` реплицирует функцию на все доступные устройства (GPU/TPU) и делит батч между ними. Внутри функции `jax.lax.pmean` и `jax.lax.psum` синхронизируют градиенты между устройствами.

Google обучает Gemini на тысячах чипов TPU v5e с помощью `pmap` (и его преемника `shard_map`). Модель программирования такая: напишите версию для одного устройства, оберните в `pmap`, готово.

> 🎒 **На пальцах.** Батч из 1024 примеров на 8 устройствах превращается в 8 порций по 128. Каждое устройство считает свои градиенты, потом `pmean` усредняет их — как восемь человек считают восемь стопок анкет, а в конце складывают результаты в один. Ваш код при этом остаётся кодом на одно устройство.

### Pytrees: The Universal Data Structure

JAX работает с «pytree» — вложенными комбинациями списков, кортежей, словарей и массивов. Параметры вашей модели — это pytree:

```python
params = {
    'layer1': {'w': jnp.zeros((784, 256)), 'b': jnp.zeros(256)},
    'layer2': {'w': jnp.zeros((256, 128)), 'b': jnp.zeros(128)},
    'layer3': {'w': jnp.zeros((128, 10)),  'b': jnp.zeros(10)},
}
```

Каждое преобразование JAX — `grad`, `jit`, `vmap` — умеет обходить pytree. `jax.tree.map(f, tree)` применяет `f` к каждому листу. Именно так оптимизаторы обновляют все параметры разом:

```python
params = jax.tree.map(lambda p, g: p - lr * g, params, grads)
```

Никакого метода `.parameters()`. Никакой регистрации параметров. Структура дерева и есть модель.

> 🎒 **На пальцах.** Pytree — это папка с вложенными папками, а листья — файлы в самом низу. `jax.tree.map` заходит в каждую папку и делает одно и то же с каждым файлом. Строка `p - lr * g` — это обычное «сделай шажок против градиента», применённое сразу ко всем шести массивам весов и смещений, без единого цикла.

### Functional vs Object-Oriented

PyTorch хранит состояние внутри объектов:

```python
class Model(nn.Module):
    def __init__(self):
        self.linear = nn.Linear(784, 10)

    def forward(self, x):
        return self.linear(x)
```

JAX использует чистые функции с явным состоянием:

```python
def predict(params, x):
    return jnp.dot(x, params['w']) + params['b']
```

Параметры передаются внутрь. Ничего не хранится. Ничего не мутирует. Это делает каждую функцию тестируемой, компонуемой и компилируемой. И это же значит, что параметрами вы управляете сами — либо берёте библиотеку вроде Flax или Equinox.

### The JAX Ecosystem

JAX даёт примитивы. Библиотеки дают удобство:

| Library | Role | Style |
|---------|------|-------|
| **Flax** (Google) | Слои нейросетей | `nn.Module` с явным состоянием |
| **Equinox** (Patrick Kidger) | Слои нейросетей | На основе pytree, по-питоновски |
| **Optax** (DeepMind) | Оптимизаторы и расписания LR | Компонуемые преобразования градиентов |
| **Orbax** (Google) | Чекпоинты | Сохранение и восстановление pytree |
| **CLU** (Google) | Метрики и логирование | Утилиты для цикла обучения |

Optax — стандартная библиотека оптимизаторов. Она отделяет преобразование градиента (Adam, SGD, обрезка) от обновления параметров, поэтому их тривиально компоновать:

```python
optimizer = optax.chain(
    optax.clip_by_global_norm(1.0),
    optax.adam(learning_rate=1e-3),
)
```

> 🎒 **На пальцах.** `optax.chain` — это конвейер: сначала градиенты проходят через обрезку по норме 1.0, потом через Adam. Как фильтр для воды из двух картриджей: каждый делает своё, порядок важен. В PyTorch обрезку пришлось бы вызывать отдельной строкой перед `step()`, а тут она стала частью самого оптимизатора.

### When to Use JAX vs PyTorch

| Factor | JAX | PyTorch |
|--------|-----|---------|
| TPU support | Первоклассная (Google сделал и то, и другое) | Поддерживается сообществом (torch_xla) |
| GPU support | Хорошая (CUDA через XLA) | Лучшая в классе (нативная CUDA) |
| Debugging | Сложно (трассировка и компиляция) | Легко (eager, построчно) |
| Ecosystem | Исследовательская (Flax, Equinox) | Огромная (HuggingFace, torchvision и т. д.) |
| Hiring | Нишевый (Google/DeepMind/Anthropic) | Массовый (везде) |
| Large-scale training | Лучше (XLA, pmap, mesh) | Хорошо (FSDP, DeepSpeed) |
| Prototyping speed | Медленнее (накладные расходы функционального стиля) | Быстрее (меняй на месте и вперёд) |
| Production inference | TensorFlow Serving, Vertex AI | TorchServe, Triton, ONNX |
| Who uses it | DeepMind (Gemini), Anthropic (Claude) | Meta (Llama), OpenAI (GPT), Stability AI |

Честный ответ: берите PyTorch, если у вас нет конкретной причины взять JAX. Такие причины — доступ к TPU, нужда в градиентах по каждому примеру, обучение на множестве устройств в огромном масштабе или работа в Google/DeepMind/Anthropic.

### Random Numbers in JAX

У JAX нет глобального состояния генератора случайных чисел. Каждая случайная операция требует явного PRNG-ключа:

```python
key = jax.random.PRNGKey(42)
key1, key2 = jax.random.split(key)
w = jax.random.normal(key1, shape=(784, 256))
```

Поначалу это раздражает. Но зато гарантирует воспроизводимость между устройствами и компиляциями — свойство, которое `torch.manual_seed` в PyTorch не может обеспечить при работе на нескольких GPU.

> 🎒 **На пальцах.** Ключ — как номер варианта контрольной. `PRNGKey(42)` всегда даёт одни и те же «случайные» числа, поэтому запуск сегодня и запуск через год совпадут до последнего знака. А `split` делает из одного ключа два новых, чтобы два разных слоя не получили одинаковые веса. Использовать один ключ дважды — как раздать двум ученикам один и тот же вариант: результат будет подозрительно одинаковым.

## Build It

### Step 1: Setup and Data

Мы обучим трёхслойный MLP на MNIST с помощью JAX и Optax. 784 входа, два скрытых слоя на 256 и 128 нейронов, 10 выходных классов.

```python
import jax
import jax.numpy as jnp
from jax import random
import optax

def get_mnist_data():
    from sklearn.datasets import fetch_openml
    mnist = fetch_openml('mnist_784', version=1, as_frame=False, parser='auto')
    X = mnist.data.astype('float32') / 255.0
    y = mnist.target.astype('int')
    X_train, X_test = X[:60000], X[60000:]
    y_train, y_test = y[:60000], y[60000:]
    return X_train, y_train, X_test, y_test
```

### Step 2: Initialize Parameters

Никаких классов. Просто функция, возвращающая pytree:

```python
def init_params(key):
    k1, k2, k3 = random.split(key, 3)
    scale1 = jnp.sqrt(2.0 / 784)
    scale2 = jnp.sqrt(2.0 / 256)
    scale3 = jnp.sqrt(2.0 / 128)
    params = {
        'layer1': {
            'w': scale1 * random.normal(k1, (784, 256)),
            'b': jnp.zeros(256),
        },
        'layer2': {
            'w': scale2 * random.normal(k2, (256, 128)),
            'b': jnp.zeros(128),
        },
        'layer3': {
            'w': scale3 * random.normal(k3, (128, 10)),
            'b': jnp.zeros(10),
        },
    }
    return params
```

He-инициализация, сделанная вручную. Три PRNG-ключа, полученные разбиением одного зерна. Каждый вес — неизменяемый массив во вложенном словаре.

> 🎒 **На пальцах.** Посчитайте `scale1`: квадратный корень из 2/784 — это примерно 0,0505. То есть стартовые веса первого слоя — крошечные числа около нуля, иначе сумма 784 слагаемых улетела бы в тысячи и сеть бы не училась. Чем больше входов у слоя, тем меньше начальные веса: у третьего слоя вход всего 128, и корень из 2/128 равен уже 0,125. Всего в этом дереве 235 146 чисел — те же, что и в версии на PyTorch.

### Step 3: Forward Pass

```python
def forward(params, x):
    x = jnp.dot(x, params['layer1']['w']) + params['layer1']['b']
    x = jax.nn.relu(x)
    x = jnp.dot(x, params['layer2']['w']) + params['layer2']['b']
    x = jax.nn.relu(x)
    x = jnp.dot(x, params['layer3']['w']) + params['layer3']['b']
    return x

def loss_fn(params, x, y):
    logits = forward(params, x)
    one_hot = jax.nn.one_hot(y, 10)
    return -jnp.mean(jnp.sum(jax.nn.log_softmax(logits) * one_hot, axis=-1))
```

Чистые функции. Параметры внутрь, предсказание наружу. Никакого `self`, никакого сохранённого состояния. `loss_fn` считает кросс-энтропию с нуля — softmax, логарифм, среднее со знаком минус.

### Step 4: JIT-Compiled Training Step

```python
@jax.jit
def train_step(params, opt_state, x, y):
    loss, grads = jax.value_and_grad(loss_fn)(params, x, y)
    updates, opt_state = optimizer.update(grads, opt_state, params)
    params = optax.apply_updates(params, updates)
    return params, opt_state, loss

@jax.jit
def accuracy(params, x, y):
    logits = forward(params, x)
    preds = jnp.argmax(logits, axis=-1)
    return jnp.mean(preds == y)
```

`jax.value_and_grad` за один проход возвращает и значение loss, и градиенты. Декоратор `@jax.jit` компилирует обе функции в XLA. После первого вызова каждый шаг обучения выполняется, не заходя в Python.

> 🎒 **На пальцах.** Обратите внимание: `train_step` принимает `params` и возвращает **новые** `params`. Старые никуда не делись — они просто больше не нужны. Это как переписывать список дел набело каждое утро, а не зачёркивать в старом. И заметьте, что `value_and_grad` считает loss и градиенты за один проход: считать их двумя вызовами означало бы делать двойную работу.

### Step 5: Training Loop

```python
optimizer = optax.adam(learning_rate=1e-3)

X_train, y_train, X_test, y_test = get_mnist_data()
X_train, X_test = jnp.array(X_train), jnp.array(X_test)
y_train, y_test = jnp.array(y_train), jnp.array(y_test)

key = random.PRNGKey(0)
params = init_params(key)
opt_state = optimizer.init(params)

batch_size = 128
n_epochs = 10

for epoch in range(n_epochs):
    key, subkey = random.split(key)
    perm = random.permutation(subkey, len(X_train))
    X_shuffled = X_train[perm]
    y_shuffled = y_train[perm]

    epoch_loss = 0.0
    n_batches = len(X_train) // batch_size
    for i in range(n_batches):
        start = i * batch_size
        xb = X_shuffled[start:start + batch_size]
        yb = y_shuffled[start:start + batch_size]
        params, opt_state, loss = train_step(params, opt_state, xb, yb)
        epoch_loss += loss

    train_acc = accuracy(params, X_train[:5000], y_train[:5000])
    test_acc = accuracy(params, X_test, y_test)
    print(f"Epoch {epoch + 1:2d} | Loss: {epoch_loss / n_batches:.4f} | "
          f"Train Acc: {train_acc:.4f} | Test Acc: {test_acc:.4f}")
```

10 эпох. Около 97% точности на тесте. Первая эпоха медленная (JIT-компиляция). Эпохи со второй по десятую — быстрые.

Заметьте, чего здесь нет: ни `.zero_grad()`, ни `.backward()`, ни `.step()`. Всё обновление — один вызов составленной функции. Градиенты считаются, преобразуются оптимизатором Adam и применяются к параметрам — всё внутри `train_step`.

> 🎒 **На пальцах.** Считаем батчи: 60 000 примеров при `batch_size=128` дают 468 шагов за эпоху (60 000 // 128 = 468). За 10 эпох — 4680 вызовов `train_step`, но компиляция происходит ровно один раз, на самом первом. Поэтому первая эпоха может занять несколько секунд, а следующие — доли секунды. Если замерить время и удивиться первой цифре, знайте: вы измеряете компилятор, а не сеть.

## Use It

### Flax: The Google Standard

Flax — самая распространённая библиотека нейросетей для JAX. Она возвращает `nn.Module`, но с явным управлением состоянием:

```python
import flax.linen as nn

class MLP(nn.Module):
    @nn.compact
    def __call__(self, x):
        x = nn.Dense(256)(x)
        x = nn.relu(x)
        x = nn.Dense(128)(x)
        x = nn.relu(x)
        x = nn.Dense(10)(x)
        return x

model = MLP()
params = model.init(jax.random.PRNGKey(0), jnp.ones((1, 784)))
logits = model.apply(params, x_batch)
```

Структура как в PyTorch, но `params` живут отдельно от модели. `model.init()` создаёт параметры. `model.apply(params, x)` выполняет прямой проход. У объекта модели нет состояния.

### Equinox: The Pythonic Alternative

Equinox (автор Patrick Kidger) представляет модели как pytree:

```python
import equinox as eqx

model = eqx.nn.MLP(
    in_size=784, out_size=10, width_size=256, depth=2,
    activation=jax.nn.relu, key=jax.random.PRNGKey(0)
)
logits = model(x)
```

Сама модель — это pytree. Никакого `.apply()` не нужно. Параметры — просто листья модели. Это ближе к тому, как мыслит JAX.

### Optax: Composable Optimizers

Optax отделяет преобразование градиента от обновления:

```python
schedule = optax.warmup_cosine_decay_schedule(
    init_value=0.0, peak_value=1e-3,
    warmup_steps=1000, decay_steps=50000
)

optimizer = optax.chain(
    optax.clip_by_global_norm(1.0),
    optax.adamw(learning_rate=schedule, weight_decay=0.01),
)
```

Обрезка градиентов, разогрев learning rate, weight decay — всё собрано в цепочку преобразований. Каждое преобразование видит градиенты, изменяет их и передаёт следующему. Никакого монолитного класса оптимизатора.

**Performance gotchas:**

- Первый вызов JIT медленный (компиляция). Прогрейте функцию перед замерами.
- Избегайте циклов Python по массивам JAX внутри JIT. Используйте `jax.lax.scan` или `jax.lax.fori_loop`.
- `jax.debug.print()` работает внутри JIT. Обычный `print()` — нет.
- Профилируйте через `jax.profiler` или TensorBoard. Компиляция XLA умеет прятать узкие места.
- JAX по умолчанию заранее занимает 75% памяти GPU. Отключается через `XLA_PYTHON_CLIENT_PREALLOCATE=false`.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|----------------------|
| XLA | «То, из-за чего JAX быстрый» | Accelerated Linear Algebra — компилятор, который сливает операции и порождает оптимизированные ядра для GPU/TPU из графа вычислений |
| JIT | «Компиляция на лету» | JAX трассирует функцию при первом вызове, компилирует её в XLA, а дальше запускает уже скомпилированную версию |
| Pure function | «Без побочных эффектов» | Функция, у которой выход зависит только от входов: ни глобального состояния, ни мутаций, ни случайности без явных ключей |
| vmap | «Автобатчинг» | Превращает функцию, обрабатывающую один пример, в функцию, обрабатывающую батч, без переписывания кода |
| pmap | «Автопараллелизм» | Реплицирует функцию на несколько устройств и делит между ними входной батч |
| Pytree | «Вложенный словарь массивов» | Любая вложенная структура из списков, кортежей, словарей и массивов, которую JAX умеет обходить и преобразовывать |
| Tracing | «Запись вычисления» | JAX выполняет функцию на абстрактных значениях, чтобы построить граф вычислений, не считая реальных результатов |
| Functional autodiff | «grad от функции» | Вычисление производных путём преобразования функций, а не за счёт хранения градиентов внутри тензоров |
| Optax | «Библиотека оптимизаторов для JAX» | Компонуемая библиотека преобразований градиента — Adam, SGD, обрезка, расписания — которые собираются в цепочку |
| Flax | «nn.Module для JAX» | Библиотека нейросетей от Google для JAX: добавляет абстракции слоёв, сохраняя состояние явным |
