# Дифференциальная приватность для LLM

> DP-SGD остаётся стандартом: обновления градиентов с подмешанным шумом дают формальные гарантии (epsilon, delta). Плата в компьюте, памяти и качестве существенная; параметр-эффективный DP-файнтюн (LoRA + DP-SGD) — типовая конфигурация 2025 года (ACM 2025). Два корпуса свидетельств спорят друг с другом: membership inference на канарейках (Duan et al., 2024) сообщает о слабых успехах против языковых моделей; извлечение обучающих данных (Carlini et al., 2021; Nasr et al., 2025) достаёт заметный объём дословно запомненного текста. Разрешение спора (arXiv:2503.06808, март 2025): расхождение в том, что именно измеряют — подсаженные канарейки или «наиболее извлекаемые» данные. Новые конструкции канареек позволяют делать MIA по функции потерь без shadow-моделей и дают первый нетривиальный DP-аудит LLM, обученной на реальных данных с реалистичными DP-гарантиями. Альтернативы: PMixED (arXiv:2403.15638) — приватное предсказание на инференсе через смесь экспертов по распределениям следующего токена; генерация синтетических данных с DP (Google Research 2024). Новая атака: Differential Privacy Reversal via LLM Feedback — утечка через confidence-оценки.

**Type:** Build
**Languages:** Python (stdlib, DP-SGD noise-injection and ε-δ accountant demonstration)
**Prerequisites:** Phase 01 · 09 (information theory), Phase 10 · 01 (large-model training)

## Learning Objectives

- Дать определение (epsilon, delta)-дифференциальной приватности и сформулировать рецепт DP-SGD.
- Объяснить противоречие 2024-2025: MIA на канарейках и извлечение обучающих данных рисуют разные картины.
- Описать PMixED и почему приватное предсказание на инференсе — альтернатива DP-обучению.
- Описать атаку Differential Privacy Reversal via LLM Feedback.

> 🎒 **На пальцах.** Языковая модель — это не только «понимание языка», но и очень вместительная записная книжка. Если в обучающих данных один раз встретился чей-то телефон, модель может его повторить дословно. Дифференциальная приватность — это математическая гарантия того, что по выходу модели нельзя надёжно понять, был конкретный человек в обучающей выборке или нет.

## The Problem

LLM запоминают. Carlini et al. 2021 показали, что продакшен-модели по запросу воспроизводят обучающий текст дословно. DP — формальная защита: обучаем так, чтобы выход доказуемо почти не зависел ни от одного отдельного обучающего примера. Свидетельства 2024-2025 показывают: DP-SGD необходим, но ε, которые реально выкатывают, могут не соответствовать модели угроз.

## The Concept

### (ε, δ)-differential privacy

Рандомизированный алгоритм M является (ε, δ)-DP, если для любых двух датасетов, отличающихся одним примером, и любого события S:
P(M(D) in S) <= e^ε * P(M(D') in S) + δ.

Интерпретация: распределения выходов настолько близки (близость задаётся через ε), что вклад любого отдельного человека нельзя надёжно вывести — кроме как с вероятностью δ.

> 🎒 **На пальцах.** Читайте формулу так: два мира — в одном ваши данные есть, в другом их нет — должны выглядеть почти одинаково. Множитель e^ε задаёт «почти»: при ε = 1 это e ≈ 2.72, то есть любой исход в одном мире не более чем в 2.7 раза вероятнее, чем в другом. При ε = 10 множитель уже e^10 ≈ 22000 — формально гарантия есть, практически почти никакой.

> 🎒 **На пальцах.** δ — это оговорка «а ещё с малой вероятностью гарантия просто не работает». Типично берут δ порядка 1e-5: примерно один случай на сто тысяч. Именно поэтому δ всегда сравнивают с размером датасета — δ, сопоставимая с 1/N, разрешает алгоритму сдать данные одного человека целиком.

### DP-SGD

Abadi et al. 2016. Стандартный рецепт:
1. Сэмплируем мини-батч.
2. Считаем градиенты по каждому примеру отдельно.
3. Обрезаем каждый пер-экземплярный градиент до порога C.
4. Складываем обрезанные градиенты и добавляем гауссов шум со стандартным отклонением σ * C.
5. Обновляем параметры по этой зашумлённой сумме.

Стоимость приватности отслеживает аккаунтант (Moments Accountant, Rényi DP accountant). Значения ε в литературе по LLM разбросаны широко и зависят от модели угроз, чувствительности данных и целевого качества; универсально «безопасного» ε по умолчанию нет. Опубликованные примеры в обучении LLM лежат примерно в диапазоне ε ≈ 1–10, но это иллюстрация, а не рекомендация. Меньший ε обычно требует больше шума и сильнее бьёт по качеству.

> 🎒 **На пальцах.** Шаг 3 — самый важный и самый неочевидный. Обрезка до C ограничивает влияние одного примера: без неё редкий выброс мог бы утащить градиент куда угодно и оставить в весах свой отпечаток. При C = 1.0 градиент длиной 5.0 сжимается в пять раз, а градиент длиной 0.3 не трогают вообще.

> 🎒 **На пальцах.** Шум добавляют один раз на всю сумму батча, а не каждому примеру. Поэтому большие батчи для DP-SGD выгодны: шум σ * C размазывается на 1000 примеров вместо 32, и полезный сигнал переживает его лучше. Это и объясняет, почему DP-обучение так прожорливо по памяти.

### LoRA + DP-SGD

Полный DP-SGD для фронтирной модели неподъёмен. LoRA (Hu et al. 2022) ограничивает обновления градиентов маленьким адаптером, что снижает объём хранения пер-экземплярных градиентов. LoRA + DP-SGD — типовая конфигурация 2025 года. Гарантии DP относятся к адаптеру; базовая модель остаётся замороженной.

> 🎒 **На пальцах.** Вспомните шаг 2 рецепта: градиент нужен отдельно для каждого примера в батче. Для модели на 7 миллиардов параметров это 7 миллиардов чисел на пример — при батче 32 память кончается мгновенно. LoRA сводит обучаемые параметры к десяткам миллионов, и та же арифметика внезапно помещается в одну карту.

> 🎒 **На пальцах.** Тонкий момент: гарантия покрывает только адаптер. Если базовая модель уже выучила чей-то телефон до вашего DP-файнтюна, никакой ε этого не отменит. DP защищает данные вашего дообучения, а не всё, что модель знала раньше.

### The 2024-2025 tension

Две линии свидетельств:

- **Canary MIA (Duan et al. 2024).** Подсаживаем в обучающие данные уникальные канарейки и смотрим, сможет ли атакующий по membership inference их опознать. Успехи на языковых моделях скромные. Вывод: MIA — сложная атака.
- **Training-data extraction (Carlini 2021, Nasr et al. 2025).** Даём модели префикс и смотрим, восстановит ли она дословный текст из обучения. Запоминание находят в заметных объёмах. Вывод: в практическом смысле MIA лёгкая.

Разрешение спора в марте 2025 (arXiv:2503.06808): эти два подхода меряют разное. MIA спрашивает «есть ли пример e в D?» про подсаженные канарейки. Извлечение спрашивает «что я вообще могу достать из D?». Для приватности важен наиболее извлекаемый пример, а канарейки его недооценивают, потому что их не оптимизировали на извлекаемость.

> 🎒 **На пальцах.** Разница как между «а есть ли в этом доме квартира номер 47» и «а что я могу вынести из этого дома». Канарейка — случайная квартира, выбранная вами; извлечение ищет ту, где дверь не заперта. Отсюда и вывод: аудит по случайным канарейкам показывает картину благополучнее реальной.

Новые конструкции канареек. MIA по функции потерь без shadow-моделей. Первый нетривиальный DP-аудит LLM на реальных данных с реалистичными DP-гарантиями.

> 🎒 **На пальцах.** Shadow-модели — это когда для атаки приходится обучить десятки копий модели на разных подвыборках, чтобы понять, как выглядит «член выборки» на фоне «не члена». Дорого настолько, что для LLM практически неприменимо. Убрать их из атаки и оставить только сравнение loss — это и есть то, что сделало аудит реальных моделей возможным.

### Alternatives to DP training

- **PMixED (arXiv:2403.15638).** Приватное предсказание на инференсе. Смесь экспертов по распределениям следующего токена; каждый эксперт видит свой шард обучающих данных; агрегация добавляет шум ради DP. DP-обучение не требуется вовсе.
- **DP synthetic data generation (Google Research 2024).** Файнтюним LoRA с DP-SGD, сэмплируем синтетические данные, обучаем на них downstream-классификатор.

Оба обходят потерю качества от полного DP-обучения ценой другой модели угроз.

> 🎒 **На пальцах.** PMixED похож на комиссию: данные разрезали на 10 частей, обучили 10 экспертов, и каждый следующий токен они выбирают голосованием с добавленным шумом. Если фраза встречалась только в одном шарде, за неё голосует один эксперт из десяти — и шум её задавит. Запомнилось всеми — переживёт голосование, но такое обычно и не приватное.

> 🎒 **На пальцах.** Синтетические данные меняют место, где вы платите приватностью: DP применяется один раз при генерации, а дальше классификатор обучается на выходе свободно. Плата в том, что синтетика наследует только те закономерности, которые пережили шум, — редкие, но важные хвосты распределения теряются первыми.

### Differential Privacy Reversal via LLM Feedback

Новая атака 2025 года. Используем confidence-оценки DP-обученной модели как оракул для повторной идентификации людей. Даже когда сами выходы ничего не выдают, распределения уверенности могут выдать.

Защита: не отдавать наружу confidence вовсе либо обрезать и квантовать их перед выдачей. Это требование сверх (ε, δ)-DP-обучения.

> 🎒 **На пальцах.** Модель может ни разу не назвать имя, но отвечать на запрос с уверенностью 0.9997 вместо обычных 0.6 — и уже этого хватит, чтобы понять, что запись такая была. Округлите ответ до двух знаков, и 0.9997 с 0.9962 сольются в одно и то же 1.00. Дёшево и ломает почти весь канал утечки.

## Use It

`code/main.py` симулирует DP-SGD на игрушечном датасете для бинарной классификации. Можно перебирать множитель шума σ и норму обрезки C, отслеживая бюджет (ε, δ) и потерю точности. «Атака канарейкой» подсаживает уникальный обучающий пример и проверяет, ловит ли его тест по log-loss до и после DP.

> 🎒 **На пальцах.** Обратите внимание на два рычага: C решает, насколько сильно урезают вклад одного примера, σ — сколько шума на этот вклад приходится. Реально важно их отношение: σ = 1.0 при C = 1.0 и σ = 1.0 при C = 10.0 дают совершенно разную приватность, потому что во втором случае один пример может двигать сумму в десять раз сильнее.

## Ship It

Урок производит `outputs/skill-dp-audit.md`. По заявлению о DP в развёрнутой языковой модели навык проверяет: значения (ε, δ), какой использовался аккаунтант, протокол оценки MIA и оценивались ли векторы утечки через confidence.

> 🎒 **На пальцах.** Четыре пункта — это ровно четыре места, где «мы применили дифференциальную приватность» обычно разваливается. Чаще всего проваливаются два последних: MIA померили канарейками (см. спор выше), а confidence отдают наружу через API как ни в чём не бывало.

## Key Terms

| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| DP | «(ε, δ)-дифференциальная приватность» | Формальная приватность: распределения выходов близки при замене одного примера |
| DP-SGD | «SGD с подмешанным шумом» | Обрезка градиентов плюс добавление гауссова шума; стандартное DP-обучение |
| LoRA + DP-SGD | «эффективный приватный файнтюн» | DP-SGD по низкоранговым адаптерам; типовая конфигурация 2025 года |
| MIA | «membership inference» | Атака, определяющая, был ли пример в обучающих данных |
| Canary | «подсаженный пример-метка» | Уникальный обучающий пример для измерения утечки при DP |
| PMixED | «приватная смесь на инференсе» | DP на инференсе через смесь экспертов по распределениям следующего токена |
| DP Reversal | «атака через утечку confidence» | Атака, использующая уверенность модели как оракул для повторной идентификации |
