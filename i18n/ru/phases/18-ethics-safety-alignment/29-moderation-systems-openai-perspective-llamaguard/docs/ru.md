# Системы модерации — OpenAI, Perspective, Llama Guard

> Продакшен-системы модерации превращают политики безопасности из уроков 12-16 в работающий код. OpenAI Moderation API: `omni-moderation-latest` (2024) построен на GPT-4o и классифицирует текст и картинки за один вызов; на многоязычном тестовом наборе он на 42% лучше прошлой версии; схема ответа возвращает 13 булевых категорий — harassment, harassment/threatening, hate, hate/threatening, illicit, illicit/violent, self-harm, self-harm/intent, self-harm/instructions, sexual, sexual/minors, violence, violence/graphic; для большинства разработчиков бесплатно. Слоистые схемы: модерация входа (до генерации), модерация выхода (после генерации), кастомная модерация (доменные правила). Асинхронные параллельные вызовы прячут задержку; на срабатывание отдаётся ответ-заглушка. Llama Guard 3/4 (урок 16): 14 опасностей MLCommons, Code Interpreter Abuse, 8 языков (v3), несколько картинок (v4). Perspective API (Google Jigsaw): оценка токсичности, появившаяся ещё до волны LLM-в-роли-модератора; в основном одномерная токсичность с вариантами severe-toxicity/insult/profanity; базовая точка отсчёта для исследований по модерации контента. Устаревание: Azure Content Moderator объявлен устаревшим в феврале 2024, снимается с поддержки в феврале 2027, заменяется на Azure AI Content Safety.

## The Problem

Уроки 12-16 описывают атаки и инструменты защиты. Урок 29 — про развёрнутые системы модерации, которые превращают эти защиты в работающий код ровно на той поверхности, где пользователь касается продукта. Схема из трёх слоёв — конфигурация по умолчанию для 2026 года.

> 🎒 **На пальцах.** Атака — это лабораторный эксперимент, а модерация — замок на двери подъезда: он стоит там, где ходят все. Три слоя из этого урока — вход, выход и доменные правила — это ровно три точки, где можно поставить проверку в цепочке «пользователь → модель → пользователь». Других точек в этой цепочке просто нет.

## The Concept

### OpenAI Moderation API

`omni-moderation-latest` (2024). Построен на GPT-4o. Классифицирует текст и картинки за один вызов. Для большинства разработчиков бесплатно.

Категории (13 булевых полей в схеме ответа):
- `harassment`, `harassment/threatening`
- `hate`, `hate/threatening`
- `self-harm`, `self-harm/intent`, `self-harm/instructions`
- `sexual`, `sexual/minors`
- `violence`, `violence/graphic`
- `illicit`, `illicit/violent`

> 🎒 **На пальцах.** 13 категорий — это 13 отдельных «да/нет» в одном ответе API, а не один общий вердикт «плохо». На каждый запрос вы получаете 13 бит информации и можете назначить каждой категории свою реакцию: `sexual/minors` — блок наглухо, `violence` — пометка и пропуск. Как медицинский анализ, где в бланке не «здоров/болен», а 13 строк с показателями.

Мультимодальность работает для `violence`, `self-harm` и `sexual`, но не для `sexual/minors`; остальные категории — только по тексту.

> 🎒 **На пальцах.** Из 13 категорий картинки понимают только три. То есть если пользователь пришлёт мем, где текст ненависти нарисован прямо на картинке, категория `hate` его не увидит — она смотрит только текст. Это как металлодетектор, который ловит железо, но не керамику: знать про дырку важнее, чем верить в прибор.

В учебном коде из `code/main.py` мы схлопываем подкатегории `/threatening`, `/intent`, `/instructions` и `/graphic` в их родительские категории — так проще объяснять. В продакшене надо использовать полную схему из 13 категорий.

> 🎒 **На пальцах.** После схлопывания остаётся шесть родительских категорий: `harassment`, `hate`, `self-harm`, `sexual`, `violence`, `illicit`. Для учебного кода этого хватает, а в проде нельзя: разница между `self-harm` и `self-harm/instructions` — это разница между «человеку плохо» и «пошаговая инструкция навредить себе», и реакции на них нужны совершенно разные.

На многоязычном тестовом наборе он на 42% лучше эндпоинта модерации предыдущего поколения. Отдаёт оценки по каждой категории; пороги приложение выставляет само.

> 🎒 **На пальцах.** Обратите внимание, что улучшение измеряли именно на многоязычном наборе: чинили самое слабое место, потому что на неанглийских языках классификаторы традиционно промахиваются чаще. И заметьте вторую фразу — API отдаёт оценки, а порог выбираете вы: поставите 0,5 — получите больше ложных срабатываний, поставите 0,9 — больше пропусков.

### Llama Guard 3/4

Разбирался в уроке 16. 14 категорий опасностей MLCommons (нарезаны иначе, чем 13 булевых полей в схеме ответа OpenAI). Поддерживает 8 языков (v3). Llama Guard 4 (апрель 2025) изначально мультимодальный, 12B.

> 🎒 **На пальцах.** Держите в голове два числа: у OpenAI 13 булевых категорий в схеме ответа, у Llama Guard 3 — 14 опасностей MLCommons. Числа почти одинаковые, а нарезка разная, и это не мелочь: перенести пороги из одной системы в другую копипастой не выйдет.

Таксономии OpenAI и Llama Guard пересекаются, но расходятся. У OpenAI есть широкая категория «illicit»; у Llama Guard отдельно «violent crimes» и отдельно «non-violent crimes». Развёртывания выбирают по тому, что лучше ложится на их собственную политику.

> 🎒 **На пальцах.** Смотрите на конкретный стык: одна широкая категория `illicit` у OpenAI против двух категорий у Llama Guard. Одно срабатывание `illicit` может означать и мелкую кражу, и вооружённое нападение — различить их вы не сможете. Если в вашей политике эти два случая наказываются по-разному, вам нужна нарезка Llama Guard.

### Perspective API (Google Jigsaw)

Система оценки токсичности, появившаяся ещё до волны LLM-в-роли-модератора (до 2020 года). Категории: TOXICITY, SEVERE_TOXICITY, INSULT, PROFANITY, THREAT, IDENTITY_ATTACK. Одна главная одномерная оценка (TOXICITY) плюс варианты-подизмерения.

> 🎒 **На пальцах.** Perspective старше эпохи LLM, и это видно по формату ответа: не набор булевых флагов, а одно число от 0 до 1 по TOXICITY плюс пять подшкал. Число удобно для порогов: комментарий с 0,85 прячем, с 0,40 показываем. Так же устроен антиспам в почте — не «спам/не спам», а score, к которому вы сами прикручиваете порог.

Широко используется как базовая точка отсчёта в исследованиях по модерации контента: API стабильный, документированный, за годы накопил данные калибровки. Для современных задач вокруг LLM обычно лучше подходят Llama Guard или OpenAI Moderation.

### The three-layer pattern

1. **Input moderation.** Классифицируем запрос пользователя до генерации. Отклоняем, если сработало. Задержка: один вызов классификатора.
2. **Output moderation.** Классифицируем ответ модели до выдачи. Заменяем на отказ, если сработало. Задержка: один вызов классификатора после генерации.
3. **Custom moderation.** Правила под конкретный домен (регулярки, белые списки, бизнес-политика). Работают либо на входе, либо на выходе.

> 🎒 **На пальцах.** Три слоя стоят в трёх разных точках времени: до генерации, после генерации и где угодно. Цена у них тоже разная: модерация входа стоит один вызов классификатора и экономит целую генерацию, модерация выхода стоит такой же вызов, но уже после того, как вы заплатили за все токены ответа. Поэтому вход дешевле — он отсекает мусор до включения дорогой модели.

Три слоя устроены последовательно по замыслу: модерация входа обязана закончиться до генерации, а модерация выхода запускается после неё. Параллелизм работает внутри слоя — несколько классификаторов (например, OpenAI Moderation + Llama Guard + Perspective) на одном и том же тексте запускаются одновременно, и задержка каждого прячется за остальными. Как необязательная оптимизация можно показать ответ-заглушку («секунду, проверяю...»), пока идёт модерация входа, и отложить стриминг первого токена. Поведение при срабатывании настраивается: отказать, вычистить, отправить человеку на проверку.

> 🎒 **На пальцах.** Ключевые слова здесь — «внутри слоя». Три классификатора на одном тексте можно запустить разом, и тогда общая задержка равна самому медленному, а не сумме трёх: вместо 90 + 120 + 60 = 270 мс получится 120 мс. А вот вход и выход параллелить нельзя в принципе — пока ответ не сгенерирован, модерировать нечего.

### Failure modes

- **Input only.** Не ловит то, что модель нафантазировала сама (а атаки с кодировками из уроков 12-14 проходят входные классификаторы насквозь).
- **Output only.** Пропускает к модели любой вход; растит расходы; показывает атакующему внутренние рассуждения.
- **Custom only.** Не держится на всех категориях; регулярки хрупкие.

Слоистая схема — вариант по умолчанию. Ремень и подтяжки.

> 🎒 **На пальцах.** У каждого «только один слой» своя дырка: только вход — не видит того, что выдумала сама модель; только выход — вы платите за генерацию по каждому вредному запросу; только регулярки — ломаются от одной опечатки в слове. Отсюда и «ремень и подтяжки»: два держателя штанов одновременно, потому что каждый по отдельности иногда подводит.

### Azure deprecation

Azure Content Moderator: объявлен устаревшим в феврале 2024, снимается с поддержки в феврале 2027. Заменяется на Azure AI Content Safety, который построен на LLM и интегрируется с Azure OpenAI. Для развёртываний на Azure миграция — это полевой проект на 2024-2027 годы.

> 🎒 **На пальцах.** Между «объявили устаревшим» (февраль 2024) и «выключат» (февраль 2027) ровно три года — типичный срок для облачных сервисов. Три года кажутся вечностью, но переезд классификатора означает перепроверку всех порогов на своих данных, а это недели работы, а не замена одного URL за день.

## Use It

`code/main.py` собирает стенд модерации из трёх слоёв: модератор входа (ключевые слова плюс оценка категории), модератор выхода (тот же классификатор, но по ответу), кастомный модератор (доменные правила). Вы можете прогонять через него входы и смотреть, какой слой что ловит.

> 🎒 **На пальцах.** Смысл упражнения — увидеть, какой слой сработал первым. Безобидный вход пройдёт все три насквозь; пограничный обычно ловится только кастомными правилами; явно вредный отсечётся ещё на входе, и модель даже не запустится. Три входа, три разных маршрута — и сразу понятно, зачем нужны все три слоя, а не один.

## Ship It

Этот урок даёт `outputs/skill-moderation-stack.md`. По описанию развёртывания он рекомендует конфигурацию стека модерации: какой классификатор на входе, какой на выходе, какие кастомные правила и какой судья для пограничных случаев.

3. Прочитайте документацию OpenAI Moderation API и список категорий Llama Guard 3. Сопоставьте каждую категорию OpenAI с ближайшими категориями Llama Guard. Найдите три категории, которые не ложатся чисто.

4. Спроектируйте стек модерации для развёртывания кодового ассистента (например, GitHub Copilot). Определите самые и наименее релевантные категории и предложите кастомные правила.

5. Azure Content Moderator снимается с поддержки в феврале 2027. Спланируйте миграцию на Azure AI Content Safety. Найдите самый рискованный элемент этой миграции.

> 🎒 **На пальцах.** Начните с третьего задания: сопоставление категорий — самая полезная скучная работа в этом уроке. 13 категорий OpenAI против 14 у Llama Guard: большая часть ляжет один к одному, но минимум три пары не сойдутся — и именно в этих трёх потом заводятся инциденты.

## Key Terms

| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| OpenAI Moderation | «omni-moderation-latest» | Классификатор на базе GPT-4o, 13 категорий по тексту, частичная поддержка мультимодальности |
| Perspective API | «Токсичность от Google Jigsaw» | Базовая оценка токсичности эпохи до LLM |
| Llama Guard | «14 категорий MLCommons» | Классификатор опасностей от Meta (v3: 8B, текст, 8 языков; v4: 12B, мультимодальный) |

| Custom moderation | «Доменные правила» | Правила под конкретное развёртывание (регулярки, белые списки, политика) |
| Layered moderation | «Все три слоя» | Стандартная схема продакшен-развёртывания |

> 🎒 **На пальцах.** Пробегитесь по таблице и разложите семь терминов на два вида: три из них — конкретные продукты (OpenAI Moderation, Perspective, Llama Guard), остальные четыре — места в архитектуре (вход, выход, кастом, слоистость).
