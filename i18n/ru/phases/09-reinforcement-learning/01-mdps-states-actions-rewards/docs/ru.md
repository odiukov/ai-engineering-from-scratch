# MDP: состояния, действия и награды

> Марковский процесс принятия решений — это пять вещей: состояния, действия, переходы, награды, дисконтирование. Всё в RL — Q-learning, PPO, DPO, GRPO — оптимизирует именно эту конструкцию. Выучите её один раз, и остальное обучение с подкреплением будете читать бесплатно.

**Type:** Learn
**Languages:** Python
**Prerequisites:** Phase 1 · 06 (Probability & Distributions), Phase 2 · 01 (ML Taxonomy)
**Time:** ~45 minutes

## The Problem

Вы пишете шахматного бота. Или планировщик складских запасов. Или торгового агента. Или тот самый цикл PPO, который обучает рассуждающую модель. Четыре разные области и один неожиданный факт: все четыре сводятся к одному и тому же математическому объекту.

Обучение с учителем даёт вам пары `(x, y)` и просит подогнать функцию. Обучение с подкреплением не даёт меток вообще — только поток состояний, действий, которые вы совершили, и скалярную награду. Этот ход выиграл партию? Это решение о закупке сэкономило деньги? Эта сделка принесла прибыль? Токен, который только что выдала LLM, привёл к более высокой оценке судьи?

Учиться на таком потоке нельзя, пока вы его не формализуете. «Что я увидел», «что я сделал», «что произошло дальше», «насколько это было хорошо» — каждое должно стать объектом, о котором можно рассуждать. Эта формализация и есть марковский процесс принятия решений. Каждый алгоритм RL в этой фазе, включая циклы RLHF и GRPO в конце, оптимизирует именно её.

> 🎒 **На пальцах.** Шахматы, склад, трейдинг и обучение LLM выглядят как четыре разные профессии, но у них одинаковый скелет: ты в какой-то ситуации, что-то делаешь, ситуация меняется, тебе начисляют очки. Обучение с учителем — это тетрадь с ответами в конце. RL — это игровой автомат без инструкции: на экране только счёт, и надо самому понять, какие нажатия его подняли.

## The Concept

![Markov decision process: states, actions, transitions, rewards, discount](../assets/mdp.svg)

**The five objects.**

- **States** `S`. Всё, что агенту нужно для решения. В GridWorld — клетка. В шахматах — доска. В LLM — контекстное окно плюс любая память.
- **Actions** `A`. Варианты выбора. Ходить вверх/вниз/влево/вправо. Сделать ход. Выдать токен.
- **Transitions** `P(s' | s, a)`. Для состояния `s` и действия `a` — распределение следующего состояния. Детерминированное в шахматах, стохастическое на складе, почти детерминированное при декодировании LLM.
- **Rewards** `R(s, a, s')`. Скалярный сигнал. Победа = +1, поражение = -1. Выручка минус издержки. Член с логарифмом отношения правдоподобий в GRPO.
- **Discount** `γ ∈ [0, 1)`. Насколько будущая награда важна по сравнению с сегодняшней. `γ = 0.99` покупает горизонт около 100 шагов, `γ = 0.9` — около 10.

> 🎒 **На пальцах.** Представьте настольную игру. Состояние — расстановка фишек на доске, действие — ваш ход, переход — правила и бросок кубика, награда — очки за ход, дисконтирование — ваша нетерпеливость. Именно нетерпеливость — единственный из пяти объектов, который выбираете вы сами, а не задача: поставили `γ = 0.9` — агент планирует на десять ходов вперёд, поставили `γ = 0.99` — на сотню.

**The Markov property** `P(s_{t+1} | s_t, a_t) = P(s_{t+1} | s_0, a_0, …, s_t, a_t)`. Будущее зависит только от текущего состояния. Если это не так, значит представление состояния неполное — это провал не метода, а состояния.

> 🎒 **На пальцах.** Фотографии шахматной доски достаточно, чтобы играть дальше: как фигуры туда попали, неважно. А вот одного кадра из видео с летящим мячом мало — по нему не видно, куда мяч летит. Первое марковское, второе нет. Лечится это не сменой алгоритма, а расширением состояния: склейте четыре кадра подряд, и скорость снова видна.

**Policies and returns.** Политика `π(a | s)` сопоставляет состояниям распределения действий. Отдача `G_t = r_t + γ r_{t+1} + γ² r_{t+2} + …` — это дисконтированная сумма будущих наград. Функция ценности `V^π(s) = E[G_t | s_t = s]` — ожидаемая отдача при старте из `s` под политикой `π`. Q-значение `Q^π(s, a) = E[G_t | s_t = s, a_t = a]` — ожидаемая отдача при старте из `s` с конкретным первым действием. Каждый алгоритм RL оценивает одну из этих двух величин, а затем улучшает `π`.

> 🎒 **На пальцах.** Посчитаем отдачу руками. Пусть агент идёт к цели ровно 6 шагов и за каждый получает -1, а `γ = 0.9`. Тогда `G = -(1 + 0.9 + 0.81 + 0.729 + 0.656 + 0.59) ≈ -4.69`, хотя честная сумма наград равна -6. Дисконтирование не подделывает результат, оно просто говорит: боль через пять шагов волнует меня меньше, чем боль прямо сейчас.

**The Bellman equations.** Уравнения неподвижной точки, на которых держится вся эта фаза:

`V^π(s) = Σ_a π(a|s) Σ_{s', r} P(s', r | s, a) [r + γ V^π(s')]`
`Q^π(s, a) = Σ_{s', r} P(s', r | s, a) [r + γ Σ_{a'} π(a'|s') Q^π(s', a')]`

Они разбивают ожидаемую отдачу на «награду за этот шаг» плюс «дисконтированную ценность того места, куда вы попали». Рекурсия. Каждый алгоритм фазы 9 либо гоняет это уравнение до сходимости (динамическое программирование), либо сэмплирует из него (Монте-Карло), либо подставляет оценку на один шаг вперёд (temporal difference).

> 🎒 **На пальцах.** Это ровно то, как вы прикидываете дорогу домой: «до метро десять минут, а от метро я и так знаю, что сорок». Не надо заново считать весь маршрут — достаточно одного шага плюс уже известного остатка. Уравнение Беллмана — та же самая мысль, только записанная так, что её может крутить компьютер.

## Build It

### Step 1: a tiny deterministic MDP

Сетка 4×4. Агент стартует сверху слева, терминальное состояние снизу справа, награда -1 за каждый шаг, действия `{up, down, left, right}`. Смотрите `code/main.py`.

```python
GRID = 4
TERMINAL = (3, 3)
ACTIONS = {"up": (-1, 0), "down": (1, 0), "left": (0, -1), "right": (0, 1)}

def step(state, action):
    if state == TERMINAL:
        return state, 0.0, True
    dr, dc = ACTIONS[action]
    r, c = state
    nr = min(max(r + dr, 0), GRID - 1)
    nc = min(max(c + dc, 0), GRID - 1)
    return (nr, nc), -1.0, (nr, nc) == TERMINAL
```

Пять строк. Это вся среда целиком. Детерминированные переходы, постоянный штраф за шаг, поглощающее терминальное состояние.

> 🎒 **На пальцах.** Пара `min(max(...))` — это стены. Агент в клетке `(0, 0)` идёт `up`, получает `r + dr = -1`, `max(-1, 0)` возвращает 0 — он остался на месте и всё равно заработал -1. Штраф за шаг здесь не злоба автора, а способ сказать агенту «торопись»: чем дольше блуждаешь, тем хуже итог.

### Step 2: roll out a policy

Политика — это функция из состояния в распределение действий. Простейшая: равномерно случайная.

```python
def uniform_policy(state):
    return {a: 0.25 for a in ACTIONS}

def rollout(policy, max_steps=200):
    s, total, steps = (0, 0), 0.0, 0
    for _ in range(max_steps):
        a = sample(policy(s))
        s, r, done = step(s, a)
        total += r
        steps += 1
        if done:
            break
    return total, steps
```

Прогоните случайную политику 1000 раз. Средняя отдача выйдет около -58 для этой доски 4×4 с ограничением в 200 шагов, как в сниппете выше; без ограничения точное матожидание отдачи равно -59.4 (это матожидание времени первого попадания в терминальную клетку при равномерном случайном блуждании). Оптимальная отдача равна -6 (путь по прямой вниз и вправо). Закрытие этого разрыва — и есть содержание всей фазы 9.

> 🎒 **На пальцах.** Разрыв почти в десять раз (59.4 / 6 ≈ 9.9) получается из-за того, что случайная политика в 25% случаев идёт назад. Пьяный человек, которому надо пройти шесть шагов до двери, потратит их почти шестьдесят. Все алгоритмы дальше — про то, как отобрать у него бутылку: вместо `0.25` на каждое действие поставить `1.0` на правильное.

### Step 3: compute `V^π` exactly via the Bellman equation

Для маленьких MDP уравнение Беллмана — это линейная система. Перечисляем состояния, применяем матожидание, повторяем, пока значения не перестанут меняться.

```python
def policy_evaluation(policy, gamma=0.99, tol=1e-6):
    V = {s: 0.0 for s in all_states()}
    while True:
        delta = 0.0
        for s in all_states():
            if s == TERMINAL:
                continue
            v = 0.0
            for a, pi_a in policy(s).items():
                s_next, r, _ = step(s, a)
                v += pi_a * (r + gamma * V[s_next])
            delta = max(delta, abs(v - V[s]))
            V[s] = v
        if delta < tol:
            return V
```

Это итеративная оценка политики. Это первый алгоритм в книге Саттона и Барто и теоретический фундамент любого RL-метода, который идёт следом.

> 🎒 **На пальцах.** Проследите первый проход. Все `V` стартуют с нуля, поэтому `v = 0.25 · (-1 + 0.99 · 0) · 4 = -1` — почти каждое состояние получает -1. На втором проходе соседние значения уже не нулевые, и минусы начинают расползаться от дальних углов. `delta` — самое большое изменение за проход; когда оно падает ниже `1e-6`, значения устаканились и цикл выходит.

### Step 4: `γ` is a hyperparameter with physical meaning

Эффективный горизонт примерно равен `1 / (1 - γ)`. `γ = 0.9` → 10 шагов. `γ = 0.99` → 100 шагов. `γ = 0.999` → 1000 шагов.

Слишком мало — агент близорук. Слишком много — распределение заслуг становится шумным, потому что за далёкую награду отвечает сразу много ранних шагов. В RLHF для LLM обычно берут `γ = 1`, потому что эпизоды короткие и ограниченные. В задачах управления — `0.95–0.99`. В долгих стратегических играх — `0.999`.

> 🎒 **На пальцах.** Считаем, сколько весит награда через 20 шагов. При `γ = 0.9` это `0.9²⁰ ≈ 0.12` — двенадцать процентов, агент её почти не замечает. При `γ = 0.99` это `0.99²⁰ ≈ 0.82` — она почти как своя. Отсюда и правило `1/(1-γ)`: дальше этого горизонта агент просто слепнет.

## Pitfalls

- **Non-Markovian state.** Если для решения нужны три последних наблюдения, то «состояние» — это не только текущее наблюдение. Лечение: склеивать кадры (DQN на Atari склеивает 4) или использовать рекуррентное состояние (LSTM/GRU поверх наблюдений).
- **Sparse rewards.** Награда только за победу делает обучение почти невозможным в больших пространствах состояний. Формируйте награду (промежуточный сигнал) или разгоняйтесь имитацией (фаза 9 · 09).
- **Reward hacking.** Оптимизация суррогатной награды часто рождает патологическое поведение. Лодочный агент OpenAI бесконечно крутился на месте, собирая бонусы, вместо того чтобы финишировать. Всегда определяйте награду от целевого результата, а не от суррогата.
- **Discount mis-spec.** `γ = 1` на задаче с бесконечным горизонтом делает все ценности бесконечными. Всегда ограничивайте либо конечным горизонтом, либо `γ < 1`.
- **Reward scale.** Награды {+100, -100} и {+1, -1} дают одинаковые оптимальные политики, но кардинально разные величины градиентов. Нормализуйте примерно в `[-1, 1]`, прежде чем скармливать PPO/DQN.

> 🎒 **На пальцах.** Reward hacking — это школьник, которого оценивают по числу исписанных страниц: он начинает писать крупно. Лодка OpenAI поступила ровно так же — очки давали за бонусы на трассе, и агент нашёл круг, где бонусы возрождаются, и катался по нему вечно. Он не сломался, он выиграл: просто выиграл ту игру, которую ему на самом деле задали.

## Use It

Стек 2026 года сводит любой RL-конвейер к MDP ещё до того, как трогать код:

| Situation | State | Action | Reward | γ |
|-----------|-------|--------|--------|---|
| Управление (локомоция, манипуляция) | Углы суставов + скорости | Непрерывные моменты | Сформированная под задачу | 0.99 |
| Игры (шахматы, го, покер) | Доска + история | Легальный ход | Победа=+1 / поражение=-1 | 1.0 (конечный) |
| Запасы / ценообразование | Остаток + спрос | Объём заказа | Выручка - издержки | 0.95 |
| RLHF для LLM | Токены контекста | Следующий токен | Оценка reward-модели в конце | 1.0 (эпизод ~200 токенов) |
| GRPO для рассуждений | Промпт + частичный ответ | Следующий токен | Верификатор 0/1 в конце | 1.0 |

Выпишите пять кортежей до того, как напишете хоть один обучающий цикл. Большинство жалоб «RL не работает» упирается в постановку MDP, сломанную ещё на бумаге.

> 🎒 **На пальцах.** Посмотрите на строку RLHF: там состояние — это весь текст, написанный до сих пор, действие — одно слово, а награда приходит один раз в самом конце. То есть модель, пишущая ответ, — это агент, делающий 200 ходов вслепую и узнающий счёт только на финише. Именно поэтому `γ = 1`: за двести токенов дисконтировать нечего, эпизод и так короткий.

## Ship It

Сохраните как `outputs/skill-mdp-modeler.md`:

```markdown
---
name: mdp-modeler
description: Given a task description, produce a Markov Decision Process spec and flag formulation risks before training.
version: 1.0.0
phase: 9
lesson: 1
tags: [rl, mdp, modeling]
---

Given a task (control / game / recommendation / LLM fine-tuning), output:

1. State. Exact feature vector or tensor spec. Justify Markov property.
2. Action. Discrete set or continuous range. Dimensionality.
3. Transition. Deterministic, stochastic-with-known-model, or sample-only.
4. Reward. Function and source. Sparse vs shaped. Terminal vs per-step.
5. Discount. Value and horizon justification.

Refuse to ship any MDP where the state is non-Markovian without explicit mention of frame-stacking or recurrent state. Refuse any reward that was not defined in terms of the target outcome. Flag any `γ ≥ 1.0` on an infinite-horizon task. Flag any reward range >100x the typical step reward as a likely gradient-explosion source.
```

> 🎒 **На пальцах.** Обратите внимание, что половина навыка — это не «сделай», а «откажись». Отказаться от немарковского состояния, отказаться от награды, придуманной под суррогат, пометить `γ ≥ 1.0` на бесконечном горизонте. Такой чек-лист ловит ошибки за пять минут на бумаге, а не за пять дней обучения на GPU.

## Exercises

1. **Easy.** Реализуйте GridWorld 4×4 и прогон случайной политики в `code/main.py`. Запустите 10 000 эпизодов. Отчитайтесь о среднем и стандартном отклонении отдачи. Сравните с оптимальной отдачей (-6).
2. **Medium.** Запустите `policy_evaluation` с `γ ∈ {0.5, 0.9, 0.99}` для равномерно случайной политики. Напечатайте `V` в виде сетки 4×4 для каждого случая. Объясните, почему ценности состояний рядом с терминальным растут быстрее при большом `γ`.
3. **Hard.** Сделайте GridWorld стохастическим: каждое действие с вероятностью `p = 0.1` соскальзывает в соседнее направление. Заново оцените равномерную политику. `V[start]` стал лучше или хуже? Почему?

> 🎒 **На пальцах.** Подсказка ко второму заданию: сравнивайте не форму сетки, а масштаб чисел. При `γ = 0.5` дальние состояния получат что-то около -2, потому что дальше двух шагов агент не видит и штрафы просто не доходят. При `γ = 0.99` те же клетки провалятся к -50 и ниже: теперь суммируется вся будущая дорога целиком.

## Key Terms

| Term | What people say | What it actually means |
|------|-----------------|-----------------------|
| MDP | «Постановка задачи RL» | Кортеж `(S, A, P, R, γ)`, удовлетворяющий марковскому свойству. |
| State | «Что видит агент» | Достаточная статистика для будущей динамики в выбранном классе политик. |
| Policy | «Поведение агента» | Условное распределение `π(a \| s)` или детерминированное отображение `s → a`. |
| Return | «Суммарная награда» | Дисконтированная сумма `Σ γ^t r_t` начиная с текущего шага. |
| Value | «Насколько хорошо состояние» | Ожидаемая отдача под `π` при старте из `s`. |
| Q-value | «Насколько хорошо действие» | Ожидаемая отдача под `π` при старте из `s` с первым действием `a`. |
| Bellman equation | «Рекурсия динамического программирования» | Разложение ценности или Q в неподвижной точке: награда за шаг плюс дисконтированная ценность следующего состояния. |
| Discount `γ` | «Будущее против настоящего» | Геометрический вес далёкой награды; эффективный горизонт `~1/(1-γ)`. |

> 🎒 **На пальцах.** Разница между Value и Q-value — как между «хорошо ли мне здесь» и «хорош ли вот этот конкретный ход отсюда». `V` отвечает на первый вопрос, `Q` на второй. Действовать можно только по `Q`: чтобы выбрать ход по `V`, нужно ещё знать, куда каждый ход ведёт, — а это и есть модель переходов, которой у нас обычно нет.

- [Puterman (2005). Markov Decision Processes](https://onlinelibrary.wiley.com/doi/book/10.1002/9780470316887) — справочник по MDP и точным методам решения со стороны исследования операций.
- [Littman (1996). Algorithms for Sequential Decision Making (PhD thesis)](https://www.cs.rutgers.edu/~mlittman/papers/thesis-main.pdf) — самый чистый вывод MDP как частного случая динамического программирования.
