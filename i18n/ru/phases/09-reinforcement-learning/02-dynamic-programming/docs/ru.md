# Динамическое программирование — итерация по политике и по ценности

> Динамическое программирование — это RL с подглядыванием в ответы. Функции переходов и наград вы уже знаете; остаётся гонять уравнение Беллмана, пока `V` или `π` не перестанут двигаться. Это эталон, к которому пытается подобраться любой метод, основанный на сэмплировании.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 9 · 01 (MDPs)
**Time:** ~75 minutes

## The Problem

У вас есть MDP с известной моделью: для любой пары «состояние-действие» можно спросить `P(s' | s, a)` и `R(s, a, s')`. Складской менеджер знает распределение спроса. У настольной игры переходы детерминированные. GridWorld — это четыре строки на Python. У вас есть *модель*.

Model-free RL (Q-learning, PPO, REINFORCE) придумали для случая, когда модели нет — можно только сэмплировать из среды. Но если модель есть, существуют методы быстрее и лучше: динамическое программирование. Беллман спроектировал их в 1957 году. Они до сих пор задают само понятие правильности: когда люди говорят «оптимальная политика для этого MDP», они имеют в виду политику, которую вернёт DP.

В 2026 году они нужны по трём причинам. Первая: каждая табличная среда в RL-исследованиях (GridWorld, FrozenLake, CliffWalking) решается через DP, чтобы получить эталонную политику. Вторая: точные значения позволяют *отлаживать* методы на сэмплах — если оценка `V*(s_0)` из Q-learning расходится с ответом DP на 30%, значит в вашем Q-learning баг. Третья: современные методы offline RL и планирования (MCTS, поиск в AlphaZero, model-based RL в фазе 9 · 10) все крутят беллмановский бэкап поверх выученной или заданной модели.

> 🎒 **На пальцах.** Разница между DP и остальным RL — как между лабиринтом с картой и лабиринтом в темноте. С картой можно посчитать лучший маршрут не сходя с места. Без карты приходится ходить и набивать шишки. Курс дальше почти весь про темноту, но начинать надо со света: только имея точный ответ, вы поймёте, насколько хорош метод, который ходит вслепую.

## The Concept

![Policy iteration and value iteration, side by side](../assets/dp.svg)

**Two algorithms, both fixed-point iteration on Bellman.**

**Policy iteration.** Чередует два шага, пока политика не перестанет меняться.

1. *Evaluation:* для политики `π` вычисляем `V^π`, многократно применяя `V(s) ← Σ_a π(a|s) Σ_{s',r} P(s',r|s,a) [r + γ V(s')]`, пока не сойдётся.
2. *Improvement:* имея `V^π`, делаем `π` жадной по `V^π`: `π(s) ← argmax_a Σ_{s',r} P(s',r|s,a) [r + γ V(s')]`.

Сходимость гарантирована, потому что (а) каждый шаг улучшения либо оставляет `π` прежней, либо строго увеличивает `V^π` хотя бы в одном состоянии, (б) пространство детерминированных политик конечно. Обычно сходится за 5–20 внешних итераций даже на больших пространствах состояний.

> 🎒 **На пальцах.** Это цикл «оценил — переиграл». Сначала честно считаете, чего стоит текущий план, потом в каждой клетке выбираете действие, ведущее в самого ценного соседа. Похоже на составление расписания: посчитали, сколько времени съедает нынешний маршрут, переставили один пункт, пересчитали. Политик конечное число, а хуже никогда не становится — значит рано или поздно упрётесь в лучшую и остановитесь.

**Value iteration.** Схлопывает оценку и улучшение в один проход. Применяем уравнение Беллмана *оптимальности*:

`V(s) ← max_a Σ_{s',r} P(s',r|s,a) [r + γ V(s')]`

Повторяем, пока `max_s |V_{new}(s) - V(s)| < ε`. В конце извлекаем политику, взяв жадное действие. Строго быстрее на одну итерацию — внутреннего цикла оценки нет, — но итераций до сходимости обычно нужно больше.

> 🎒 **На пальцах.** Вся разница с предыдущим алгоритмом — одно слово: `Σ_a π(a|s)` заменили на `max_a`. То есть перестали спрашивать «что в среднем даст мой нынешний план» и начали спрашивать «что даст лучший ход отсюда». Улучшение политики больше не отдельный этап, оно спрятано внутри максимума и происходит на каждом проходе само собой.

**Generalized policy iteration (GPI).** Объединяющая рамка. Функция ценности и политика заперты в двустороннем цикле улучшения; любой метод, который толкает их к взаимной согласованности (асинхронная итерация по ценности, модифицированная итерация по политике, Q-learning, actor-critic, PPO), — это частный случай GPI.

> 🎒 **На пальцах.** Держите в голове двух персонажей: критик считает ценности при текущем поведении, актёр меняет поведение под текущие ценности. Каждый портит работу другому — и именно из-за этого оба сходятся к общей точке. Когда в фазе 9 дойдёте до PPO, узнаете ту же пару, просто вместо таблицы там будут две нейросети.

**Why `γ < 1` matters.** Оператор Беллмана является `γ`-сжатием в sup-норме: `||T V - T V'||_∞ ≤ γ ||V - V'||_∞`. Сжатие влечёт единственность неподвижной точки и геометрическую сходимость. Уберите `γ < 1` — потеряете гарантию: понадобится конечный горизонт или поглощающее терминальное состояние.

> 🎒 **На пальцах.** «Сжатие» буквально значит, что после каждого прохода ошибка умножается на `γ`. Начали с ошибки 1 и хотите 1e-6: при `γ = 0.9` нужно около 131 прохода, при `γ = 0.99` — около 1375. Ошибка не может застрять на месте, потому что 0.99 в большой степени неизбежно уходит в ноль. При `γ = 1` множитель равен единице, ошибка не уменьшается — и никаких обещаний у вас больше нет.

## Build It

### Step 1: build the GridWorld MDP model

Берём тот же GridWorld 4×4 из урока 01. Добавляем стохастический вариант: с вероятностью `0.1` агент соскальзывает в случайное перпендикулярное направление.

```python
SLIP = 0.1

def action_probs(action):
    perp = ("left", "right") if action in ("up", "down") else ("up", "down")
    return [(action, 1.0 - SLIP)] + [(d, SLIP / 2.0) for d in perp]

def transitions(state, action):
    if state == TERMINAL:
        return [(state, 0.0, 1.0)]
    outcomes = []
    for direction, prob in action_probs(action):
        outcomes.append((apply_move(state, direction), -1.0, prob))
    return outcomes
```

`transitions(s, a)` возвращает список `(s', r, p)`. Это и есть модель целиком.

> 🎒 **На пальцах.** Вот она, та самая «карта», которой нет у model-free методов: функция говорит, куда вы попадёте и с какой вероятностью, ни разу не сделав хода. Для действия `down` список выйдет примерно такой: вниз с вероятностью 0.9, влево с 0.05, вправо с 0.05. Сумма вероятностей всегда 1, иначе где-то потерялась часть будущего.

### Step 2: policy evaluation

Имея политику `π(s) = {action: prob}`, гоняем уравнение Беллмана, пока `V` не перестанет двигаться:

```python
def policy_evaluation(policy, gamma=0.99, tol=1e-6):
    V = {s: 0.0 for s in states()}
    while True:
        delta = 0.0
        for s in states():
            v = sum(pi_a * sum(p * (r + gamma * V[s_prime])
                              for s_prime, r, p in transitions(s, a))
                   for a, pi_a in policy(s).items())
            delta = max(delta, abs(v - V[s]))
            V[s] = v
        if delta < tol:
            return V
```

> 🎒 **На пальцах.** Внутри стоит двойная сумма, и порядок в ней важен. Внешняя идёт по действиям с весами политики — «что я вообще собираюсь делать». Внутренняя идёт по исходам перехода с весами среды — «что из этого может получиться». Для 16 клеток и 4 действий это 64 маленьких вычисления на проход: ноутбук делает такой проход за микросекунды.

### Step 3: policy improvement

Заменяем `π` на жадную политику по `V`. Если `π` не изменилась — возвращаем: мы в оптимуме.

```python
def policy_improvement(V, gamma=0.99):
    new_policy = {}
    for s in states():
        best_a = max(
            ACTIONS,
            key=lambda a: sum(p * (r + gamma * V[s_prime])
                              for s_prime, r, p in transitions(s, a)),
        )
        new_policy[s] = best_a
    return new_policy
```

> 🎒 **На пальцах.** `max(..., key=...)` перебирает четыре действия и оставляет то, у которого ожидаемая «награда сейчас плюс дисконтированная ценность потом» максимальна. Заметьте: сама `V` тут не меняется ни на йоту, меняются только стрелки в клетках. Это шаг «переиграть план по уже посчитанной карте».

### Step 4: stitch them together

```python
def policy_iteration(gamma=0.99):
    policy = {s: "up" for s in states()}   # arbitrary start
    for _ in range(100):
        V = policy_evaluation(lambda s: {policy[s]: 1.0}, gamma)
        new_policy = policy_improvement(V, gamma)
        if new_policy == policy:
            return V, policy
        policy = new_policy
```

Типичная сходимость на 4×4: 4–6 внешних итераций (`code/main.py` укладывается в 5). На выходе `V*(0,0) = -6.43` на этой *скользкой* сетке — чуть хуже, чем `-5.85` детерминированной сетки из урока 01, потому что соскальзывания стоят лишних шагов, — и политика, которая строго сокращает ожидаемое число шагов.

> 🎒 **На пальцах.** Стартовая политика «всегда вверх» — образцово плохая: агент упирается в потолок и стоит там вечно, получая -1 за шаг. При `γ = 0.99` это даёт `-1/(1-0.99) = -100` в каждом состоянии. За четыре-шесть внешних итераций эти -100 превращаются в -6.43. Начальная политика может быть любой глупостью, лишь бы модель была верной.

### Step 5: value iteration (the one-loop version)

```python
def value_iteration(gamma=0.99, tol=1e-6):
    V = {s: 0.0 for s in states()}
    while True:
        delta = 0.0
        for s in states():
            v = max(sum(p * (r + gamma * V[s_prime])
                       for s_prime, r, p in transitions(s, a))
                   for a in ACTIONS)
            delta = max(delta, abs(v - V[s]))
            V[s] = v
        if delta < tol:
            break
    policy = policy_improvement(V, gamma)
    return V, policy
```

Та же неподвижная точка, меньше строк кода.

> 🎒 **На пальцах.** Сравните с шагом 2 построчно: исчез внешний цикл по действиям политики, `sum(pi_a * ...)` превратился в `max(...)`. И пропала функция `policy_iteration` целиком — улучшение теперь встроено в сам проход. Политику достают один раз в самом конце, потому что жадный выбор по уже сошедшейся `V` и есть оптимальная политика.

## Pitfalls

- **Forgetting to handle terminals.** Если применить Беллмана к поглощающему состоянию, оно всё равно выберет «лучшее действие», которое ничего не меняет. Ставьте защиту: `if s == terminal: V[s] = 0`.
- **Sup-norm vs L2 convergence.** Используйте `max |V_new - V|`, а не среднее. Теоретическая гарантия даётся именно для sup-нормы.
- **In-place vs synchronous updates.** Обновление `V[s]` на месте (Гаусс-Зейдель) сходится быстрее, чем через отдельный словарь `V_new` (Якоби). Продакшен-код обновляет на месте.
- **Policy ties.** Если у двух действий одинаковое Q-значение, `argmax` может разрешать ничью по-разному на каждой итерации, и проверка «политика стабильна» начнёт колебаться. Используйте устойчивое разрешение ничьих (первое действие в фиксированном порядке).
- **State-space explosion.** DP стоит `O(|S| · |A|)` на проход. Работает примерно до 10⁷ состояний. Дальше нужна аппроксимация функций (фаза 9 · 05 и далее).

> 🎒 **На пальцах.** Ловушка с ничьими коварнее, чем кажется. Представьте клетку, из которой «вниз» и «вправо» одинаково хороши: на одной итерации `argmax` выбрал одно, на следующей — другое, и цикл `if new_policy == policy` никогда не срабатывает, хотя ценности давно сошлись. Алгоритм крутится вечно не из-за математики, а из-за порядка перебора в словаре.

## Use It

В 2026 году DP — это эталон правильности и внутренний цикл планировщиков:

| Use case | Method |
|----------|--------|
| Точно решить маленький табличный MDP | Итерация по ценности (проще) или по политике (меньше внешних шагов) |
| Проверить реализацию Q-learning / PPO | Сравнить с DP-оптимальной V* на игрушечной среде |
| Model-based RL (фаза 9 · 10) | Беллмановский бэкап поверх выученной модели переходов |
| Планирование в AlphaZero / MuZero | Monte Carlo Tree Search = асинхронный беллмановский бэкап |
| Offline RL (CQL, IQL) | Консервативная Q-итерация — DP со штрафом за действия вне распределения |

Каждый раз, когда кто-то говорит «оптимальная функция ценности», он имеет в виду «неподвижная точка DP». Когда вы видите в статье `V*` или `Q*`, представляйте себе этот цикл.

> 🎒 **На пальцах.** Вторая строка таблицы — самый практичный совет всего урока. Обучили Q-learning на GridWorld, он выдал `V(0,0) = -9`, а DP говорит -6? Значит дело не в «RL просто такой шумный», а в баге. На игрушечной среде у вас есть настоящий ответ, и глупо им не пользоваться, прежде чем запускать что-то большое.

## Exercises

1. **Easy.** Запустите итерацию по ценности на GridWorld 4×4 с `γ ∈ {0.9, 0.99}`. Сколько проходов до `max |ΔV| < 1e-6`? Напечатайте `V*` в виде сетки 4×4.
2. **Medium.** Сравните итерацию по политике и итерацию по ценности на *стохастическом* GridWorld (вероятность соскальзывания `0.1`). Посчитайте: проходы, время по часам, итоговое `V*(0,0)`. Что сходится быстрее по итерациям? А по времени?
3. **Hard.** Постройте модифицированную итерацию по политике: на шаге оценки делайте всего `k` проходов вместо сходимости. Постройте график ошибки `V*(0,0)` от `k` для `k ∈ {1, 2, 5, 10, 50}`. Что кривая говорит о балансе между оценкой и улучшением?

> 🎒 **На пальцах.** Подсказка к первому заданию: число проходов почти не зависит от размера сетки, зато сильно зависит от `γ`. Ошибка режется в `γ` раз за проход, поэтому при `γ = 0.9` до 1e-6 добираетесь примерно за 131 проход, а при `γ = 0.99` — примерно за 1375. Один и тот же лабиринт, разница в десять раз, и всё из-за одного числа в аргументах.

## Key Terms

| Term | What people say | What it actually means |
|------|-----------------|-----------------------|
| Policy iteration | «Алгоритм DP» | Чередование оценки (`V^π`) и улучшения (жадная `π` по `V^π`), пока политика не перестанет меняться. |
| Value iteration | «DP побыстрее» | Беллмановский бэкап оптимальности за один проход; сходится к `V*` геометрически. |
| Bellman operator | «Та самая рекурсия» | `(T V)(s) = max_a Σ P (r + γ V(s'))`; `γ`-сжатие в sup-норме. |
| Contraction | «Почему DP сходится» | Любой оператор `T` со свойством `\|\|T x - T y\|\| ≤ γ \|\|x - y\|\|` имеет единственную неподвижную точку. |
| GPI | «Всё есть DP» | Обобщённая итерация по политике: любой метод, толкающий `V` и `π` к взаимной согласованности. |
| Synchronous update | «В стиле Якоби» | Использовать старую `V` на всём проходе; красиво анализируется, но медленнее. |
| In-place update | «В стиле Гаусса-Зейделя» | Использовать `V` прямо по мере обновления; на практике сходится быстрее. |

> 🎒 **На пальцах.** Разница между двумя последними строками видна в коде шага 2: там `V[s] = v` пишет в тот же словарь, из которого читает следующая клетка. Значит, посчитав клетку `(3,2)`, вы тут же пользуетесь свежим числом при расчёте `(3,1)` — хорошая новость расползается по сетке за один проход вместо двух. Ровно поэтому продакшен-код обновляет на месте, хотя в учебниках анализируют синхронный вариант.
