# Варианты attention — sliding window, sparse, differential

> Полный attention — это круг. Каждый токен видит каждый токен, и за это платит память. Четыре варианта гнут форму круга и возвращают половину стоимости.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 7 · 02 (Self-Attention), Phase 7 · 03 (Multi-Head), Phase 7 · 12 (KV Cache / Flash Attention)
**Time:** ~60 minutes

## The Problem

Полный attention стоит `O(N²)` памяти и `O(N²)` вычислений по длине последовательности. Для Llama 3 70B с контекстом 128K это 16 миллиардов элементов матрицы attention на слой, умножить на 80 слоёв. Flash Attention (урок 12) прячет `O(N²)` памяти под активации, но арифметическую стоимость не меняет — каждый токен по-прежнему смотрит на каждый другой.

Три класса вариантов меняют саму топологию матрицы attention:

1. **Sliding window attention (SWA).** Каждый токен смотрит на фиксированное окно соседей, а не на весь префикс. Память и вычисления падают до `O(N · W)`, где `W` — окно. Gemma 2/3, первые слои Mistral 7B, Phi-3-Long.
2. **Sparse / block attention.** Оценки считаются только для выбранных пар `(i, j)`, остальным принудительно ставится нулевой вес. Longformer, BigBird, sparse transformer от OpenAI.
3. **Differential attention.** Считаем две карты attention с раздельными проекциями Q/K и вычитаем одну из другой. Убивает «attention sink», который сливает вес в первые несколько токенов. DIFF Transformer от Microsoft (2024).

Они уживаются вместе. Передовая модель 2026 года обычно их смешивает: большинство слоёв — SWA-1024, каждый пятый — глобальный полный attention, плюс горстка differential-голов, которые вычищают ретривал. Соотношение 5:1 между SWA и global у Gemma 3 — текущее умолчание из учебника.

> 🎒 **На пальцах.** Прикиньте масштаб: 128K токенов в квадрате — это 16 миллиардов чисел на один слой, и таких слоёв 80. Sliding window с окном 1024 оставляет от каждой строки только 1024 колонки вместо 128 000, то есть в 128 раз меньше. Именно поэтому длинный контекст в 2026-м вообще существует: полный круг никто не строит.

## The Concept

### Sliding Window Attention (SWA)

Каждый query на позиции `i` смотрит только на позиции из `[i - W, i]` (причинный SWA) или `[i - W/2, i + W/2]` (двунаправленный). Токены вне окна получают `-inf` в матрице оценок.

```
full causal:           sliding window (W=4):
positions 0-7          positions 0-7, W=4
    0 1 2 3 4 5 6 7        0 1 2 3 4 5 6 7
0 | x                0 |  x
1 | x x              1 |  x x
2 | x x x            2 |  x x x
3 | x x x x          3 |  x x x x
4 | x x x x x        4 |    x x x x
5 | x x x x x x      5 |      x x x x
6 | x x x x x x x    6 |        x x x x
7 | x x x x x x x x  7 |          x x x x
```

Для `N = 8192` и `W = 1024` в матрице оценок примерно 7.9M ненулевых **ячеек** (`Σᵢ min(i+1, W)`) против 33.6M у полного причинного attention (`N(N+1)/2`) — сокращение в 4.3 раза. Часто вместо этого называют «8×»: так получается, если сравнивать `N·W` с полным `N²` = 67M и тихо забыть, что причинная маска уже выбросила половину матрицы.

> 🎒 **На пальцах.** Посмотрите на правую картинку: строка 7 отмечена только в колонках 4-7, а всё, что левее, отрезано. То есть седьмой токен буквально не помнит про нулевой. При `W = 4` каждая строка после разогрева содержит ровно 4 крестика, сколько бы токенов ни было всего.

**KV cache shrinks with SWA.** На слой нужно хранить только последние `W` токенов K и V. Для конфигурации в духе Gemma 3 (окно 1024, контекст 128K) KV cache падает в 128 раз.

**Quality cost.** Трансформеры на одном SWA плохо справляются с поиском на длинных дистанциях. Лечение: чередовать слои SWA со слоями полного attention. Gemma 3 использует SWA:global как 5:1. Mistral 7B использовал стопку причинных SWA, где информация «течёт вперёд» через перекрывающиеся окна — каждый слой расширяет эффективное поле зрения на `W − 1`, поэтому после `L` слоёв модель дотягивается на `L·(W − 1) + 1` токенов назад. Посчитайте по картинке выше: 4 слоя с окном `W = 4` дают 13 токенов, а не 16.

> 🎒 **На пальцах.** Эффект перекрытия — как испорченный телефон, только полезный. С окном 1024 первый слой видит 1024 токена назад, но второй слой смотрит на выходы первого, а те уже впитали свои 1024. После 30 слоёв получается 30 × 1024 ≈ 30 тысяч токенов охвата, хотя ни один слой не смотрел дальше тысячи.

### Sparse / Block Attention

Выбираем шаблон разреженности `N × N` заранее. Три канонических формы:

- **Local + strided (sparse transformer от OpenAI).** Смотрим на последние `W` токенов плюс на каждый `stride`-й токен до этого. Ловит и локальное, и дальнее за `O(N · sqrt(N))` вычислений.
- **Longformer / BigBird.** Локальное окно плюс небольшой набор глобальных токенов (например, `[CLS]`), которые смотрят на всех и на которых смотрят все, плюс случайные разреженные связи. Эмпирически контекст в 2 раза длиннее при том же качестве.
- **Native Sparse Attention (DeepSeek, 2025).** Учим модель понимать, какие блоки `(Q, K)` важны; нулевые блоки пропускаем прямо на уровне ядра. Совместимо с FlashAttention.

Sparse attention — это история про инженерию ядер. Математика простая (замаскировать матрицу оценок); выигрыш берётся из того, что нулевые элементы вообще не загружаются в SRAM. FlashAttention-3 и API FlexAttention образца 2026 года делают свои разреженные шаблоны полноправным гражданином PyTorch.

> 🎒 **На пальцах.** Ключевая мысль здесь контринтуитивная: умножение на ноль ничего не стоит, а вот доставка этого нуля из памяти в чип стоит всё. Замаскировать матрицу 8192 × 8192 в лоб — значит всё равно её прочитать. Ядро sparse attention просто не открывает эти страницы памяти, поэтому экономия реальная, а не бумажная.

### Differential Attention (DIFF Transformer, 2024)

У обычного attention есть проблема «attention sink»: softmax заставляет каждую строку суммироваться в 1, поэтому токены, которым в общем-то не на что смотреть, сваливают вес на первый токен (или на первые несколько). Это ворует ёмкость, которая должна была уйти на реальное содержимое.

Differential attention чинит это, считая **две** карты attention и вычитая одну из другой:

```
A1 = softmax(Q1 K1^T / √d)
A2 = softmax(Q2 K2^T / √d)
DiffAttn = (A1 - λ · A2) V
```

где `λ` — обучаемый скаляр (обычно 0.5-0.8). A1 ловит веса реального содержимого; A2 ловит сток. Вычитание гасит сток и перераспределяет вес на релевантные токены.

> 🎒 **На пальцах.** Softmax обязан раздать ровно 100 % веса, даже когда раздавать некому. Представьте голосование, где нельзя воздержаться: все «неопределившиеся» голоса автоматом уходят первому кандидату в бюллетене. Differential attention считает те же выборы дважды и вычитает — фон, одинаковый в обоих подсчётах, сокращается, остаётся только осмысленный сигнал.

Заявленные результаты (Microsoft, 2024): перплексия ниже на 5-10 %, эффективный контекст в 1.5-2 раза длиннее при той же длине обучения, более чёткий поиск иголки в стоге сена.

### Variant Comparison

| Variant | Compute | KV cache | Quality vs full | Production use |
|---------|---------|----------|-----------------|----------------|
| Полный attention | O(N²) | O(N) на слой | базовый уровень | слой по умолчанию в любой модели |
| SWA (окно 1024) | O(N·W) | O(W) на слой | -0.1 ppl, хорошо в паре с global-слоями | Gemma 2/3, Phi-3-Long |
| Local + strided sparse | O(N·√N) | смешанный | примерно как SWA | sparse transformer от OpenAI, Longformer |
| BigBird (local + global + random) | примерно O(N) | смешанный | догоняет полный при вдвое длиннее контексте | ранние long-context BERT |

## Build It

Смотрите `code/main.py`. Мы реализуем сравнитель причинных масок, который показывает full, SWA, local+strided и differential attention бок о бок на игрушечной последовательности.

### Step 1: full causal mask (baseline)

```python
def causal_mask(n):
    return [[0.0 if j <= i else float("-inf") for j in range(n)] for i in range(n)]
```

Базовый вариант из урока 07. Нижнетреугольная матрица; нулевой вес выше диагонали.

> 🎒 **На пальцах.** Здесь `0.0` значит «смотреть можно», а `-inf` — «нельзя». Логика перевёрнута только на первый взгляд: эти числа прибавляются к оценкам до softmax, поэтому ноль ничего не меняет, а минус бесконечность после `exp` даёт ровно нулевой вес. Для `n = 8` таких `-inf` будет 28 штук — это верхний треугольник.

### Step 2: sliding window causal mask

```python
def swa_mask(n, window):
    M = [[float("-inf")] * n for _ in range(n)]
    for i in range(n):
        lo = max(0, i - window + 1)
        for j in range(lo, i + 1):
            M[i][j] = 0.0
    return M
```

Один параметр — `window`. При `window >= n` вы получаете обратно полный причинный attention. При `window = 1` каждый токен смотрит только на себя.

> 🎒 **На пальцах.** Вся разница со Step 1 в одной строке: `lo = max(0, i - window + 1)` вместо нуля. Для `i = 7` и `window = 4` получается `lo = 4`, то есть открыты колонки 4, 5, 6, 7 — ровно четыре. Для `i = 2` выходит `lo = 0`, потому что назад просто нечего смотреть, и строка совпадает с полной причинной.

### Step 3: local + strided sparse mask

```python
def strided_mask(n, window, stride):
    M = [[float("-inf")] * n for _ in range(n)]
    for i in range(n):
        lo = max(0, i - window + 1)
        for j in range(lo, i + 1):
            M[i][j] = 0.0
        for j in range(0, i + 1, stride):
            M[i][j] = 0.0
    return M
```

Плотное локальное окно плюс каждый `stride`-й токен до самого начала последовательности. С добавлением слоёв поле зрения растёт логарифмическими шагами.

**Обратите внимание на побочный эффект:** `range(0, i + 1, stride)` всегда начинается с `j = 0`, потому что нуль делится на любой stride. Значит, *каждая* строка смотрит на позицию 0 — этот паттерн бесплатно протаскивает глобальный токен в духе Longformer. Обычно это хорошо (стоку появляется куда законно сливаться), но это ваше проектное решение, а не случайность в устройстве цикла, и надо отдавать себе отчёт, что вы его приняли.

> 🎒 **На пальцах.** Второй цикл — это «маячки». При `stride = 8` и `i = 100` он открывает позиции 0, 8, 16, ... 96, то есть 13 дополнительных колонок вместо 100. Токен получает подробную картину рядом с собой и редкие опорные точки вдали — как водитель, который видит дорогу под колёсами и километровые столбы на горизонте. И заметьте первый «столб» в этом списке: нуль. Запустите скрипт и посмотрите на нулевую колонку в распечатке маски `local (W=2) + strided (stride=3)` — она забита крестиками сверху донизу, в каждой строке без исключения.

### Step 4: differential attention

```python
def diff_attention(Q1, K1, Q2, K2, V, lam):
    A1 = softmax_causal(Q1 @ K1.T / sqrt_d)
    A2 = softmax_causal(Q2 @ K2.T / sqrt_d)
    return (A1 - lam * A2) @ V
```

Два прохода attention, вычитание с обучаемым коэффициентом смешивания. В коде мы сравниваем веса attention для одиночного и differential варианта и смотрим, как сток схлопывается: позиция 0 падает с 61% строки до 11% при `λ = 0.8`.

Одна оговорка про эту демонстрацию: сток **выучивается**, он не появляется сам. На случайных Q/K позиция 0 получает обычный случайный вес, и никакого стока нет. Поэтому `code/main.py` строит руками ту структуру, к которой сходится обученная модель — ключ с большой нормой на позиции 0, направленный вдоль смещения, которое несёт в себе каждый query, — и только потом вычитает её. Если вы прогоните демо на чисто случайных тензорах и не увидите стока, это правильный результат, а не сломанный скрипт.

> 🎒 **На пальцах.** Обратите внимание, что `V` тут один на оба прохода — удваиваются только Q и K. Если `lam = 0.6`, а обе карты дали токену 0 вес 0.5, то итог будет `0.5 - 0.6 * 0.5 = 0.2`: сток просел больше чем вдвое. А токен, которому A1 дал 0.3, а A2 всего 0.05, получит `0.3 - 0.03 = 0.27` и почти не пострадает.

### Step 5: KV cache sizes

Напечатайте размер кеша на слой при `N = 131072` для каждого варианта. SWA и разреженные варианты дают падение в 10-100 раз. Differential удваивает. Платите по счетам за память осознанно.

> 🎒 **На пальцах.** Прикиньте счёт руками: 131 072 токена против окна 1024 — это отношение 128:1. Если полный KV cache занимал 40 ГБ, то со SWA останется около 320 МБ на те же слои, а differential тот же полный кеш превратит в 80 ГБ. Один параметр в конфиге двигает потребление видеопамяти на два порядка.

## Use It

Продакшен-паттерны 2026 года:

```python
from transformers import AutoModelForCausalLM
# Gemma 3 mixes SWA (window=1024) and global layers at 5:1.
model = AutoModelForCausalLM.from_pretrained("google/gemma-3-27b-it")
# print(model.config.sliding_window, model.config.layer_types)
```

FlexAttention в PyTorch 2.5+ принимает функцию маски:

```python
from torch.nn.attention.flex_attention import flex_attention, create_block_mask

def swa_pattern(b, h, q_idx, kv_idx):
    return (q_idx - kv_idx < 1024) & (q_idx >= kv_idx)

mask = create_block_mask(swa_pattern, B=batch, H=heads, Q_LEN=n, KV_LEN=n)
out = flex_attention(q, k, v, block_mask=mask)
```

Это компилируется в свой Triton-ядро. Для типовых шаблонов — в пределах 10 % от скорости FlashAttention-3, при том что функция маски остаётся обычным вызываемым объектом Python.

> 🎒 **На пальцах.** Разберите `swa_pattern` по частям: `q_idx >= kv_idx` — это причинность («не подглядывай в будущее»), а `q_idx - kv_idx < 1024` — это окно («не помни глубже тысячи»). Две строки булевой логики вместо ручного ядра на CUDA, и на выходе почти та же скорость.

**When to pick each:**

- **Pure full attention** — каждый слой вплоть до контекста ~16K, либо когда качество поиска превыше всего.
- **SWA + global mix** — длинный контекст (>32K), обучение и инференс упираются в память. Умолчание 2026 года выше 32K.
- **Sparse block attention** — своё ядро, свой шаблон. Оставьте для специализированных нагрузок (ретривал, аудио).
- **Differential attention** — любая нагрузка, где загрязнение от attention sink вредит (long-context RAG, поиск иголки в стоге сена).

> 🎒 **На пальцах.** Практическое правило одно: до 16K не выпендривайтесь, полный attention дешевле по инженерным силам. Порог 32K — это примерно 40 страниц текста; ниже него экономия не окупает сложность, выше — вы просто не влезете в память.

3. **Hard.** Реализуйте в капстоун-модели смесь слоёв 5:1 в стиле Gemma 3 (5 SWA, 1 global). Сравните loss, память и качество генерации с чистым SWA и чистым global при равном числе параметров.
4. **Hard.** Реализуйте differential attention с обучаемым `λ` на каждую голову. Обучите на синтетической задаче поиска (одна иголка, 2000 отвлекающих). Измерьте точность поиска против базовой модели с одиночным attention при равном числе параметров.

> 🎒 **На пальцах.** Подсказка к первому заданию: сравнивать маски надо именно побитово, а не «на глаз». При `window = n` формула `lo = max(0, i - n + 1)` всегда даёт 0, значит `swa_mask` обязана совпасть с `causal_mask` элемент в элемент. Если не совпала — вы ошиблись на единицу в границе окна, это классический промах в этом коде.

## Key Terms

| Term | What people say | What it actually means |
|------|-----------------|-----------------------|
| Sliding window attention (SWA) | "Local attention" | Каждый query смотрит на свои последние `W` токенов; KV cache ужимается до `O(W)`. |
| Effective receptive field | "How far back the model sees" | В стопке из `L` слоёв SWA с окном `W` — до `L·(W − 1) + 1` токенов. |
| Longformer / BigBird | "Local + global + random" | Разреженные шаблоны с несколькими вечно доступными глобальными токенами; ранний подход к длинному контексту. |
| Native Sparse Attention | "DeepSeek's kernel trick" | Обучаемая разреженность на уровне блоков; нулевые блоки пропускаются в ядре без потери качества. |
| Differential attention | "Two maps, one subtracts" | DIFF Transformer: вычесть из первой карты attention вторую, умноженную на обучаемое `λ`, чтобы погасить attention sink. |
| Attention sink | "Weight bleeds to token 0" | Нормировка softmax заставляет строки суммироваться в 1; неинформативные query сваливают вес на позицию 0. |
| FlexAttention | "Mask-as-Python" | API из PyTorch 2.5+, который компилирует произвольные функции маски в ядра формата FlashAttention. |
| Layer type mix | "5:1 SWA-to-global" | Чередование разреженных и полных слоёв attention в стопке, чтобы держать качество при меньшей памяти. |
