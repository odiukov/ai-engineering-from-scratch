# Speculative decoding — черновик, проверка, повтор

> Авторегрессивное декодирование последовательно. Каждый токен ждёт предыдущего. Speculative decoding рвёт цепочку: дешёвая модель набрасывает N токенов, дорогая проверяет все N за один forward pass. Когда черновик угадал, вы заплатили один большой forward за N сгенерированных токенов.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 7 · 07 (GPT Causal LM), Phase 7 · 12 (KV Cache & Flash Attention)
**Time:** ~60 minutes

## The Problem

LLM на 70B выдаёт один токен примерно за 30 мс на H100. Draft-модель на 3B — примерно за 3 мс. Если дать 3B набросать 5 токенов вперёд, а потом запустить 70B *один раз*, чтобы проверить все 5, то суммарно выходит `5×3 + 30 = 45 мс` на пять принятых токенов — против `5×30 = 150 мс` при обычной построчной генерации. Вот и весь смысл speculative decoding: обменять немного лишней видеопамяти (draft-модель) на снижение latency декодирования в 2-4 раза.

Фокус обязан сохранять распределение. Speculative sampling, предложенный Leviathan et al. (2023) и параллельно Chen et al., гарантирует, что выходная последовательность **распределена в точности так же**, как если бы большая модель писала её сама. Никакого размена на качество. Просто быстрее.

В инференсе 2026 года господствуют четыре семейства пар «черновик — проверяющий»:

1. **Vanilla speculative (Leviathan 2023).** Отдельная draft-модель (например, Llama 3 1B) плюс verifier (например, Llama 3 70B).
2. **Medusa (Cai 2024).** Несколько декодирующих голов на самом verifier предсказывают позиции `t+1..t+k` параллельно. Отдельная draft-модель не нужна.
3. **Семейство EAGLE (Li 2024, 2025).** Лёгкий черновик, который переиспользует скрытые состояния verifier; доля принятия выше, чем у vanilla; типично 3-4 раза ускорения.
4. **Lookahead decoding (Fu 2024).** Итерация Якоби; draft-модель не нужна вообще. Само-спекуляция. Нишевая штука, зато без зависимостей.

Любой продакшен-стек инференса в 2026 году поставляется со speculative decoding по умолчанию. vLLM, TensorRT-LLM, SGLang и llama.cpp поддерживают как минимум vanilla и EAGLE-2.

> 🎒 **На пальцах.** Пересчитайте арифметику из первого абзаца сами: пять маленьких шагов по 3 мс — это 15 мс, плюс одна большая проверка 30 мс, итого 45 мс на пять токенов, то есть 9 мс на токен вместо 30. Ключ в том, что большая модель проверяет все пять токенов за один проход: ей всё равно, один токен обрабатывать или пять, она упирается в чтение весов из памяти, а не в счёт.

## The Concept

### The core algorithm

Даны verifier `M_q` и более дешёвый черновик `M_p`:

1. Пусть `x_1..x_k` — уже раскодированный префикс.
2. **Draft**: с помощью `M_p` авторегрессивно предлагаем `d_{k+1}, d_{k+2}, ..., d_{k+N}` с вероятностями черновика `p_1..p_N`.
3. **Verify in parallel**: запускаем `M_q` один раз на `x_1..x_k, d_{k+1}, ..., d_{k+N}` и получаем вероятности verifier `q_1..q_{N+1}` для позиций `k+1..k+N+1`.
4. **Accept/reject each draft token left to right**: для каждого `i` принимаем с вероятностью `min(1, q_i(d_i) / p_i(d_i))`.
5. При первом отказе на позиции `j`: сэмплируем `t_j` из нормированного «остаточного» распределения `(q_j - p_j)_+`. Все черновики после `j` выбрасываем.
6. Если приняли все `N`: сэмплируем один лишний токен `t_{N+1}` из `q_{N+1}` (бесплатный бонусный токен).

Трюк с остаточным распределением — это и есть математическая находка, благодаря которой выход распределён ровно так, будто `M_q` сэмплировал с нуля.

> 🎒 **На пальцах.** Разберите правило принятия на числах. Черновик предложил слово с вероятностью 0.4, а большая модель считает его вероятность 0.6. Отношение `0.6 / 0.4 = 1.5`, `min(1, 1.5) = 1` — принимаем всегда. Наоборот: черновик уверен на 0.9, а большая модель даёт 0.3, отношение 0.33 — принимаем примерно в трети случаев, в остальных откатываемся к остаточному распределению.

> 🎒 **На пальцах.** Почему бонусный токен «бесплатный»: verifier за один проход считает распределения не только для N черновых позиций, но и для следующей за ними. Если все 5 черновиков приняты, распределение шестого токена уже посчитано и лежит в памяти. Не взять его было бы расточительством — поэтому пять принятых черновиков дают шесть новых токенов.

### What determines speedup

Пусть `α` — ожидаемая доля принятия на один черновой токен. Пусть `c` — отношение стоимости черновика к verifier. На шаг:

- Наивная генерация делает 1 вызов большой модели на токен.
- Speculative делает 1 вызов большой модели на `(1 - α^{N+1}) / (1 - α) ≈ 1/(1-α)` токенов, когда `α` велика.

Типовое эмпирическое правило при `α = 0.75` и `N = 5`: вызовов большой модели втрое меньше. Черновик обходится в 5 раз дешевле. Общее время по часам падает примерно в 2.5 раза.

**α depends on:**

- Насколько хорошо черновик приближает verifier. Одно семейство и одни данные обучения заметно поднимают α.
- Стратегия декодирования. Жадный черновик против жадного verifier — высокая α. Sampling с температурой попасть труднее, доля принятия падает.
- Тип задачи. Код и структурированный вывод принимаются чаще (предсказуемо); свободное творческое письмо — реже.

> 🎒 **На пальцах.** Подставьте `α = 0.75` и `N = 5` в формулу: `(1 - 0.75^6) / (1 - 0.75) = (1 - 0.178) / 0.25 ≈ 3.3` токена за один вызов большой модели. При `α = 0.5` та же формула даёт всего 1.97. Разница между «черновик угадывает в трёх случаях из четырёх» и «в половине» — это разница между ускорением втрое и вдвое.

### Medusa — drafts without a draft model

Medusa заменяет draft-модель дополнительными выходными головами на самом verifier. На позиции `t`:

```
shared trunk → hidden h_t
    ├── head_0: predict token at t+1  (standard LM head)
    ├── head_1: predict token at t+2
    ├── head_2: predict token at t+3
    ├── head_3: predict token at t+4
```

Каждая голова выдаёт свои логиты. На инференсе вы сэмплируете из каждой головы, получаете последовательность-кандидат, а потом проверяете её одним forward pass по схеме tree attention, которая рассматривает все продолжения-кандидаты разом.

Плюсы: второй модели нет. Минусы: добавляются обучаемые параметры; нужна стадия supervised fine-tuning (примерно 1B токенов); доля принятия чуть ниже, чем у vanilla speculative с хорошим черновиком.

> 🎒 **На пальцах.** Головы Medusa — это как один человек, который пишет фразу и тут же угадывает, чем она закончится. `head_0` — обычная голова языковой модели, она предсказывает следующий токен. `head_1` перепрыгивает через один и целится в `t+2`, `head_2` — в `t+3`. Угадывать через голову объективно труднее, поэтому дальние головы ошибаются чаще, и доля принятия падает с каждой следующей позицией.

### EAGLE — better draft by reusing hidden states

EAGLE-1/2/3 (Li et al., 2024-2025) делает draft-моделью крошечный трансформер (обычно один слой), который получает на вход скрытые состояния последнего слоя verifier. Поскольку черновик видит признаковое представление verifier, его предсказания сильно коррелируют с выходным распределением verifier. Доля принятия поднимается с примерно 0.6 (vanilla) до 0.85 и выше.

EAGLE-3 (2025) добавил древовидный поиск по продолжениям-кандидатам. vLLM и SGLang поставляют EAGLE-2/3 как путь спекуляции по умолчанию для Llama 3/4 и Qwen 3.

> 🎒 **На пальцах.** Обычная draft-модель угадывает только по тексту — как коллега, который видит написанное и пытается предугадать вашу мысль. EAGLE читает скрытые состояния verifier, то есть подглядывает прямо в его черновые размышления. Отсюда и скачок α с 0.6 до 0.85: подставьте это в формулу выше, и вместо 2.5 токена на проход получится около 5.

### The KV cache dance

Проверка загоняет `N` черновых токенов в verifier за один forward pass. Это удлиняет KV cache verifier на `N` записей. Если часть черновиков отвергнута, кеш надо откатить до длины принятого префикса.

Продакшен-реализации (`--speculative-model` у vLLM, LookaheadDecoder у TensorRT-LLM) решают это черновыми KV-буферами. Сначала пишем, при принятии — фиксируем. Концептуально несложно, но возни много.

> 🎒 **На пальцах.** Это как черновик в тетради на отдельном листке. Записали 5 предположений, три подошли — переписываем в чистовик только три, остальное зачёркиваем. Если забыть откатить кеш, модель на следующем шаге будет считать отвергнутые токены частью текста, и генерация тихо развалится: ошибки не будет, просто пойдёт бессвязица.

## Build It

Смотрите `code/main.py`. Мы реализуем ядро алгоритма speculative sampling (шаг отказа плюс остаточное распределение) вместе с:

- «Большой моделью», которая представляет собой детерминированный softmax над заданным вручную распределением (чтобы проверять арифметику принятия аналитически).
- «Draft-моделью», которая является возмущением большой модели.
- Циклом принятия / отказа, который даёт то же маргинальное распределение, что и прямое сэмплирование.

### Step 1: the rejection step

```python
def accept_or_reject(q_prob, p_prob, draft_token, u):
    ratio = q_prob / p_prob if p_prob > 0 else float("inf")
    return u < min(1.0, ratio)
```

`u` — равномерное случайное число. `q_prob` — вероятность черновикового токена по мнению verifier. `p_prob` — вероятность по мнению draft-модели. Теорема Leviathan гласит, что это решение по Бернулли, дополненное сэмплированием из остатка при отказе, сохраняет распределение verifier в точности.

> 🎒 **На пальцах.** Строка с `u < min(1.0, ratio)` — это подбрасывание монетки с нужным перекосом. `u` равномерно лежит между 0 и 1, поэтому условие `u < 0.33` срабатывает ровно в 33 % случаев. Когда `ratio` больше единицы, `min` обрезает его до 1, и условие выполняется всегда — большая модель ценит токен даже выше, чем черновик, отказываться незачем.

### Step 2: residual distribution

```python
def residual_dist(q, p):
    raw = [max(0.0, qi - pi) for qi, pi in zip(q, p)]
    s = sum(raw)
    return [r / s for r in raw]
```

Вычитаем `p` из `q` поэлементно, отрицательные значения зажимаем в ноль, перенормируем. Из этого распределения сэмплируем при любом отказе.

> 🎒 **На пальцах.** Возьмите три токена: `q = [0.5, 0.3, 0.2]`, `p = [0.9, 0.05, 0.05]`. Разности дают `[-0.4, 0.25, 0.15]`, после зажима — `[0, 0.25, 0.15]`, после нормировки — `[0, 0.625, 0.375]`. Смысл прозрачен: токен, который черновик переоценил, в замене запрещён совсем, а вес уходит тем, кого черновик недооценил.

### Step 3: one speculative step

```python
def spec_step(prefix, q_model, p_model, N, rng):
    drafts = []
    p_probs = []
    ctx = list(prefix)
    for _ in range(N):
        p_dist = p_model(ctx)
        d = sample(p_dist, rng)
        drafts.append(d)
        p_probs.append(p_dist[d])
        ctx.append(d)

    q_dists = [q_model(prefix + drafts[:i]) for i in range(N + 1)]

    for i, d in enumerate(drafts):
        u = rng.random()
        q_prob = q_dists[i][d]
        p_prob = p_probs[i]
        if u < min(1.0, q_prob / p_prob if p_prob > 0 else float("inf")):
            prefix = prefix + [d]
        else:
            res = residual_dist(q_dists[i], p_model(prefix))
            prefix = prefix + [sample(res, rng)]
            return prefix
    prefix = prefix + [sample(q_dists[N], rng)]
    return prefix
```

Пять принятых плюс один бонусный — шесть токенов за один проход verifier.

Держите эти два счётчика раздельно. Шаг выдаёт `n_accepted + 1` токенов, где `n_accepted ∈ [0, N]` — это сколько *черновиков* пережило проверку, а `+1` — ровно один добавочный токен: либо перевыборка из residual при отказе, либо бонус из `q_{N+1}` при полном принятии. Никогда оба сразу. Именно поэтому `spec_step_n` в `code/main.py` возвращает `(final_token, n_accepted, is_bonus)`: если свернуть бонус в счётчик принятых, функция начнёт сообщать `N+1` принятых из `N` черновиков.

> 🎒 **На пальцах.** Соблазн написать `accepted + 1` одним числом велик, но тогда вы теряете возможность отличить «приняли все 5 черновиков и взяли бонус» от «приняли 5 черновиков, а шестой откуда-то взялся» — а второго не бывает вовсе, черновиков-то всего пять. Проверьте на крайних случаях: отказ на самом первом черновике — это `n_accepted = 0` и один токен из residual, итого 1 токен за проход verifier, то есть спекуляция не дала ничего, но и не сломала распределение. Полное принятие — это `n_accepted = 5` и бонус, итого 6. Скрипт печатает средние по 20 000 шагов и проверяет инвариант ассертом.

> 🎒 **На пальцах.** Проследите за переменной `prefix`: она растёт только на принятых токенах. Первый цикл набирает `N` черновиков в `drafts`, второй проходит их слева направо и при первом же отказе делает `return`, отбрасывая весь хвост. Именно поэтому доля принятия входит в формулу в степени: чтобы дожить до пятого токена, надо выиграть подряд пять раз.

### Step 4: measure acceptance rate

Прогоните 10 000 спекулятивных шагов при разном качестве черновика. Постройте график доли принятия против KL-дивергенции между распределениями черновика и verifier. Вы должны увидеть чистую монотонную зависимость.

> 🎒 **На пальцах.** KL-дивергенция здесь — просто мера «насколько черновик врёт». Ноль означает, что распределения совпадают и принимается вообще всё. Чем дивергенция больше, тем чаще отношение `q/p` проваливается ниже единицы и тем чаще срабатывает отказ. Монотонная кривая на графике и есть доказательство, что α — не магия, а функция от близости двух моделей.

### Step 5: verify distribution equivalence

Эмпирически: гистограмма токенов, выданных спекулятивным циклом, должна совпасть с гистограммой прямого сэмплирования из verifier. Это и есть теорема Leviathan на практике. Критерий хи-квадрат подтверждает совпадение в пределах ошибки сэмплирования.

> 🎒 **На пальцах.** Это самый важный тест урока. Он проверяет не скорость, а честность: если гистограммы совпали, значит speculative decoding не подменил вам модель на кривую. Слабое место здесь — сама проверка: на 1000 сэмплов хи-квадрат пропустит и заметный перекос, поэтому в задании и стоит 50 000 токенов.

## Use It

Продакшен:

```bash
# vLLM with EAGLE
vllm serve meta-llama/Llama-3.1-70B-Instruct \
    --speculative-model /models/llama-3.1-eagle-70b \
    --speculative-draft-tensor-parallel-size 1 \
    --num-speculative-tokens 5

# vLLM with vanilla draft model
vllm serve meta-llama/Llama-3.1-70B-Instruct \
    --speculative-model meta-llama/Llama-3.2-1B-Instruct \
    --num-speculative-tokens 5
```

У TensorRT-LLM на середину 2026 года самый быстрый путь для Medusa. `faster-whisper` заворачивает speculative decoding для Whisper-large с маленьким черновиком.

**Picking a draft:**

| Strategy | When to pick | Speedup |
|----------|--------------|---------|
| Vanilla draft (1B/3B из семейства Llama) | Быстрый прототип, обучать ничего не надо | 1.8-2.3× |
| Medusa heads | Есть возможность дообучить verifier | 2-3× |
| EAGLE-2 / 3 | Продакшен, максимальная скорость | 3-4× |
| Lookahead | Ни черновика, ни обучения, ни лишних параметров | 1.3-1.6× |

> 🎒 **На пальцах.** Таблица читается как лесенка «сколько работы вы готовы вложить». Vanilla — скачали вторую модель, получили ускорение вдвое, потратили день. EAGLE — обучили специальный черновик под свой verifier, получили вчетверо, потратили недели. Lookahead ничего не требует и даёт всего процентов сорок, зато его можно включить прямо сегодня.

**When NOT to spec-decode:**

- Генерация одной последовательности длиной 1-5 токенов. Накладные расходы съедают выигрыш.
- Дико творческий sampling с высокой температурой (α падает).
- Развёртывания, ограниченные по памяти (draft-модель отъедает видеопамять).

> 🎒 **На пальцах.** Первый пункт — арифметика: если ответ состоит из трёх токенов, а черновик набрасывает пять, вы посчитали два токена впустую и всё равно ждали проверку. Второй пункт про температуру: чем она выше, тем более непредсказуем выбор большой модели, тем реже черновик в него попадает, а при α около 0.3 формула даёт ускорение примерно в 1.4 раза — и то до вычета накладных расходов.

1. **Easy.** Запустите `code/main.py`. Убедитесь, что распределение спекулятивных токенов совпадает с распределением прямого сэмплирования из verifier на 50 000 токенов при p > 0.05 по хи-квадрату.
2. **Medium.** Постройте график ускорения (токенов на один forward большой модели) как функцию от `N` при `α = 0.5, 0.7, 0.85`. Найдите оптимальное `N` для каждой α. (Подсказка: ожидаемое число токенов на вызов проверки равно `(1 - α^{N+1}) / (1 - α)`.)
3. **Hard.** Реализуйте мини-Medusa: возьмите капстоун-GPT из урока 14, добавьте 3 дополнительные LM-головы, предсказывающие позиции t+2, t+3, t+4. Обучите на tinyshakespeare с совместным многоголовым loss. Сравните доли принятия с vanilla-черновиком, полученным усечением той же модели.
4. **Hard.** Реализуйте откат: начните с KV cache на префиксе из 10 токенов, подайте 5 черновых токенов, сымитируйте отказ на позиции 3. Убедитесь, что на следующей итерации чтения из кеша в точности соответствуют «префикс плюс первые 2 принятых черновика».

> 🎒 **На пальцах.** Подсказка ко второму заданию: `N` нельзя задирать бесконечно. При `α = 0.5` каждый следующий черновой токен доживает с вероятностью вдвое меньшей, поэтому после `N = 4` формула почти перестаёт расти (1.94 против 1.97), а платить за лишние шаги черновика вы продолжаете. При `α = 0.85` кривая насыщается только около `N = 8-10`. Оптимум всегда там, где прирост токенов перестал окупать стоимость черновика.

## Key Terms

| Term | What people say | What it actually means |
|------|-----------------|-----------------------|
| Draft model | "The cheap one" | Модель поменьше, которая предлагает токены-кандидаты; обычно в 10-50 раз дешевле verifier. |
| Verifier | "The big one" | Целевая модель, распределение которой мы сохраняем; запускается один раз за спекулятивный шаг. |
| Acceptance rate (α) | "How often the draft is right" | Вероятность на токен, что verifier примет черновик. Типично 0.7-0.9. |
| Residual distribution | "The rejection fallback" | Нормированное `(q - p)_+`; сэмплирование из него при отказе сохраняет распределение verifier. |
| Bonus token | "The free one" | Когда приняты все N черновиков, сэмплируем ещё один из распределения verifier для следующего шага. |
| Medusa | "Draft-less speculative" | Несколько LM-голов на verifier параллельно предсказывают позиции t+1..t+k. |
| EAGLE | "Hidden-state draft" | Крошечный трансформер-черновик, обусловленный скрытыми состояниями последнего слоя verifier. |
| Lookahead decoding | "Jacobi iteration" | Само-спекуляция через итерацию до неподвижной точки; draft-модели нет. |
| Tree attention | "Verify many candidates at once" | Ветвящаяся проверка, которая рассматривает несколько черновых продолжений одновременно. |
| KV rollback | "Undo rejected drafts" | Черновой KV-буфер; при принятии фиксируем, при отказе выбрасываем. |

- [vLLM docs — Speculative Decoding](https://docs.vllm.ai/en/latest/features/spec_decode.html) — каноническая продакшен-справка со всеми четырьмя стратегиями.
