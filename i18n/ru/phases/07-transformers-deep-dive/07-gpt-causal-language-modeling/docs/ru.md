# GPT — языковое моделирование с causal-маской

> BERT видит обе стороны. GPT видит только прошлое. Треугольная маска — самая значимая одна строка кода в современном AI.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 7 · 02 (Self-Attention), Phase 7 · 05 (Full Transformer), Phase 7 · 06 (BERT)
**Time:** ~75 minutes

## The Problem

Языковая модель отвечает на один вопрос: даны первые `t-1` токенов — каково распределение вероятностей над токеном `t`? Обучите модель на этом сигнале (next-token prediction) — и получите модель, которая умеет порождать произвольный текст по одному токену за шаг.

Чтобы обучать её end-to-end сразу на всей последовательности параллельно, предсказание в каждой позиции должно зависеть только от более ранних позиций. Иначе модель тривиально жульничает и подглядывает ответ.

Это и делает causal mask. Она устроена просто: верхнетреугольная матрица из `-inf`, которую прибавляют к attention-скорам перед softmax. После softmax эти позиции становятся нулями. Каждая позиция смотрит только на себя и на прошлое. А поскольку маску применяют один раз ко всей последовательности, за один forward pass вы получаете сразу N предсказаний следующего токена.

> 🎒 **На пальцах.** Маска — это лист бумаги, которым закрывают ещё не прочитанную часть строки. Возьмём последовательность из 4 токенов: позиция 0 видит 1 токен, позиция 1 — 2, позиция 2 — 3, позиция 3 — все 4. Итого 1 + 2 + 3 + 4 = 10 разрешённых пар из 16 клеток квадрата. Остальные 6 клеток — будущее, они закрыты.

GPT-1 (2018), GPT-2 (2019), GPT-3 (2020), GPT-4 (2023), GPT-5 (2025), Claude, Llama, Qwen, Mistral, DeepSeek, Kimi — все они decoder-only causal-трансформеры с одним и тем же ядром. Различаются они качеством данных, масштабом, архитектурными доработками и post-training (SFT, RLHF, DPO и их наследники).

> 🎒 **На пальцах.** Список моделей выглядит как список разных технологий, но внутри у них один и тот же цикл: «посмотри назад, предскажи следующий токен». Разница между GPT-2 и современной моделью — примерно как между школьником и профессором: устройство головы то же, отличаются объём прочитанного и годы тренировки.

## The Concept

![Causal mask creates a triangular attention matrix](../assets/causal-attention.svg)

### The mask

Для последовательности длины `N` строим матрицу `N × N`:

```
M[i, j] = 0       if j <= i
M[i, j] = -inf    if j > i
```

Прибавляем `M` к сырым attention-скорам перед softmax. `exp(-inf) = 0`, поэтому замаскированные позиции получают нулевой вес. Каждая строка attention-матрицы — распределение вероятностей только по предыдущим позициям.

Цена реализации: один вызов `torch.tril()`. Время вычисления: наносекунды. Влияние на область: всё.

> 🎒 **На пальцах.** Разберём одну строку. Пусть скоры в позиции 2 равны `[1.0, 2.0, 0.5, 3.0]`, а последнее число — будущее. Маска превращает их в `[1.0, 2.0, 0.5, -inf]`, softmax даёт примерно `[0.23, 0.62, 0.14, 0.00]`. Токен с самым большим скором 3.0 просто выпал из игры, а оставшиеся три веса честно сложились в единицу.

### Where the triangle comes from

Маску обычно подают как заплатку, прикрученную к attention. Пройдите вывод в обратную сторону — и мистика исчезнет: attention это третье уточнение обычного среднего по префиксу, а треугольник — границы цикла этого среднего, записанные в виде матрицы.

**Stage 1 — prefix average.** Самая тупая причинная сводка последовательности: позиция `i` становится средним позиций `0…i`. В виде цикла это `out[i] = X[:i+1].mean(0)`. То же самое вычисление — одно матричное умножение. Берём нижнетреугольную матрицу из единиц, делим каждую строку на её количество единиц, умножаем:

```python
import numpy as np

A = np.tril(np.ones((n, n)))
A = A / A.sum(axis=1, keepdims=True)
out = A @ X
```

Строка `i` матрицы `A` равна `[1/(i+1), …, 1/(i+1), 0, …, 0]`. Нули над диагональю — это и есть причинность. Будущее не маскировали; будущего никогда не было в сумме.

> 🎒 **На пальцах.** Возьмём `n = 3`. Строка 0 матрицы `A` = `[1, 0, 0]`, строка 1 = `[0.5, 0.5, 0]`, строка 2 = `[1/3, 1/3, 1/3]`. Это буквально «среднее по всему, что уже прочитано». Никакой маски здесь ещё нет — нули появились сами, потому что мы просто не складывали то, чего не видели.

**Stage 2 — learned weights.** Равномерное среднее считает все прошлые токены одинаково важными. Заменим единицы на обучаемую матрицу скоров `S`. Теперь строки уже не суммируются в единицу по построению, поэтому нормируем каждую строку через softmax, а не делением на счётчик. Softmax никогда не выдаёт точный ноль, а это ломает причинность — если только скоры будущего не подать как `-inf`, ведь `exp(-inf) = 0`:

```python
def softmax(x, axis):
    e = np.exp(x - np.max(x, axis=axis, keepdims=True))
    return e / e.sum(axis=axis, keepdims=True)

S = S + np.triu(np.full((n, n), -np.inf), k=1)
A = softmax(S, axis=1)
out = A @ X
```

Тот же треугольник, та же строчно-стохастическая матрица, тот же один matmul. Маска из `-inf` — это не новая машинерия. Это нули первой стадии, переведённые во входной домен softmax.

> 🎒 **На пальцах.** Softmax живёт в мире логарифмов: чтобы вес стал нулём, скор должен уйти в минус бесконечность. Если бы мы поставили не `-inf`, а `-100`, вес был бы примерно `e^-100` — не ноль, но и не отличим от нуля на практике. `-inf` просто честнее и не даёт ни капли утечки из будущего.

**Stage 3 — content-dependent weights.** На стадии 2 матрица `S` фиксируется после обучения: позиция 7 всегда взвешивает позицию 3 одинаково, что бы там ни было за токены. Пусть скоры зависят от самих токенов: `S = Q @ K.T / sqrt(d_k)`. Больше ничего не меняется. Маска, softmax, matmul — те же самые.

Три стадии, один инвариант: нижнетреугольная строчно-стохастическая матрица, умноженная на последовательность. Равномерное среднее, обученные статические веса, веса, зависящие от содержимого. Маску никогда не добавляли к attention. Она уцелела от среднего.

> 🎒 **На пальцах.** Сравните три стадии на позиции 2 из трёх токенов. Стадия 1 всегда даёт веса `[0.33, 0.33, 0.33]`. Стадия 2 даёт что-то вроде `[0.1, 0.6, 0.3]` — и так для любого текста. Стадия 3 даёт `[0.1, 0.6, 0.3]` на одной фразе и `[0.7, 0.2, 0.1]` на другой, потому что веса теперь считаются из самих слов.

### Parallel training, serial inference

Обучение: прогоняем всю последовательность `(N, d_model)` за один forward pass, считаем N cross-entropy-лоссов (по одному на позицию), усредняем, делаем backprop. Всё параллельно вдоль последовательности. Именно поэтому обучение GPT масштабируется — миллион токенов в батче обрабатывается за один проход по GPU.

Инференс: генерируем токен за токеном. Подали `[t1, t2, t3]` — получили `t4`. Подали `[t1, t2, t3, t4]` — получили `t5`. Подали `[t1, t2, t3, t4, t5]` — получили `t6`. KV cache (урок 12) хранит скрытые состояния `t1…tn`, чтобы не пересчитывать их на каждом шаге. Но последовательная глубина на инференсе равна длине вывода. Это налог авторегрессии и причина, по которой декодирование — узкое место по задержке у любой LLM.

> 🎒 **На пальцах.** Обучение похоже на проверку уже написанного диктанта: учитель видит весь текст и ставит 1000 отметок разом. Генерация — на сам диктант: 1000 токенов = 1000 отдельных проходов по модели, один за другим. Поэтому обучение считают в токенах в секунду на GPU, а генерацию — в токенах в секунду на один запрос, и вторая цифра всегда куда меньше.

### The loss — shift-by-one

Дана последовательность токенов `[t1, t2, t3, t4]`:

- Input: `[t1, t2, t3]`
- Targets: `[t2, t3, t4]`

Для каждой позиции `i` считаем `-log P(target_i | inputs[:i+1])`. **Усредняем по позициям.** Это среднее и есть cross-entropy для всей последовательности: усреднение, а не суммирование, оставляет лосс сравнимым между последовательностями разной длины — поэтому и все LM-фреймворки, и `cross_entropy_shifted` в `code/main.py` возвращают именно среднее.

Каждая трансформерная LM, о которой вы слышали, обучается на этом лоссе. Pre-training, fine-tuning, SFT — лосс тот же, данные разные.

> 🎒 **На пальцах.** Сдвиг на один — это просто «ответы = тот же текст, сдвинутый влево». Если модель дала правильному токену вероятность 0.5, её штраф равен `-log(0.5) ≈ 0.69`. Если 0.9 — штраф `0.105`. Если 0.01 — штраф `4.6`. Обучение весь день давит эти числа вниз, и ничего сверх этого не происходит.

### Decoding strategies

После обучения выбор способа сэмплирования значит больше, чем принято думать.

| Method | What it does | When to use |
|--------|--------------|-------------|
| Greedy | Берёт argmax на каждом шаге | Детерминированные задачи, автодополнение кода |
| Temperature | Делит логиты на T и сэмплирует | Творческие задачи, выше T — больше разнообразия |
| Top-k | Сэмплирует только из топ-k токенов | Убивает хвост из маловероятных вариантов |
| Top-p (nucleus) | Сэмплирует из наименьшего множества с накопленной вероятностью ≥ p | Дефолт с 2020 года; подстраивается под форму распределения |
| Min-p | Оставляет токены с `p ≥ min_p × max_p` | С 2024 года; отсекает длинные хвосты лучше, чем top-p |
| Speculative decoding | Черновая модель предлагает N токенов, большая проверяет | Ускорение в 2–3 раза при том же качестве |

В 2026 году min-p плюс temperature 0.7 — разумный дефолт для open-weights моделей. Speculative decoding — обязательная часть любого продакшн-стека инференса.

> 🎒 **На пальцах.** Возьмём распределение `[0.6, 0.2, 0.1, 0.05, 0.05]`. Greedy всегда берёт первый токен. Top-p при p = 0.9 оставит первые три (0.6 + 0.2 + 0.1 = 0.9) и выбросит хвост. Min-p при min_p = 0.1 оставит токены с вероятностью не ниже `0.1 × 0.6 = 0.06` — то есть тоже три первых. А если распределение плоское, `[0.25, 0.25, 0.25, 0.25]`, min-p оставит все четыре, потому что порог сам опустится до 0.025.

### What made the "GPT recipe" work

1. **Decoder-only.** Нет накладных расходов на энкодер. Один проход attention + FFN на слой.
2. **Scaling.** 124M → 1.5B → 175B → триллионы. Chinchilla scaling laws (урок 13) подсказывают, как тратить вычисления.
3. **In-context learning.** Проявилось где-то на 6B–13B. Модель следует few-shot примерам без дообучения.
4. **RLHF.** Post-training на человеческих предпочтениях превратил сырой предобученный текст в чат-ассистентов.
5. **Pre-norm + RoPE + SwiGLU.** Стабильное обучение на масштабе.

Базовая архитектура почти не менялась со времён GPT-2. Всё интересное происходило в данных, масштабе и post-training.

> 🎒 **На пальцах.** Обратите внимание на числа масштаба: от 124M до 175B — это рост примерно в 1400 раз, и всё это без смены архитектуры. Так бывает редко. Обычно инженерное решение упирается в потолок и требует переделки; здесь его просто продолжали раздувать, и оно продолжало работать лучше.

## Build It

### Step 1: the causal mask

Смотрите `code/main.py`. Одна строка:

```python
def causal_mask(n):
    return [[0.0 if j <= i else float("-inf") for j in range(n)] for i in range(n)]
```

Прибавьте её к attention-скорам перед softmax. Это весь механизм целиком.

> 🎒 **На пальцах.** Разберите условие `0.0 if j <= i else float("-inf")` вслух: «если колонка не правее строки — пропускаем, иначе закрываем». Для `n = 3` получается сетка `[[0, -inf, -inf], [0, 0, -inf], [0, 0, 0]]`. Ровно тот же треугольник, что и в стадии 1 выше, только записанный нулями и минус бесконечностями.

### Step 2: a 2-layer GPT-ish model

Ставим друг на друга два decoder-блока (masked self-attention + FFN, без cross-attention). Добавляем token embedding, positional encoding и unembedding (связанный с матрицей token embedding — стандартный трюк со времён GPT-2).

> 🎒 **На пальцах.** «Связанный unembedding» означает, что одна и та же таблица векторов используется и на входе, и на выходе. Для словаря в 50 000 токенов и `d_model = 768` это экономит 50000 × 768 ≈ 38 миллионов параметров — примерно треть маленькой модели. Плюс логика приятная: если два слова близки на входе, они близки и на выходе.

### Step 3: next-token prediction, end-to-end

На игрушечном словаре из 20 токенов выдаём логиты в каждой позиции. Считаем cross-entropy против цели, сдвинутой на один. Градиента нет — это проверка forward pass на вменяемость.

> 🎒 **На пальцах.** Необученная модель на словаре из 20 токенов даёт примерно равномерное распределение, то есть вероятность 1/20 = 0.05 правильному токену. Лосс получается `-log(0.05) ≈ 3.0`. Увидели около 3.0 — код работает. Увидели 0.1 или 40 — где-то баг, а не «модель уже гениальна».

### Step 4: sampling

Реализуем greedy, temperature, top-k, top-p, min-p. Прогоняем каждый на фиксированном промпте и сравниваем выводы. Функция сэмплирования — это 10 строк.

> 🎒 **На пальцах.** Temperature — это деление логитов перед softmax. Логиты `[2.0, 1.0]` при T = 1 дают `[0.73, 0.27]`, при T = 0.5 (делим на 0.5, то есть умножаем на 2) — `[0.88, 0.12]`, а при T = 2 — `[0.62, 0.38]`. Низкая температура заостряет распределение, высокая сглаживает. Только и всего.

## Use It

PyTorch, идиома 2026 года:

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-3.2-3B-Instruct")
tok = AutoTokenizer.from_pretrained("meta-llama/Llama-3.2-3B-Instruct")

prompt = "Attention is all you need because"
inputs = tok(prompt, return_tensors="pt")
out = model.generate(
    **inputs,
    max_new_tokens=64,
    temperature=0.7,
    top_p=0.9,
    do_sample=True,
)
print(tok.decode(out[0]))
```

Под капотом `generate()` делает forward pass, берёт логиты последней позиции, сэмплирует следующий токен, дописывает его и повторяет. Каждый продакшн-стек инференса LLM (vLLM, TensorRT-LLM, llama.cpp, Ollama, MLX) реализует тот же цикл с тяжёлой оптимизацией — батчевый prefill, continuous batching, пагинация KV cache, speculative decoding.

**GPT vs BERT, one line each:** GPT предсказывает `P(x_t | x_{<t})`. BERT предсказывает `P(x_masked | x_unmasked)`. Именно лосс определяет, умеет модель генерировать или нет.

> 🎒 **На пальцах.** Отсюда же следует, почему BERT нельзя попросить «допиши предложение». Он никогда не решал задачу «что дальше» — он всю жизнь восстанавливал дырки в уже готовом тексте. Архитектуры почти одинаковые, но одна строка про маску разводит их по разным профессиям.

## Exercises

1. **Easy.** Запустите `code/main.py` и убедитесь, что causal attention-матрица после softmax нижнетреугольная. Точечная проверка: в строке 3 веса должны быть только в колонках 0–3.
2. **Medium.** Реализуйте beam search шириной 4. Сравните perplexity beam-4 и greedy на 10 коротких промптах. Всегда ли beam выигрывает? (Подсказка: обычно для перевода, но не для открытого чата.)
3. **Hard.** Реализуйте speculative decoding: маленькая 2-слойная модель как черновик, 6-слойная как проверяющая. Замерьте ускорение по часам на 100 генерациях длиной 64. Убедитесь, что выводы совпадают с greedy проверяющей модели.

> 🎒 **На пальцах.** Подсказка к третьему заданию: черновая модель предлагает, скажем, 4 токена, большая проверяет их одним параллельным проходом. Если совпали первые 3 из 4 — вы получили 3 токена за один вызов большой модели вместо трёх. Отсюда и ускорение в 2–3 раза, и отсюда же требование: выход обязан быть побайтово равен greedy большой модели, иначе вы не ускорили, а испортили.

## Key Terms

| Term | What people say | What it actually means |
|------|-----------------|-----------------------|
| Causal mask | «Треугольник» | Верхнетреугольная матрица из `-inf`, прибавляемая к attention-скорам, чтобы позиция `i` видела только позиции `≤ i`. |
| Next-token prediction | «Тот самый лосс» | Cross-entropy между распределением модели и настоящим следующим токеном в каждой позиции. |
| Autoregressive | «Генерирует по одному» | Выход подаётся обратно на вход; параллельность есть только при обучении, но не при генерации. |
| Logits | «Скоры до softmax» | Сырой выход LM-головы перед softmax; сэмплирование происходит именно на них. |
| Temperature | «Ручка креативности» | Делим логиты на T; T→0 даёт greedy, T→∞ даёт равномерное распределение. |
| Top-p | «Nucleus sampling» | Обрезаем распределение до наименьшего множества с суммой ≥ p и сэмплируем из остатка. |
| Min-p | «Лучше, чем top-p» | Оставляем токены с `p ≥ min_p × max_p`; порог подстраивается под остроту распределения. |
| Speculative decoding | «Черновик плюс проверка» | Дешёвая модель предлагает N токенов; большая модель проверяет их параллельно. |
| Teacher forcing | «Трюк обучения» | На обучении подаём настоящий предыдущий токен, а не предсказание модели. Стандарт для любой seq2seq LM. |
