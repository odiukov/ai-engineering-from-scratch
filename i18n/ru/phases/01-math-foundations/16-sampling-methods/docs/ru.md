# Методы сэмплирования

> Сэмплирование — то, как AI исследует пространство возможностей.

**Type:** Build

**Time:** ~120 minutes

## Learning Objectives

- Реализовать с нуля метод обратной функции, отбраковку и importance sampling, имея только равномерные случайные числа
- Построить сэмплирование с температурой, top-k и top-p (nucleus) для генерации токенов языковой моделью
- Объяснить reparameterization trick и почему он позволяет пропускать градиенты через сэмплирование в VAE
- Запустить MCMC методом Метрополиса-Гастингса для сэмплирования из ненормированного целевого распределения

> 🎒 **На пальцах.** Модель никогда не «знает» следующее слово. Она получает список вероятностей и тянет жребий. Весь урок — про то, как правильно тянуть этот жребий: дописывая «я пошёл в...», всегда брать самое частое слово — получится робот, который повторяет одно и то же, а тянуть наугад из всего языка — получится «я пошёл в кастрюлю».

## The Problem

Языковая модель дочитала ваш запрос и выдала вектор из 50 000 логитов. По одному на каждый токен словаря. Теперь надо выбрать один. Как?

Если всегда брать токен с наибольшей вероятностью, каждый ответ будет одинаковым. Детерминированным. Скучным. Если брать равномерно случайно, на выходе получится бред. Ответ лежит где-то между этими крайностями, и этим «где-то» управляет сэмплирование.

Сэмплирование не ограничено генерацией текста. Обучение с подкреплением оценивает градиенты политики, сэмплируя траектории. VAE учат латентные представления, сэмплируя из выученных распределений и пропуская градиенты через случайность. Диффузионные модели порождают изображения, сэмплируя шум и итеративно его убирая. Методы Монте-Карло оценивают интегралы без замкнутой формы. Алгоритмы MCMC исследуют многомерные апостериорные распределения, которые невозможно перебрать.

Каждая генеративная AI-система — система сэмплирования. Стратегия сэмплирования определяет качество, разнообразие и управляемость выхода. Этот урок строит все основные методы с нуля, начиная с равномерных случайных чисел и заканчивая техниками, на которых работают современные LLM и генеративные модели.

## The Concept

### Why Sampling Matters

Сэмплирование выступает в AI и машинном обучении в четырёх фундаментальных ролях:

**Generation.** Языковые модели, диффузионные модели и GAN выдают результат через сэмплирование. Алгоритм сэмплирования прямо управляет креативностью, связностью и разнообразием. Температура, top-k и nucleus sampling — ручки, которые инженеры крутят ежедневно.

**Training.** Стохастический градиентный спуск сэмплирует mini-batch. Dropout сэмплирует нейроны для отключения. Аугментация данных сэмплирует случайные преобразования. Importance sampling перевзвешивает примеры, снижая дисперсию градиента в обучении с подкреплением (PPO, TRPO).

**Estimation.** У многих величин в ML нет замкнутой формы. Ожидаемые потери по распределению данных, статистическая сумма энергетической модели, свидетельство в байесовском выводе. Оценка Монте-Карло приближает всё это усреднением по выборкам.

**Exploration.** Алгоритмы MCMC исследуют апостериорные распределения в байесовском выводе. Эволюционные стратегии сэмплируют возмущения параметров. Thompson sampling балансирует исследование и эксплуатацию в задачах о многоруких бандитах.

Ключевая сложность: напрямую сэмплировать можно только из простых распределений (равномерного, нормального). Для всего остального нужен способ превратить простые выборки в выборки из вашего целевого распределения.

### Uniform Random Sampling

Любой метод сэмплирования начинается здесь. Генератор равномерных случайных чисел выдаёт значения в [0, 1), где любой подынтервал одинаковой длины равновероятен.

```
U ~ Uniform(0, 1)

P(a <= U <= b) = b - a    for 0 <= a <= b <= 1

Properties:
  E[U] = 0.5
  Var(U) = 1/12
```

Чтобы равномерно выбрать один из n элементов, сгенерируйте U и верните floor(n * U). Чтобы выбрать из непрерывного диапазона [a, b], вычислите a + (b - a) * U.

Ключевая мысль: одно равномерное случайное число содержит ровно столько случайности, сколько нужно для одной выборки из любого распределения. Вся хитрость — найти правильное преобразование.

> 🎒 **На пальцах.** Компьютер умеет одну-единственную случайную вещь: назвать число от 0 до 1. Всё остальное — броски кубика, шум для картинки, выбор следующего слова — сделано из этого одного числа математическими преобразованиями.

### Inverse CDF Method (Inverse Transform Sampling)

Функция распределения (CDF) переводит значения в вероятности:

```
F(x) = P(X <= x)

Properties:
  F is non-decreasing
  F(-inf) = 0
  F(+inf) = 1
  F maps the real line to [0, 1]
```

Обратная функция распределения переводит вероятности обратно в значения. Если U ~ Uniform(0, 1), то X = F_inverse(U) распределён по целевому закону.

```
Algorithm:
  1. Generate u ~ Uniform(0, 1)
  2. Return F_inverse(u)

Why it works:
  P(X <= x) = P(F_inverse(U) <= x) = P(U <= F(x)) = F(x)
```

**Exponential distribution example:**

```
PDF: f(x) = lambda * exp(-lambda * x),   x >= 0
CDF: F(x) = 1 - exp(-lambda * x)

Solve F(x) = u for x:
  u = 1 - exp(-lambda * x)
  exp(-lambda * x) = 1 - u
  x = -ln(1 - u) / lambda

Since (1 - U) and U have the same distribution:
  x = -ln(u) / lambda
```

Это работает идеально, когда F_inverse записывается в замкнутой форме. У нормального распределения обратной функции в замкнутой форме нет, поэтому используют другие методы (Бокс-Мюллер или численное приближение).

**Discrete version:** Для дискретных распределений постройте CDF как накопленную сумму, сгенерируйте U и найдите первый индекс, где накопленная сумма превышает U. Так работает `sample_categorical` из урока 06.

> 🎒 **На пальцах.** Это лотерейный барабан с секторами разной ширины. Вероятности превращаются в границы на отрезке от 0 до 1. Кинули случайное число — попали в чей-то сектор. Чем больше вероятность, тем шире сектор, тем чаще в него попадают.

### Rejection Sampling

Когда обратить CDF нельзя, но целевую плотность можно вычислять с точностью до константы, работает отбраковка.

```
Target distribution: p(x)  (can evaluate, possibly unnormalized)
Proposal distribution: q(x)  (can sample from)
Bound: M such that p(x) <= M * q(x) for all x

Algorithm:
  1. Sample x ~ q(x)
  2. Sample u ~ Uniform(0, 1)
  3. If u < p(x) / (M * q(x)), accept x
  4. Otherwise, reject and go to step 1

Acceptance rate = 1/M
```

Чем плотнее граница M, тем выше доля принятых. В малых размерностях (1-3) отбраковка работает хорошо. В высоких доля принятых падает экспоненциально, потому что почти весь объём предложения отбрасывается. Это проклятие размерности для отбраковки.

**Example: sampling from a truncated normal.** Используйте равномерное предложение на урезанном диапазоне. Огибающая M — максимум нормальной плотности на этом диапазоне.

**Example: sampling from a semicircle.** Предлагайте равномерно в описанном прямоугольнике. Принимайте, если точка попала внутрь полукруга. Так Монте-Карло вычисляет число пи: доля принятых равна отношению площадей пи/4.

> 🎒 **На пальцах.** Кидайте дротики в квадрат с нарисованным кругом. Попал в круг — засчитали, не попал — выкинули. Так вы «сэмплируете круг», умея кидать только в квадрат. И заодно можете посчитать пи: доля попаданий в круг × 4.

### Importance Sampling

Иногда выборки из целевого распределения p(x) не нужны. Нужно оценить математическое ожидание под p(x), а выборки у вас из другого распределения q(x).

```
Goal: estimate E_p[f(x)] = integral of f(x) * p(x) dx

Rewrite:
  E_p[f(x)] = integral of f(x) * (p(x)/q(x)) * q(x) dx
            = E_q[f(x) * w(x)]

where w(x) = p(x) / q(x)  are the importance weights.

Estimator:
  E_p[f(x)] ~ (1/N) * sum(f(x_i) * w(x_i))    where x_i ~ q(x)
```

Это критично в обучении с подкреплением. В PPO (Proximal Policy Optimization) вы собираете траектории по старой политике pi_old, но хотите оптимизировать новую pi_new. Вес важности равен pi_new(a|s) / pi_old(a|s). PPO обрезает эти веса, чтобы новая политика не уходила слишком далеко от старой.

Дисперсия оценки importance sampling зависит от того, насколько q похоже на p. Если q сильно отличается от p, несколько выборок получают огромные веса и захватывают всю оценку. Самонормированный вариант делит на сумму весов, смягчая проблему:

```
E_p[f(x)] ~ sum(w_i * f(x_i)) / sum(w_i)
```

> 🎒 **На пальцах.** Вы опросили посетителей спортзала о здоровье, а выводы хотите сделать про весь город. Ответы придётся перевзвесить: спортсменов в городе меньше, чем в вашей выборке. Вес важности и есть этот коэффициент пересчёта.

### Monte Carlo Estimation

Оценка Монте-Карло приближает интегралы усреднением случайных выборок. Закон больших чисел гарантирует сходимость.

```
Goal: estimate I = integral of g(x) dx over domain D

Method:
  1. Sample x_1, ..., x_N uniformly from D
  2. I ~ (Volume of D / N) * sum(g(x_i))

Error: O(1 / sqrt(N))   regardless of dimension
```

Скорость сходимости не зависит от размерности. Поэтому методы Монте-Карло царят в высоких размерностях, где сеточное интегрирование невозможно.

**Estimating pi:**

```
Sample (x, y) uniformly from [-1, 1] x [-1, 1]
Count how many fall inside the unit circle: x^2 + y^2 <= 1
pi ~ 4 * (count inside) / (total count)
```

**Estimating expectations:**

```
E[f(X)] ~ (1/N) * sum(f(x_i))    where x_i ~ p(x)

The sample mean converges to the true expectation.
Variance of the estimator = Var(f(X)) / N
```

> 🎒 **На пальцах.** Хотите узнать площадь пятна неправильной формы на асфальте? Обведите его квадратом, посыпьте квадрат горстью песчинок и посчитайте, какая доля упала на пятно. Умножьте на площадь квадрата. Ни формул, ни интегралов — только счёт песчинок.

### Markov Chain Monte Carlo (MCMC): Metropolis-Hastings

MCMC строит цепь Маркова, у которой стационарное распределение совпадает с целевым p(x). После достаточного числа шагов выборки из цепи (приближённо) становятся выборками из p(x).

```
Target: p(x)  (known up to a normalizing constant)
Proposal: q(x'|x)  (how to propose the next state given the current state)

Metropolis-Hastings algorithm:
  1. Start at some x_0
  2. For t = 1, 2, ..., T:
     a. Propose x' ~ q(x'|x_t)
     b. Compute acceptance ratio:
        alpha = [p(x') * q(x_t|x')] / [p(x_t) * q(x'|x_t)]
     c. Accept with probability min(1, alpha):
        - If u < alpha (u ~ Uniform(0,1)): x_{t+1} = x'
        - Otherwise: x_{t+1} = x_t
  3. Discard first B samples (burn-in)
  4. Return remaining samples
```

Для симметричных предложений (q(x'|x) = q(x|x')) отношение упрощается до p(x')/p(x). Это исходный алгоритм Метрополиса.

**Why it works.** Правило принятия обеспечивает детальный баланс: вероятность быть в x и перейти в x' равна вероятности быть в x' и перейти в x. Детальный баланс означает, что p(x) — стационарное распределение цепи.

**Practical considerations:**
- Burn-in: выбросить ранние выборки, пока цепь не дошла до равновесия
- Прореживание: оставлять каждую k-ю выборку, снижая автокорреляцию
- Масштаб предложения: слишком мал — цепь ползёт (высокая доля принятия, медленное исследование); слишком велик — почти все предложения отвергаются (цепь стоит на месте)
- Оптимальная доля принятия для гауссова предложения в высоких размерностях примерно 0.234

> 🎒 **На пальцах.** Слепой турист ищет самую высокую точку холмистой местности. Шаг в случайную сторону: стало выше — идём туда. Стало ниже — иногда всё равно идём, чтобы не застрять на маленьком холмике. Через тысячи шагов он проводит больше всего времени на вершинах — а это и значит «сэмплировать из распределения».

### Gibbs Sampling

Сэмплирование Гиббса — частный случай MCMC для многомерных распределений. Вместо предложения хода сразу по всем измерениям оно обновляет по одной переменной из её условного распределения.

```
Target: p(x_1, x_2, ..., x_d)

Algorithm:
  For each iteration t:
    Sample x_1^{t+1} ~ p(x_1 | x_2^t, x_3^t, ..., x_d^t)
    Sample x_2^{t+1} ~ p(x_2 | x_1^{t+1}, x_3^t, ..., x_d^t)
    ...
    Sample x_d^{t+1} ~ p(x_d | x_1^{t+1}, x_2^{t+1}, ..., x_{d-1}^{t+1})
```

Сэмплирование Гиббса требует, чтобы вы умели сэмплировать из каждого условного распределения p(x_i | x_{-i}). Для многих моделей это просто:
- Байесовские сети: условные следуют из структуры графа
- Смеси гауссиан: условные гауссовы
- Модели Изинга: условное для каждого спина зависит только от соседей

Доля принятия всегда равна 1 (каждое предложение принимается), потому что сэмплирование из точного условного автоматически удовлетворяет детальному балансу.

**Limitation.** Когда переменные сильно скоррелированы, Гиббс перемешивается медленно: обновляя по одной переменной, нельзя делать большие диагональные ходы по распределению.

> 🎒 **На пальцах.** Кубик Рубика крутят по одной грани за раз, а не пытаются повернуть всё сразу. Гиббс так же: зафиксировал все переменные кроме одной, обновил её, перешёл к следующей. Каждый ход простой, но вместе они обходят всё пространство.

### Temperature Sampling (Used in LLMs)

Языковые модели выдают логиты z_1, ..., z_V для каждого токена словаря. Softmax превращает их в вероятности. Температура перемасштабирует логиты перед softmax:

```
p_i = exp(z_i / T) / sum(exp(z_j / T))

T = 1.0: standard softmax (original distribution)
T -> 0:  argmax (deterministic, always picks highest logit)
T -> inf: uniform (all tokens equally likely)
T < 1.0: sharpens the distribution (more confident, less diverse)
T > 1.0: flattens the distribution (less confident, more diverse)
```

**Why it works.** Деление логитов на T < 1 усиливает различия между ними. Если z_1 = 2 и z_2 = 1, деление на T = 0.5 даёт z_1/T = 4 и z_2/T = 2, разрыв вырос. После softmax токен с наибольшим логитом получает намного большую долю.

**In practice:**
- T = 0.0: жадное декодирование, лучше всего для фактических вопросов
- T = 0.3-0.7: слегка креативно, хорошо для генерации кода
- T = 0.7-1.0: сбалансированно, хорошо для обычного диалога
- T = 1.0-1.5: творческое письмо, брейнсторм
- T > 1.5: всё случайнее, полезно редко

Температура не меняет, какие токены возможны. Она меняет распределение вероятностной массы между ними.

> 🎒 **На пальцах.** Температура — ручка «насколько модель осмеливается». Ноль — отличник, который всегда отвечает самое безопасное. Единица — обычный человек. Полтора — фантазёр, который может ляпнуть что угодно. Это буквально тот же ползунок «креативности» в интерфейсах чат-ботов.

### Top-k Sampling

Top-k ограничивает набор кандидатов k токенами с наибольшими вероятностями, затем перенормирует и сэмплирует из этого ограниченного набора.

```
Algorithm:
  1. Compute softmax probabilities for all V tokens
  2. Sort tokens by probability (descending)
  3. Keep only the top k tokens
  4. Renormalize: p_i' = p_i / sum(p_j for j in top-k)
  5. Sample from the renormalized distribution

k = 1:  greedy decoding
k = V:  no filtering (standard sampling)
k = 40: typical setting, removes long tail of unlikely tokens
```

Top-k не даёт модели выбрать крайне маловероятные токены (опечатки, бессмыслицу), живущие в длинном хвосте распределения. Проблема: k фиксировано независимо от контекста. Когда модель уверена (у одного токена 95% вероятности), k = 40 всё равно оставляет 39 альтернатив. Когда модель не уверена (вероятность размазана по 1000 токенов), k = 40 отрезает правдоподобные варианты.

### Top-p (Nucleus) Sampling

Top-p динамически подстраивает размер набора кандидатов. Вместо фиксированного числа токенов он оставляет наименьший набор, чья суммарная вероятность превышает p.

```
Algorithm:
  1. Compute softmax probabilities for all V tokens
  2. Sort tokens by probability (descending)
  3. Find smallest k such that sum of top-k probabilities >= p
  4. Keep only those k tokens
  5. Renormalize and sample

p = 0.9:  keeps tokens covering 90% of probability mass
p = 1.0:  no filtering
p = 0.1:  very restrictive, nearly greedy
```

Когда модель уверена, nucleus sampling оставляет мало токенов (может, 2-3). Когда не уверена — много (может, 200). Именно эта адаптивность обычно даёт текст лучше, чем top-k.

**Common combinations:**
- Температура 0.7 + top-p 0.9: хорошая универсальная настройка
- Температура 0.0 (жадно): лучше всего для детерминированных задач
- Температура 1.0 + top-k 50: настройка из оригинальной статьи Fan et al. (2018)

Top-k и top-p можно комбинировать. Сначала применяют top-k, затем top-p на оставшемся наборе.

> 🎒 **На пальцах.** Разница на примере. Вопрос «столица Франции — ...»: модель уверена, правильный ответ занимает 99% вероятности. Top-k = 40 всё равно оставит 39 городов-конкурентов, среди которых может выпасть чушь. Top-p = 0.9 оставит один Париж. А на вопросе «мне нравится...» top-p сам расширится до сотен вариантов. Одна ручка, поведение подстраивается.

### Reparameterization Trick (Used in VAEs)

Вариационные автокодировщики (VAE) учатся, кодируя вход в распределение в латентном пространстве, сэмплируя из этого распределения и декодируя выборку обратно. Проблема: через операцию сэмплирования нельзя пропустить градиенты.

```
Standard sampling (not differentiable):
  z ~ N(mu, sigma^2)

  The randomness blocks gradient flow.
  d/d_mu [sample from N(mu, sigma^2)] = ???
```

Reparameterization trick отделяет случайность от параметров:

```
Reparameterized sampling:
  epsilon ~ N(0, 1)          (fixed random noise, no parameters)
  z = mu + sigma * epsilon   (deterministic function of parameters)

  Now z is a deterministic, differentiable function of mu and sigma.
  d(z)/d(mu) = 1
  d(z)/d(sigma) = epsilon

  Gradients flow through mu and sigma.
```

Это работает, потому что N(mu, sigma^2) имеет то же распределение, что и mu + sigma * N(0, 1). Ключевая идея: перенести случайность в источник без параметров (epsilon), а затем выразить выборку как дифференцируемое преобразование параметров.

**In the VAE training loop:**
1. Кодировщик выдаёт mu и log(sigma^2) для каждого входа
2. Сэмплируем epsilon ~ N(0, 1)
3. Вычисляем z = mu + sigma * epsilon
4. Декодируем z, восстанавливая вход
5. Пропускаем градиенты через шаги 4, 3, 2, 1 (возможно, потому что шаг 3 дифференцируем)

Без reparameterization trick VAE нельзя обучать обычным обратным распространением. Одна эта идея сделала VAE практичными.

> 🎒 **На пальцах.** Хитрость такая же, как «вытянуть жребий заранее». Нельзя посчитать, как изменится результат лотереи от ваших действий, пока лотерея внутри процесса. Но если сначала вытянуть бумажку, а потом применить к ней вашу формулу — всё становится обычной арифметикой, которую можно дифференцировать. Случайность вынесли наружу.

### Gumbel-Softmax (Differentiable Categorical Sampling)

Reparameterization trick работает для непрерывных распределений (гауссова). Для дискретных категориальных нужен другой подход. Gumbel-Softmax даёт дифференцируемое приближение категориального сэмплирования.

**The Gumbel-Max trick (non-differentiable):**

```
To sample from a categorical distribution with log-probabilities log(p_1), ..., log(p_k):
  1. Sample g_i ~ Gumbel(0, 1) for each category
     (g = -log(-log(u)), where u ~ Uniform(0, 1))
  2. Return argmax(log(p_i) + g_i)

This produces exact categorical samples.
```

**Gumbel-Softmax (differentiable approximation):**

```
Replace the hard argmax with a soft softmax:
  y_i = exp((log(p_i) + g_i) / tau) / sum(exp((log(p_j) + g_j) / tau))

tau (temperature) controls the approximation:
  tau -> 0:  approaches a one-hot vector (hard categorical)
  tau -> inf: approaches uniform (1/k, 1/k, ..., 1/k)
  tau = 1.0: soft approximation
```

Gumbel-Softmax даёт непрерывное послабление дискретной выборки. Выход — вектор вероятностей (мягкий one-hot) вместо жёсткого one-hot. Градиенты текут через softmax. При обучении на прямом проходе можно использовать straight-through оценку: жёсткий argmax вперёд, мягкие градиенты Gumbel-Softmax назад.

**Applications:**
- Дискретные латентные переменные в VAE
- Поиск архитектуры нейросети (выбор дискретных операций)
- Механизмы жёсткого внимания
- Обучение с подкреплением с дискретными действиями

### Stratified Sampling

Обычное сэмплирование Монте-Карло может случайно оставить дыры в пространстве. Стратифицированное сэмплирование заставляет покрытие быть равномерным: пространство делят на слои и сэмплируют из каждого.

```
Standard Monte Carlo:
  Sample N points uniformly from [0, 1]
  Some regions may have clusters, others gaps

Stratified sampling:
  Divide [0, 1] into N equal strata: [0, 1/N), [1/N, 2/N), ..., [(N-1)/N, 1)
  Sample one point uniformly within each stratum
  x_i = (i + u_i) / N   where u_i ~ Uniform(0, 1),  i = 0, ..., N-1
```

У стратифицированного сэмплирования дисперсия всегда не выше, чем у обычного Монте-Карло:

```
Var(stratified) <= Var(standard Monte Carlo)

The improvement is largest when f(x) varies smoothly.
For piecewise-constant functions, stratified sampling is exact.
```

**Applications:**
- Численное интегрирование (квази-Монте-Карло)
- Разбиение обучающих данных (сохранение баланса классов в каждом фолде)
- Importance sampling со стратификацией (комбинация обеих техник)
- NeRF (Neural Radiance Fields) использует стратификацию вдоль лучей камеры

> 🎒 **На пальцах.** Опрос по школе. Можно выбрать 30 учеников наугад — и случайно попасть почти во всех одиннадцатиклассников. А можно взять по 3 человека из каждого класса — покрытие честное, разброс меньше. Это и есть стратификация.

### Connection to Diffusion Models

Диффузионные модели порождают изображения процессом сэмплирования. Прямой процесс добавляет к картинке гауссов шум за T шагов, пока она не станет чистым шумом. Обратный процесс учится убирать шум, восстанавливая исходное изображение шаг за шагом.

```
Forward process (known):
  x_t = sqrt(alpha_t) * x_{t-1} + sqrt(1 - alpha_t) * epsilon
  where epsilon ~ N(0, I)

  After T steps: x_T ~ N(0, I)  (pure noise)

Reverse process (learned):
  x_{t-1} = (1/sqrt(alpha_t)) * (x_t - (1 - alpha_t)/sqrt(1 - alpha_bar_t) * epsilon_theta(x_t, t)) + sigma_t * z
  where z ~ N(0, I)

  Each denoising step is a sampling step.
```

Связь с методами этого урока:
- Каждый шаг очистки использует reparameterization trick (сэмплируем шум, применяем детерминированное преобразование)
- Расписание шума {alpha_t} задаёт форму отжига температуры
- Обучение использует оценку Монте-Карло для приближения ELBO (нижней границы свидетельства)
- Предковое сэмплирование в диффузионных моделях — цепь Маркова (каждый шаг зависит только от текущего состояния)

Весь процесс генерации изображения — итеративное сэмплирование: начать с шума и на каждом шаге сэмплировать чуть менее зашумлённую версию, опираясь на выученную модель очистки.

> 🎒 **На пальцах.** Представьте, что вы смотрите на телевизионный «снег» и постепенно, шаг за шагом, различаете в нём кота. Именно это делают Midjourney и Stable Diffusion: начинают с чистого шума и за 20-50 шагов вытаскивают из него картинку. Каждый шаг — одна операция сэмплирования из этого урока.

```python
def rejection_sample(target_pdf, proposal_sample, proposal_pdf, M):
    while True:
        x = proposal_sample()
        u = random.random()
        if u < target_pdf(x) / (M * proposal_pdf(x)):
            return x
```

### Step 3: Importance sampling

```python
def importance_sampling_estimate(f, target_pdf, proposal_pdf, proposal_sample, n):
    total = 0
    for _ in range(n):
        x = proposal_sample()
        w = target_pdf(x) / proposal_pdf(x)
        total += f(x) * w
    return total / n
```

### Step 4: Monte Carlo estimation of pi

```python
def monte_carlo_pi(n):
    inside = 0
    for _ in range(n):
        x = random.uniform(-1, 1)
        y = random.uniform(-1, 1)
        if x*x + y*y <= 1:
            inside += 1
    return 4 * inside / n
```

> 🎒 **На пальцах.** Откуда четвёрка в формуле: круг радиуса 1 имеет площадь пи, квадрат вокруг него — 2×2 = 4. Значит доля попаданий равна пи/4, и чтобы получить пи, умножаем на 4. Запустите с n = 1000 — получите примерно 3.1. С n = 1 000 000 — примерно 3.1416.

### Step 5: Metropolis-Hastings MCMC

```python
def metropolis_hastings(target_log_pdf, proposal_sample, proposal_log_pdf, x0, n_samples, burn_in):
    samples = []
    x = x0
    for i in range(n_samples + burn_in):
        x_new = proposal_sample(x)
        log_alpha = (target_log_pdf(x_new) + proposal_log_pdf(x, x_new)
                     - target_log_pdf(x) - proposal_log_pdf(x_new, x))
        if math.log(random.random()) < log_alpha:
            x = x_new
        if i >= burn_in:
            samples.append(x)
    return samples
```

Сэмплируйте из двумодального распределения (смеси двух гауссиан). Визуализируйте траекторию цепи.

### Step 6: Gibbs sampling

```python
def gibbs_sampling_2d(conditional_x_given_y, conditional_y_given_x, x0, y0, n_samples, burn_in):
    x, y = x0, y0
    samples = []
    for i in range(n_samples + burn_in):
        x = conditional_x_given_y(y)
        y = conditional_y_given_x(x)
        if i >= burn_in:
            samples.append((x, y))
    return samples
```

### Step 7: Temperature sampling

```python
def softmax(logits):
    max_l = max(logits)
    exps = [math.exp(z - max_l) for z in logits]
    total = sum(exps)
    return [e / total for e in exps]

def temperature_sample(logits, temperature):
    scaled = [z / temperature for z in logits]
    probs = softmax(scaled)
```

### Step 8: Top-k and top-p sampling

```python
def top_k_sample(logits, k):
    indexed = sorted(enumerate(logits), key=lambda x: -x[1])
    top = indexed[:k]
    top_logits = [l for _, l in top]
    probs = softmax(top_logits)
    idx = sample_from_probs(probs)
    return top[idx][0]

def top_p_sample(logits, p):
    probs = softmax(logits)
    indexed = sorted(enumerate(probs), key=lambda x: -x[1])
    cumsum = 0
    selected = []
    for token_idx, prob in indexed:
        cumsum += prob
        selected.append((token_idx, prob))
        if cumsum >= p:
            break
    sel_probs = [pr for _, pr in selected]
    total = sum(sel_probs)
    sel_probs = [pr / total for pr in sel_probs]
    idx = sample_from_probs(sel_probs)
    return selected[idx][0]
```

> 🎒 **На пальцах.** Обратите внимание: обе функции — это тридцать строк обычного кода без единой сложной формулы. Отсортировали, отрезали хвост, перенормировали, кинули жребий. Всё «поведение характера» чат-бота, за которое хвалят и ругают модели, живёт вот в этих тридцати строках.

### Step 9: Reparameterization trick

```python
def reparam_sample(mu, sigma):
    epsilon = random.gauss(0, 1)
    return mu + sigma * epsilon

def reparam_gradient(mu, sigma, epsilon):
    dz_dmu = 1.0
    dz_dsigma = epsilon
    return dz_dmu, dz_dsigma
```

Продемонстрируйте, что градиенты проходят через репараметризованную выборку, но не через прямое сэмплирование.

### Step 10: Gumbel-Softmax

```python
def gumbel_sample():
    u = random.random()
    return -math.log(-math.log(u))

def gumbel_softmax(logits, temperature):
    gumbels = [math.log(p) + gumbel_sample() for p in logits]
    return softmax([g / temperature for g in gumbels])
```

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|----------------------|
| Sampling | «Вытягивание случайных значений» | Порождение значений согласно распределению вероятностей. Механизм, стоящий за всей генеративной AI |
| Uniform distribution | «Всё равновероятно» | Каждое значение в [a, b] имеет одинаковую плотность 1/(b-a). Отправная точка всех методов сэмплирования |
| Inverse CDF | «Преобразование вероятности» | F_inverse(U) превращает равномерную выборку в выборку из любого распределения с известной функцией распределения. Точно и эффективно |
| Rejection sampling | «Предложить и принять/отбросить» | Генерировать из простого предложения, принимать с вероятностью, пропорциональной отношению цель/предложение. Точно, но расходует выборки |
| Importance sampling | «Перевзвесить выборки» | Оценивать ожидания под p(x) по выборкам из q(x), взвешивая каждую на p(x)/q(x). Основа PPO в обучении с подкреплением |
| Monte Carlo | «Усреднить случайные выборки» | Приближать интегралы средним по выборке. Ошибка O(1/sqrt(N)) независимо от размерности |
| MCMC | «Случайное блуждание, которое сходится» | Построить цепь Маркова, чьё стационарное распределение — целевое. Метрополис-Гастингс — базовый алгоритм |
| Metropolis-Hastings | «Вверх всегда, вниз иногда» | Предлагать ходы, принимать по отношению плотностей. Детальный баланс обеспечивает сходимость к цели |
| Gibbs sampling | «По одной переменной за раз» | Обновлять каждую переменную из её условного распределения при фиксированных остальных. Доля принятия 100% |
| Temperature | «Ручка уверенности» | Делит логиты на T перед softmax. T<1 обостряет (увереннее), T>1 сглаживает (разнообразнее) |
| Top-k sampling | «Оставить k лучших» | Обнулить всё, кроме k самых вероятных токенов, перенормировать, сэмплировать. Фиксированный размер набора кандидатов |
| Nucleus sampling (top-p) | «Оставить вероятные» | Оставить наименьший набор токенов, чья суммарная вероятность превышает p. Адаптивный размер набора |
| Reparameterization trick | «Вынести случайность наружу» | Записать z = mu + sigma * epsilon, где epsilon ~ N(0,1). Делает сэмплирование дифференцируемым. Необходимо для обучения VAE |
| Gumbel-Softmax | «Мягкое категориальное сэмплирование» | Дифференцируемое приближение категориального сэмплирования через шум Гумбеля + softmax с температурой |
| Stratified sampling | «Принудительное покрытие» | Разделить пространство на слои и сэмплировать из каждого. Всегда меньшая дисперсия, чем у наивного Монте-Карло |
| Burn-in | «Период разогрева» | Начальные выборки MCMC, отбрасываемые до выхода цепи на стационарное распределение |
| Detailed balance | «Условие обратимости» | p(x) * T(x->y) = p(y) * T(y->x). Достаточное условие того, что p — стационарное распределение цепи Маркова |
| Diffusion sampling | «Итеративная очистка от шума» | Порождать данные, начиная с шума и применяя выученные шаги очистки. Каждый шаг — операция условного сэмплирования |
