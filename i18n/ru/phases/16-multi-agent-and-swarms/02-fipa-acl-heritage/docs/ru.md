# Наследие FIPA-ACL и речевых актов

> До MCP, до A2A был FIPA-ACL. В 2000 году организация IEEE Foundation for Intelligent Physical Agents ратифицировала язык общения агентов с двадцатью перформативами, двумя языками содержимого и набором протоколов взаимодействия: contract net, subscribe/notify, request-when. Из индустрии он ушёл, потому что накладные расходы на онтологии оказались для веба слишком тяжёлыми, — но LLM-возрождение мультиагентных систем тихо переизобретает те же идеи без формальной семантики: вместо перформативов JSON-контракты, вместо онтологий естественный язык. В этом уроке мы читаем FIPA-ACL всерьёз, чтобы увидеть, какие решения протоколов 2026 года — переизобретение, какие — настоящая новизна, и где текущая волна заново наступит на грабли, уже пройденные в двухтысячных.

**Type:** Learn
**Languages:** Python (stdlib)
**Prerequisites:** Phase 16 · 01 (Why Multi-Agent)
**Time:** ~60 minutes

## Problem

Ландшафт агентных протоколов 2026 года плотно населён: MCP для инструментов, A2A для агентов, ACP для корпоративного аудита, ANP для децентрализованного доверия, NLIP для содержимого на естественном языке, плюс CA-MCP и десятки исследовательских предложений. Каждая спецификация объявляет себя фундаментальной.

Честное чтение такое: большинство из них заново открывают одно очень конкретное дерево решений двадцатилетней давности. Теория речевых актов Остина (1962) и Сёрла (1969) дала нам мысль «высказывания — это действия». KQML (1993) превратил её в проводной протокол. FIPA-ACL (ратифицирован в 2000-м) дал эталонную стандартизацию: двадцать перформативов, языки содержимого SL0/SL1, протоколы взаимодействия для contract-net и subscribe-notify. JADE и JACK были референсными платформами на Java. Всё это заглохло около 2010-го, потому что накладные расходы на онтологии оказались слишком тяжёлыми, а веб побеждал.

Когда вы смотрите на `tools/call` из MCP, на жизненный цикл задачи в A2A или на общее хранилище контекста в CA-MCP, вы смотрите на более мягкую, JSON-родную переделку решений FIPA. Знание этого наследия даёт две вещи: понимание, какие новые «инновации» на самом деле переизобретения, и какие старые режимы отказа новые спецификации откроют для себя заново.

> 🎒 **На пальцах.** Это как обнаружить, что модный «шеринг самокатов» — это прокат велосипедов, который был всегда. Посчитайте по абзацу: 1962 (Остин) → 1993 (KQML) → 2000 (FIPA-ACL) → 2010 (закат) → 2024-2026 (MCP, A2A). Между ратификацией FIPA и появлением MCP прошло около четверти века, а поля в сообщении почти те же: кто, кому, зачем, что.

## Concept

### Speech acts, in one paragraph

Остин заметил, что некоторые предложения не описывают мир, а меняют его. «Обещаю». «Прошу». «Объявляю». Он назвал их перформативными высказываниями. Сёрл формализовал пять категорий: assertive, directive, commissive, expressive, declarative. KQML (Finin et al., 1993) сделал это рабочим для программных агентов: сообщение — это перформатив (действие) плюс содержимое (о чём это действие). FIPA-ACL закрыл пробелы KQML и стандартизировал около двадцати перформативов.

> 🎒 **На пальцах.** Разница как между «на улице дождь» и «объявляю вас мужем и женой»: первое сообщает, второе меняет реальность. Для агентов это ровно то же деление: `inform` только рассказывает, а `request` создаёт обязательство что-то сделать. Именно поэтому перформатив выносят в отдельное поле, а не прячут внутри текста.

### The twenty FIPA performatives (partial list)

| Performative | Intent |
|---|---|
| `inform` | «Сообщаю тебе, что P истинно» |
| `request` | «Прошу тебя сделать X» |
| `query-if` | «Истинно ли P?» |
| `query-ref` | «Каково значение X?» |
| `propose` | «Предлагаю сделать X» |
| `accept-proposal` | «Принимаю предложение» |
| `reject-proposal` | «Отклоняю предложение» |
| `agree` | «Согласен сделать X» |
| `refuse` | «Отказываюсь делать X» |
| `confirm` | «Подтверждаю, что P истинно» |
| `disconfirm` | «Отрицаю P» |
| `not-understood` | «Твоё сообщение не распарсилось» |
| `cfp` | «Объявляю сбор предложений по X» |
| `subscribe` | «Уведомляй меня, когда X меняется» |
| `cancel` | «Отмени текущий X» |
| `failure` | «Я пытался сделать X и не смог» |

Полный список лежит в `fipa00037.pdf` (FIPA ACL Message Structure). Смысл не в том, чтобы его выучить, — смысл в том, что каждому пункту соответствует примитив, который любой LLM-протокол в итоге добавляет обратно.

> 🎒 **На пальцах.** Прочитайте таблицу как список кнопок в мессенджере для агентов: «сообщить», «попросить», «спросить», «предложить», «согласиться», «отказаться», «отменить». В таблице 16 строк из двадцати, и почти каждая уже есть в современных стеках под другим именем: `request` — это `tools/call`, `subscribe` — это подписка на SSE, `failure` — это поле `error`. Заметьте пару `agree` и `refuse`: у MCP отдельного «согласен, начинаю» нет, и его каждый раз изобретают руками.

### Canonical FIPA-ACL message

```
(inform
  :sender       agent1@platform
  :receiver     agent2@platform
  :content      "((price IBM 83))"
  :language     SL0
  :ontology     finance
  :protocol     fipa-request
  :conversation-id   conv-42
  :reply-with   msg-17
)
```

Семь полей несут конверт протокола; одно поле (`content`) несёт полезную нагрузку. Остальные поля — ровно то, что вы переизобретаете каждый раз, когда прикручиваете к JSON-протоколу повторы, ветки диалога и онтологию.

> 🎒 **На пальцах.** Посчитайте по примеру: девять строк, из них полезных данных ровно одна — `:content "((price IBM 83))"`. Всё остальное — адреса, язык, онтология, идентификатор разговора. Это как конверт письма: марка, адрес и индекс занимают больше места, чем «привет», но без них письмо не дойдёт и не найдётся в переписке.

### The two legacy platforms

**JADE** (Java Agent DEvelopment framework, 1999–2020-е) был самым используемым FIPA-совместимым рантаймом. Агенты наследовались от базового класса, обменивались ACL-сообщениями, жили внутри контейнеров и координировались через «поведения». В комплекте шла библиотека протоколов взаимодействия: contract-net, subscribe-notify, request-when, propose-accept.

**JACK** (Agent Oriented Software, коммерческий) делал упор на BDI-рассуждения (Belief-Desire-Intention) поверх FIPA-сообщений. Более формальный, менее принятый.

Оба сошли со сцены, как только веб-стек съел мультиагентные сценарии. MCP и A2A — это «контейнеры» рантайма 2026 года.

> 🎒 **На пальцах.** JADE и JACK — как две операционные системы для агентов: одна открытая на Java, другая коммерческая и строгая. Обратите внимание на даты JADE: 1999–2020-е, то есть больше двадцати лет жизни, а сегодня его почти никто не вспоминает. Причина не в качестве протокола, а в том, что вся индустрия ушла в HTTP и JSON.

### Why FIPA faded

- **Ontology overhead.** FIPA требовал общей онтологии, чтобы распарсить `content`. Договориться об онтологиях — это многолетний процесс стандартизации. Веб просто взял HTTP + JSON.
- **Formal semantics nobody used.** SL (Semantic Language) давал строгие условия истинности, но большинство продакшен-систем использовали свободное содержимое и игнорировали формализм.
- **Tooling lock-in.** JADE был только под Java; JACK был коммерческим. Полиглотные команды обходили оба.
- **The internet won the stack.** REST, потом JSON-RPC, потом gRPC заменили транспорт ACL.

> 🎒 **На пальцах.** Все четыре причины сводятся к цене входа. Онтология — это как требование, чтобы обе команды сначала подписали общий словарь терминов: пока согласовывают, соседи уже выкатили REST-эндпоинт и работают. Заметьте иронию второго пункта: самая ценная часть FIPA — формальная семантика — оказалась той, которой почти никто не пользовался.

### The LLM revival is FIPA-lite

Сравните FIPA `request` с MCP `tools/call`:

```
(request                                {
  :sender  agent1                         "jsonrpc": "2.0",
  :receiver tool-server                   "method":  "tools/call",
  :content "(lookup stock IBM)"           "params":  {"name":"lookup_stock",
  :ontology finance                                   "arguments":{"symbol":"IBM"}},
  :conversation-id c42                    "id": 42
)                                        }
```

Один и тот же конверт, разный синтаксис. Оба несут: кто, кому, интент, полезную нагрузку, идентификатор для сопоставления. Ни один не является революцией относительно другого — это разные компромиссы в одном и том же дизайне.

Обзор 2025 года от Liu et al. («A Survey of Agent Interoperability Protocols: MCP, ACP, A2A, ANP», arXiv:2505.02279) делает эту родословную явной: MCP соответствует речевым актам использования инструментов, A2A — речевым актам между равноправными агентами, ACP — речевым актам аудиторского следа, ANP — расширениям про децентрализованную идентичность. Новые спецификации — потомки ACL с JSON-синтаксисом и более расслабленной семантикой.

> 🎒 **На пальцах.** Сопоставьте поля построчно: `:sender` — это отправитель, `:receiver` — `"method": "tools/call"` вместе с адресом сервера, `:content` — `"arguments"`, `:conversation-id c42` — `"id": 42`. Совпадений четыре из пяти, и главное расхождение — `:ontology finance`, которому в JSON-RPC соответствует ничто. Как перевод одного и того же письма с русского на английский: слова другие, конверт тот же.

### The trade-off, stated plainly

**What FIPA gave you and modern specs drop:**

- Формальную семантику — можно доказать, что `inform` подразумевает: отправитель верит в содержимое.
- Канонический каталог перформативов — не нужно каждый раз заново спорить, «а нужен ли нам `cancel`?».
- Десятилетия паттернов протоколов взаимодействия — contract-net, subscribe-notify, propose-accept — с известными свойствами корректности.

**What modern specs give you and FIPA did not:**

- JSON-родные полезные нагрузки, совместимые с любым современным инструментом.
- Содержимое на естественном языке, которое LLM понимают без написанной руками онтологии.
- Транспорт веб-стека (HTTP, SSE, WebSocket).
- Обнаружение возможностей через самоописывающиеся документы (`listTools` в MCP, Agent Card в A2A).

Более расслабленная семантика интента взамен на простоту реализации. Это ровно та сделка, которая происходит.

> 🎒 **На пальцах.** Сделка выглядит так: три пункта строгости обменяли на четыре пункта удобства. Пример потери из первого списка — спор про `cancel`: у FIPA он был в каталоге, а в новых протоколах отмену задачи каждая команда добавляет заново и по-своему. Пример выигрыша из второго списка — Agent Card: чтобы узнать возможности агента, достаточно скачать один JSON, а не согласовывать онтологию месяцами.

### Interaction protocols worth porting

FIPA поставлял примерно 15 протоколов взаимодействия. Три стоит перенести в LLM-мультиагентные системы:

1. **Contract Net Protocol (CNP).** Менеджер выпускает `cfp` (сбор предложений); участники отвечают `propose`; менеджер принимает или отклоняет. Это канонический паттерн рынка задач (Phase 16 · 16 Negotiation).
2. **Subscribe/Notify.** Подписчик отправляет `subscribe`; издатель отправляет `inform` каждый раз, когда тема меняется. Это любая шина событий в 2026-м.
3. **Request-When.** «Сделай X, когда выполнится условие Y». Отложенное действие с предусловиями. Аналог 2026 года — отложенные задачи в надёжных workflow-движках (Phase 16 · 22 Production Scaling).

Каждый чисто ложится на современные очереди сообщений, HTTP + опрос или стриминг через SSE.

> 🎒 **На пальцах.** Contract Net — это тендер: заказчик объявляет работу, трое присылают цены, он выбирает одного. Обратите внимание на счёт сообщений: один `cfp`, три `propose`, один `accept-proposal` и два `reject-proposal` — семь сообщений на одну задачу, зато исполнителя выбирает рынок, а не жёсткое правило в коде. Subscribe/Notify вы уже знаете под именем «подписка на обновления».

### What breaks when you drop the ontology

Без общей онтологии агенты выводят смысл из содержимого на естественном языке. Задокументированный режим отказа 2026 года — **semantic drift**: два агента используют одно и то же слово (`"customer"`) для тонко различающихся понятий, агент-получатель действует по неверной интерпретации, и ни один валидатор схемы этого не ловит. Требование онтологии в FIPA отклонило бы такое сообщение ещё при разборе.

Меры смягчения без полноценной онтологии:

- JSON Schema на `content` — отклоняет структурные ошибки на проводе.
- Типизированные артефакты (A2A) — отклоняют неверную модальность.
- Явный перформатив в конверте — делает интент однозначным даже там, где содержимое на естественном языке.

> 🎒 **На пальцах.** Semantic drift — это когда один отдел считает «клиентом» плательщика, а другой — пользователя аккаунта: слово одно, отчёты разные. Обратите внимание, почему JSON Schema тут помогает только частично: она проверит, что поле `customer` — строка, но не что вы оба имели в виду одно и то же. Из трёх мер по-настоящему дёшев третий пункт: явный перформатив в конверте стоит одно поле, а снимает половину догадок.

### The 2026 specs, mapped to speech-act heritage

| Modern spec | FIPA analog | What it keeps | What it drops |
|---|---|---|---|
| MCP `tools/call` | `request` | явный интент, id для сопоставления | формальную семантику, онтологию |
| MCP `resources/read` | `query-ref` | явный интент, id для сопоставления | формальную семантику |
| A2A Task lifecycle | contract-net + request-when | асинхронный жизненный цикл, переходы состояний | гарантии формальной полноты |
| A2A streaming events | subscribe/notify | асинхронный push | подписку по типизированному предикату |
| CA-MCP shared context | blackboard (Hayes-Roth 1985) | общую память с несколькими писателями | модель логической согласованности |
| NLIP | natural-language content | LLM-родной формат | схему |

Если читать таблицу сверху вниз, виден паттерн: структурный примитив сохраняют, формализм выбрасывают, а неоднозначность оставляют замазывать LLM.

```figure
sw-contract-net
```

> 🎒 **На пальцах.** В таблице шесть строк, и в колонке «что выбрасывают» пять раз из шести стоит формальная строгость: семантика, онтология, гарантии полноты, модель согласованности, схема. То есть закономерность не случайная, а системная. Как переход от чертежей с допусками к фотографии готовой детали: собрать по ней быстрее, а проверить точность нечем.

## Build It

`code/main.py` реализует транслятор FIPA-ACL на чистой стандартной библиотеке. Он кодирует и декодирует канонический ACL-конверт и показывает, как любая форма сообщения MCP / A2A сводится к тем же семи полям. Демо:

- Кодирует пять сообщений в стиле MCP и A2A как FIPA-ACL.
- Декодирует FIPA-ACL обратно в современный эквивалент.
- Прогоняет игрушечную переговорную схему Contract Net между одним менеджером и тремя участниками через `cfp`, `propose`, `accept-proposal`, `reject-proposal`.

Запустите:

```
python3 code/main.py
```

Вывод — это параллельный трейс, где каждое современное сообщение показано и в JSON-форме 2026 года, и в форме FIPA-ACL, а затем полный оборот заявки в contract-net. Те же примитивы протокола выживают в обе стороны; различается только синтаксис.

> 🎒 **На пальцах.** Смысл круговой конвертации в том, что она либо получается, либо нет: если MCP-сообщение переводится в ACL и обратно без потерь, значит нового в нём ничего нет. Проверьте на числах: пять сообщений заходят, пять выходят, и во всех пяти те же семь полей конверта. А тендер с тремя участниками покажет, что рынок задач умещается в четыре перформатива.

## Use It

`outputs/skill-fipa-mapper.md` — это навык, который читает любую спецификацию агентного протокола и выдаёт её отображение на FIPA-ACL. Применяйте его перед принятием нового протокола, чтобы ответить на вопрос: «Это правда новое или это `inform` с JSON-синтаксисом?»

> 🎒 **На пальцах.** Навык работает как детектор пустой новизны: скармливаете спецификацию, получаете таблицу «этот метод = вот такой перформатив». Тот самый вопрос про «`inform` с JSON-синтаксисом» экономит недели: если все методы нового протокола отображаются один в один, переходить на него незачем.

## Ship It

Не возвращайте FIPA-ACL обратно. Верните его чек-лист:

- Какой примитив интента (перформатив) несёт каждое сообщение?
- Есть ли id для сопоставления запроса с ответом и для отмены?
- Есть ли явный язык содержимого (JSON-RPC, обычный текст, структурированный типизированный артефакт)?
- Протоколы взаимодействия — первоклассные сущности, или вы заново реализуете contract-net с нуля?
- Что происходит, когда два агента расходятся в понимании смысла содержимого (semantic drift)?

Задокументируйте эти пять вопросов для любого нового протокола, прежде чем выпускать его в продакшен.

> 🎒 **На пальцах.** Пять вопросов — это пять мест, где системы ломаются в продакшене чаще всего. Проверьте на своём последнем проекте: если на второй вопрос ответ «id есть, а отмены нет», значит зависшая задача у вас снимается только рестартом. Такой чек-лист занимает пол-страницы, а экономит недели разбора инцидентов.

2. Расширьте демо contract-net перформативом `cancel`, который позволяет менеджеру снять задачу посреди сбора заявок. Какой случай отказа решает `cancel` и не решают одни повторы?
3. Прочитайте FIPA ACL Message Structure (http://www.fipa.org/specs/fipa00037/), разделы 4.1–4.3. Выберите один перформатив, не разобранный в этом уроке, и опишите его современный аналог в JSON-RPC.
4. Прочитайте Liu et al., arXiv:2505.02279. Для каждого из MCP, A2A, ACP, ANP выпишите, какие семейства перформативов FIPA они сохраняют, а какие выбрасывают.
5. Спроектируйте минимальную JSON-Schema для поля `content` перформатива `request` в вашей собственной системе. Что эта схема даёт по сравнению с чистым естественным языком и чего она стоит?

> 🎒 **На пальцах.** Задание 2 бьёт в точное место: повтор помогает, когда сообщение не дошло, а `cancel` нужен, когда задача больше не нужна вообще. Представьте тендер, где заказчик передумал: без отмены три участника продолжают считать заявки и жечь токены впустую. Один перформатив — и трое исполнителей останавливаются сразу.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Speech act | "An utterance that does something" | Остин и Сёрл: высказывания как действия. Теоретический родитель ACL. |
| FIPA | "That old XML thing" | IEEE Foundation for Intelligent Physical Agents. Стандартизировала ACL в 2000 году. |
| ACL | "Agent Communication Language" | Формат конверта FIPA: перформатив + содержимое + метаданные. |
| Performative | "The verb" | Класс интента сообщения: `inform`, `request`, `propose`, `cfp` и так далее. |
| KQML | "FIPA's predecessor" | Knowledge Query and Manipulation Language (1993). Проще и уже по охвату. |
| Ontology | "Shared vocabulary" | Формальное определение понятий, о которых говорит язык содержимого. |
| SL0 / SL1 | "FIPA content languages" | Semantic Language уровней 0 и 1 — семейство формальных языков содержимого. |
| Contract Net | "Task market" | Менеджер выпускает cfp; участники предлагают; менеджер принимает. Канонический протокол взаимодействия. |
| Interaction protocol | "Pattern of messages" | Последовательность перформативов с известной корректностью: request-when, subscribe-notify и прочие. |

> 🎒 **На пальцах.** Держите в голове разницу между Performative и Interaction protocol: первое — одно слово-действие, второе — целая партия из таких слов. `cfp` сам по себе ничего не решает, а Contract Net — это уже сценарий из `cfp`, `propose` и `accept-proposal`. Как ход в шахматах против дебюта: примитив один, а осмысленная последовательность другая.

## Further Reading

- [Liu et al. — A Survey of Agent Interoperability Protocols: MCP, ACP, A2A, ANP](https://arxiv.org/html/2505.02279v1) — канонический обзор 2025 года, связывающий современные спецификации с наследием FIPA
- [FIPA ACL Message Structure Specification (fipa00037)](http://www.fipa.org/specs/fipa00037/) — ратифицированный в 2000-м формат конверта
- [FIPA Communicative Act Library Specification (fipa00037)](http://www.fipa.org/specs/fipa00037/) — полный каталог перформативов
- [MCP specification 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25) — современный эквивалент `request` / `query-ref` для инструментов
- [A2A specification](https://a2a-protocol.org/latest/specification/) — современный эквивалент contract-net и subscribe-notify для равноправных агентов
