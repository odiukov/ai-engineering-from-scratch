# Корни и elicitation — ограничиваем область и спрашиваем пользователя на полпути

> Жёстко прописанные пути ломаются в ту же секунду, когда пользователь открывает другой проект. Заранее заполненные аргументы инструмента ломаются, когда пользователь сказал слишком мало. Корни ограничивают сервер набором URI, которым распоряжается пользователь; elicitation ставит вызов инструмента на паузу, чтобы спросить у пользователя структурированный ввод через форму или URL. Два клиентских примитива, два лекарства от типовых поломок MCP. SEP-1036 (elicitation в режиме URL, 2025-11-25) экспериментален всё первое полугодие 2026 года — проверяйте версии SDK, прежде чем на него опираться.

**Type:** Build
**Languages:** Python (stdlib, roots + elicitation demo)
**Prerequisites:** Phase 13 · 07 (MCP server)
**Time:** ~45 minutes

## Learning Objectives

- Объявлять `roots` и реагировать на `notifications/roots/list_changed`.
- Ограничивать файловые операции сервера теми URI, что лежат внутри объявленного набора корней.
- Использовать `elicitation/create`, чтобы попросить у пользователя подтверждение или структурированный ввод посреди вызова инструмента.
- Выбирать между elicitation в режиме формы и в режиме URL (второй экспериментален, риск дрейфа отмечен).

> 🎒 **На пальцах.** Два примитива — два разных вопроса. Корни отвечают на «куда мне вообще можно лезть», elicitation — на «что именно ты имел в виду». Первый спрашивается один раз при подключении, второй — в момент, когда инструмент уже начал работу и застрял.

## The Problem

Две конкретные поломки, в которые MCP-сервер для заметок влетает в продакшене.

**Broken path assumption.** Сервер написан под `~/notes`. Пользователь на другой машине держит заметки в `~/Documents/Notes` и получает вызов инструмента, который молча падает (файл не найден) или, что хуже, записывает не туда.

**Missing argument the user would know.** Пользователь просит «удали ту старую заметку про TPS-отчёт». Модель зовёт `notes_delete(title: "TPS report")`, а подходящих заметок три — за 2023, 2024 и 2025 годы. Инструмент не может угадать. Упасть с ошибкой «неоднозначно» раздражает; выполнить на всех трёх — катастрофа.

Корни лечат первое: клиент при `initialize` объявляет набор URI, к которым серверу можно прикасаться. Elicitation лечит второе: сервер ставит вызов инструмента на паузу и отправляет `elicitation/create`, чтобы пользователь выбрал нужную заметку.

> 🎒 **На пальцах.** Заметьте, какая из двух поломок опаснее. Первая теряет данные тихо: вы думаете, что заметка записалась, а она ушла в несуществующую папку. Вторая громче, но необратимее: три удалённые заметки вместо одной не вернёшь. Отсюда и два разных механизма, а не один общий.

## The Concept

### Roots

Клиент объявляет список корней при `initialize`:

```json
{
  "capabilities": {"roots": {"listChanged": true}}
}
```

Дальше сервер может вызвать `roots/list`:

```json
{"roots": [{"uri": "file:///Users/alice/Documents/Notes", "name": "Notes"}]}
```

Серверы ОБЯЗАНЫ считать корни границей: любое чтение или запись файла за пределами набора корней отклоняется. Клиент это не проверяет силой (сервер — всё ещё код, которому пользователь доверился), но серверы, соблюдающие спецификацию, эту границу уважают.

Когда пользователь добавляет или убирает корень, клиент присылает `notifications/roots/list_changed`. Сервер заново зовёт `roots/list` и обновляет свою границу.

> 🎒 **На пальцах.** Обратите внимание на формат: `file:///Users/alice/Documents/Notes` — это URI, а не путь, и у него есть человеческое имя `"Notes"` для интерфейса. Флаг `listChanged: true` означает «я буду присылать уведомления, не кэшируй список навсегда»: пользователь может открыть другую папку прямо посреди сессии.

### Why roots are a client primitive

Корни объявляет клиент, потому что они выражают модель согласия пользователя. Пользователь сказал Claude Desktop: «дай этому серверу заметок доступ вот к этим двум каталогам». Сервер не может расширить эту область сам.

> 🎒 **На пальцах.** Сравните с домашними ключами: вы даёте сантехнику ключ от одной квартиры, а не право самому решить, что ему нужен ещё и подвал. Именно поэтому `roots/list` — запрос от сервера к клиенту, а не поле, которое сервер прописывает у себя в конфиге.

### Elicitation: the form-mode default

`elicitation/create` принимает схему формы плюс формулировку на естественном языке:

```json
{
  "method": "elicitation/create",
  "params": {
    "message": "Delete 'TPS report'? Multiple notes match; pick one.",
    "requestedSchema": {
      "type": "object",
      "properties": {
        "note_id": {
          "type": "string",
          "enum": ["note-3", "note-7", "note-14"]
        },
        "confirm": {"type": "boolean"}
      },
      "required": ["note_id", "confirm"]
    }
  }
}
```

Клиент рисует форму, собирает ответ пользователя, возвращает:

```json
{
  "action": "accept",
  "content": {"note_id": "note-14", "confirm": true}
}
```

Возможных действий три: `accept` (пользователь заполнил), `decline` (пользователь закрыл окно), `cancel` (пользователь отменил весь вызов инструмента).

Схемы форм плоские — вложенные объекты в v1 не поддерживаются. SDK обычно отклоняют всё, что сложнее одного слоя.

> 🎒 **На пальцах.** Разберём схему по частям: `enum` с тремя id превращается в выпадающий список ровно из трёх вариантов, `confirm` типа boolean — в галочку, а `required` заставляет пользователя ответить на оба вопроса. Плюс `message` — единственная строка, которую человек читает глазами. То есть сервер описывает форму данными, а рисует её клиент.

### Elicitation: URL mode (SEP-1036, experimental)

Новое в 2025-11-25. Вместо схемы сервер отправляет URL:

```json
{
  "method": "elicitation/create",
  "params": {
    "message": "Sign in to GitHub",
    "url": "https://github.com/login/oauth/authorize?client_id=..."
  }
}
```

Клиент открывает URL в браузере, ждёт завершения и возвращает управление, когда пользователь вернулся. Полезно для OAuth-потоков, авторизации платежей и подписания документов, где формы недостаточно.

Оговорка про дрейф: форма ответа в SEP-1036 ещё устаканивается; одни SDK возвращают callback-URL, другие — токен завершения. Прочитайте release notes своего SDK, прежде чем полагаться на режим URL в продакшене.

> 🎒 **На пальцах.** Форму нельзя использовать там, где секрет не должен попасть на сервер: пароль от GitHub в поле `requestedSchema` прилетел бы прямо в MCP-сервер. В режиме URL сервер отдаёт только ссылку, логин происходит между браузером и GitHub, а сервер узнаёт лишь «получилось». Ровно тот же приём, что кнопка «Войти через Google» на любом сайте.

### When elicitation is the right tool

- Подтверждение пользователем перед разрушительными действиями (destructive hint плюс elicitation).
- Разрешение неоднозначности (выбрать один из N совпадений).
- Настройка при первом запуске (API-ключи, каталоги, предпочтения).
- Потоки в стиле OAuth (режим URL).

> 🎒 **На пальцах.** У всех четырёх пунктов общий признак: без ответа человека продолжать нельзя физически. Три заметки с одинаковым названием — сервер не угадает. API-ключ при первом запуске — сервер не придумает. Если же ответ можно вывести из данных, elicitation не нужен.

### When elicitation is wrong

- Заполнение обязательных аргументов инструмента, о которых модель могла бы спросить обычным текстом. Тут нужен нормальный повторный вопрос, а не диалог elicitation.
- Частые вызовы. Elicitation прерывает разговор; не дёргайте его внутри цикла.
- Всё, что сервер мог бы проверить уже после факта. Проверьте, верните ошибку, пусть модель сама спросит пользователя текстом.

> 🎒 **На пальцах.** Правило простое: elicitation стоит дорого, потому что тормозит человека. Один диалог перед удалением трёх заметок — уместно. Диалог на каждой из 200 строк при импорте — вы только что заставили пользователя нажать «ок» двести раз, и он выключит ваш сервер.

### Human-in-the-loop bridge

Elicitation вместе с sampling дают ту самую модель MCP «человек в цикле». Агентный цикл сервера может встать на паузу и за пользовательским вводом (elicitation), и за рассуждением модели (sampling). Phase 13 · 11 разбирал sampling; этот урок разбирает elicitation. Соедините их — получите полный контроль посреди цикла.

> 🎒 **На пальцах.** Два механизма — две разные паузы одного цикла: sampling спрашивает у модели, elicitation спрашивает у человека. Сервер описания репозитория делает так: sampling выбирает пять файлов, elicitation спрашивает «читаем эти пять? один из них с секретами». Ни один ключ, ни одно решение при этом не остаются у сервера.

## Use It

`code/main.py` расширяет сервер заметок следующим:

- Ответ на `roots/list`, который сервер перезапрашивает после уведомлений о смене списка корней.
- Инструмент `notes_delete`, который через `elicitation/create` уточняет выбор, когда совпало несколько заметок.
- Инструмент `notes_setup`, который через elicitation в режиме URL открывает страницу настройки при первом запуске (смоделировано).
- Проверка границы, отклоняющая операции над URI за пределами объявленных корней.

Демо прогоняет три сценария: счастливый путь (одно совпадение), уточнение (три совпадения, срабатывает elicitation), запись за пределы корней (отклоняется).

> 🎒 **На пальцах.** Три сценария — это ровно три ветки, которые сервер обязан уметь: «всё понятно, делаю», «непонятно, спрашиваю», «нельзя, отказываю». Если в вашем инструменте есть только первая, значит две другие вы просто ещё не написали, а пользователь на них уже наткнётся.

## Ship It

Этот урок производит `outputs/skill-elicitation-form-designer.md`. Получив инструмент, которому может понадобиться подтверждение пользователя или уточнение, навык проектирует схему формы elicitation и шаблон сообщения.

> 🎒 **На пальцах.** Самая трудная часть здесь — не схема, а строка `message`. Сравните «Confirm action?» и «Delete 'TPS report'? Multiple notes match; pick one.» Первое пользователь одобрит на автопилоте, второе заставит прочитать. Навык проектирует именно это: понятный текст плюс плоскую схему под него.

## Exercises

1. Запустите `code/main.py`. Пройдите ветку с уточнением; убедитесь, что смоделированный ответ пользователя доезжает обратно до инструмента.

2. Добавьте новый инструмент `notes_archive`, который каждый раз требует подтверждения через elicitation (destructive hint). Оцените UX: чем это отличается от того, как модель переспрашивает текстом?

3. Реализуйте elicitation в режиме URL для OAuth-потока при первом запуске. Учтите риск дрейфа и добавьте проверку версии SDK.

4. Расширьте обработку `roots/list`: когда приходит уведомление, сервер должен атомарно перечитать список и заново проверить открытые файловые дескрипторы, которые могли оказаться вне области.

5. Прочитайте ветку обсуждения issue по SEP-1036 на GitHub. Найдите один открытый вопрос, который влияет на то, как серверам следует обрабатывать callback в режиме URL.

> 🎒 **На пальцах.** Задание четыре хитрее, чем кажется. Пользователь убрал корень `~/Documents/Notes`, а у вас уже открыт дескриптор на файл внутри него — операционной системе всё равно, запись пройдёт. Значит проверять границу надо не только при открытии, но и заново после каждого `list_changed`.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Root | «Граница согласия» | URI, к которому клиент разрешил серверу прикасаться |
| `roots/list` | «Сервер спрашивает свою область» | Клиент возвращает текущий набор корней |
| `notifications/roots/list_changed` | «Пользователь сменил область» | Клиент сообщает, что набор корней изменился |
| Elicitation | «Спросить пользователя посреди вызова» | Инициированный сервером запрос структурированного ввода от пользователя |
| `elicitation/create` | «Тот самый метод» | JSON-RPC-метод для запросов elicitation |
| Form mode | «Форма по схеме» | Плоская JSON Schema, отрисованная формой в интерфейсе клиента |
| URL mode | «Переход в браузер» | Экспериментальный SEP-1036; открывает URL и ждёт |
| `accept` / `decline` / `cancel` | «Варианты ответа пользователя» | Три ветки, которые сервер обязан обработать |
| Disambiguation | «Выбери одну» | Типовой сценарий elicitation, когда у инструмента N кандидатов |
| Flat form | «Только свойства верхнего уровня» | Схемы elicitation не умеют вложенность |

> 🎒 **На пальцах.** Обратите внимание, что все десять терминов делятся на две группы: три верхних — про корни, семь остальных — про elicitation. Общее у них одно слово, которого в таблице нет прямо: согласие. Корни — согласие, выданное заранее; elicitation — согласие, запрошенное на месте.
