# OpenTelemetry GenAI — сквозная трассировка вызовов инструментов

> Агент вызывает пять инструментов, три MCP-сервера и двух под-агентов. Вам нужен один трейс на всё это сразу. Семантические соглашения OpenTelemetry GenAI (стабильные атрибуты начиная с v1.37) — стандарт 2026 года, который из коробки понимают Datadog, Langfuse, Arize Phoenix, OpenLLMetry и AgentOps. В этом уроке называем обязательные атрибуты, проходим иерархию спанов (агент → LLM → инструмент) и собираем на stdlib генератор спанов, который вставляется в любой экспортёр OTel.

**Type:** Build
**Languages:** Python (stdlib, OTel span emitter)
**Prerequisites:** Phase 13 · 07 (MCP server), Phase 13 · 08 (MCP client)
**Time:** ~75 minutes

## Learning Objectives

- Назвать обязательные атрибуты OTel GenAI для спана LLM и спана выполнения инструмента.
- Построить иерархию трейса, покрывающую цикл агента, вызов LLM, вызов инструмента и отправку через MCP-клиент.
- Решить, какое содержимое захватывать (по явному согласию), а какое скрывать (значения по умолчанию).
- Отправлять спаны в локальный коллектор (Jaeger, Langfuse), не переписывая код инструментов.

## The Problem

Реальная отладка из февраля 2026-го: пользователь пишет «мой агент иногда отвечает 30 секунд, а иногда 3». Трейсов нет. В логах виден вызов LLM, но не отправка инструмента, не круг до MCP-сервера, не под-агент. Вы гадаете. В итоге находите причину: один MCP-сервер время от времени подвисает на холодном старте.

Без сквозной трассировки это не найти. OTel GenAI это лечит.

Соглашения устоялись в 2025-2026 годах в группе OpenTelemetry по семантическим соглашениям. Они задают стабильные имена атрибутов, чтобы Datadog, Langfuse, Phoenix, OpenLLMetry и AgentOps разбирали одни и те же спаны. Обвесили код один раз — отправляете куда угодно.

> 🎒 **На пальцах.** Разница 30 секунд против 3 — это десятикратный разброс, и без трейса вы не знаете, где именно осели 27 секунд. Это как искать пробку на маршруте, зная только общее время поездки: пока не разметишь путь по участкам, виноват «весь город». Спаны и есть разметка по участкам.

## The Concept

### Span hierarchy

```
agent.invoke_agent  (top, INTERNAL span)
 ├── llm.chat       (CLIENT span)
 ├── tool.execute   (INTERNAL)
 │    └── mcp.call  (CLIENT span)
 ├── llm.chat       (CLIENT span)
 └── subagent.invoke (INTERNAL)
```

Всё целиком вкладывается под один trace id. Span id связывают отношения «родитель — ребёнок».

> 🎒 **На пальцах.** Посчитайте спаны на схеме: их шесть — один агентский сверху, два вызова LLM, один инструмент, один MCP-вызов внутри инструмента и один под-агент. Глубина три уровня. В интерфейсе трассировки это рисуется водопадом полосок, и та полоска, что длиннее остальных, и есть ваша проблема.

### Required attributes

Согласно семантическим соглашениям 2025-2026:

- `gen_ai.operation.name` — `"chat"`, `"text_completion"`, `"embeddings"`, `"execute_tool"`, `"invoke_agent"`.
- `gen_ai.provider.name` — `"openai"`, `"anthropic"`, `"google"`, `"azure_openai"`.
- `gen_ai.request.model` — строка запрошенной модели (например, `"gpt-4o-2024-08-06"`).
- `gen_ai.response.model` — модель, которая фактически обслужила запрос.
- `gen_ai.usage.input_tokens` / `gen_ai.usage.output_tokens`.
- `gen_ai.response.id` — id ответа провайдера, чтобы сопоставлять записи.

Для спанов инструментов:

- `gen_ai.tool.name` — идентификатор инструмента.
- `gen_ai.tool.call.id` — id конкретного вызова.
- `gen_ai.tool.description` — описание инструмента (необязательно).

Для спанов агентов:

- `gen_ai.agent.name` / `gen_ai.agent.id` / `gen_ai.agent.description`.

> 🎒 **На пальцах.** Зачем два поля под модель? Вы просите `"gpt-4o"`, а обслуживает вас `"gpt-4o-2024-08-06"` — `request.model` хранит вашу просьбу, `response.model` реальность. Когда провайдер тихо подменит версию и качество просядет, разница между этими двумя полями будет единственной уликой.

### Span kinds

- `SpanKind.CLIENT` для вызовов, пересекающих границу процесса (провайдер LLM, MCP-сервер).
- `SpanKind.INTERNAL` для шагов собственного цикла агента и выполнения инструмента.

> 🎒 **На пальцах.** Правило простое: ушли за пределы своего процесса — CLIENT, остались внутри — INTERNAL. В иерархии выше CLIENT ровно у трёх спанов: два `llm.chat` и один `mcp.call`. Зачем различать: по CLIENT-спанам считают сетевые задержки и внешние сбои, а INTERNAL — это ваш собственный код, и виноваты в нём вы.

### Opt-in content capture

По умолчанию спаны несут метрики и тайминги — не промпты и не ответы модели. Крупные payload'ы и персональные данные выключены по умолчанию. Чтобы захватывать содержимое, выставьте `OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental` и нужные переменные окружения для захвата контента. Перед включением в проде подумайте дважды.

> 🎒 **На пальцах.** Дефолт выключен не из скромности. Один промпт с медицинской выпиской пользователя, улетевший в Datadog, — это утечка персональных данных в систему, где логи живут 30 дней и доступны всей команде. Включайте захват контента на стейджинге и на синтетических данных, а в проде — только если юристы сказали «да».

### Events on spans

События внутри спана могут нести и токен-уровневые подробности:

- `gen_ai.content.prompt` — входные сообщения.
- `gen_ai.content.completion` — выходные сообщения.
- `gen_ai.content.tool_call` — вызов инструмента, как он был записан.

События упорядочены по времени внутри спана, поэтому дают детальный повтор происходившего.

> 🎒 **На пальцах.** Спан отвечает на вопрос «сколько это длилось», события — «что именно происходило внутри». Как запись матча: спан — итоговый счёт, события — таймкоды голов. Порядок событий важнее, чем кажется: именно по нему видно, что модель сначала попросила инструмент, потом получила ошибку, потом попросила его снова.

### Exporters

Спаны OTel уезжают в:

- **Jaeger / Tempo.** Open source, разворачивается на своих серверах.
- **Langfuse.** Специально под наблюдаемость LLM; рисует расход токенов.
- **Arize Phoenix.** Оценка и трассировка в одном месте.
- **Datadog.** Коммерческий; разбирает атрибуты `gen_ai.*` из коробки.
- **Honeycomb.** Колоночный; удобно писать запросы.

Все они говорят на OTLP — это формат передачи по проводу. Вашему коду всё равно.

> 🎒 **На пальцах.** Ровно та же выгода, что у MCP: пишете под стандарт, а не под вендора. Пять бэкендов в списке выше — и переезд с Jaeger на Datadog меняет строку конфигурации экспортёра, а не сотню мест с инструментированием. Проверять надёжность стандарта надо именно так: сколько кода придётся тронуть при смене бэкенда.

### Propagation across MCP

Когда MCP-клиент вызывает сервер, вставляйте в запрос заголовок W3C `traceparent`. Streamable HTTP обычные заголовки поддерживает. Stdio заголовки HTTP не несёт вовсе; в роадмапе спецификации на 2026 год обсуждается добавление поля `_meta.traceparent` в вызовы JSON-RPC.

Пока это не вышло: кладите traceparent в `_meta` каждого запроса руками. Сервер записывает trace id в лог.

> 🎒 **На пальцах.** Без проброски traceparent у вас получаются два разных трейса — один у клиента, один у сервера, и связать их можно только по времени, на глазок. С пробросом trace id один и тот же по обе стороны провода, и подвисший MCP-сервер из начала урока находится за один поиск по id, а не за вечер сопоставления логов.

### Metrics

Помимо спанов, семантические соглашения GenAI задают метрики:

- `gen_ai.client.token.usage` — гистограмма.
- `gen_ai.client.operation.duration` — гистограмма.
- `gen_ai.tool.execution.duration` — гистограмма.

Берите их для дашбордов, которым не нужны подробности по каждому вызову.

> 🎒 **На пальцах.** Спаны и метрики отвечают на разные вопросы. «Почему вот этот запрос тормозил» — спаны. «Растёт ли p95 по инструментам за неделю» — метрики. Гистограмма дешевле: она хранит не миллион вызовов, а распределение по корзинам, поэтому по ней можно строить дашборд за месяц, не разоряясь на хранении.

### AgentOps layer

AgentOps (основан в 2024-м) специализируется на наблюдаемости GenAI. Он оборачивает популярные фреймворки (LangGraph, Pydantic AI, CrewAI) и сам отдаёт спаны OTel. Полезен, если ваш стек стоит на поддерживаемом фреймворке; во всех остальных случаях обвешивайте код руками.

```figure
t3-span-waterfall
```

> 🎒 **На пальцах.** Автоматическое инструментирование — как автоматическая коробка передач: удобно, пока едете по знакомой дороге. На LangGraph вы получаете спаны бесплатно, но за свой самописный цикл агента отвечаете сами, и ни один враппер не догадается, что ваш `run_step()` — это `invoke_agent`.

## Use It

`code/main.py` печатает в stdout спаны в форме OTel (в формате, похожем на OTLP-JSON) для агента, который вызывает LLM, отправляет два инструмента и делает один круг до MCP-сервера. Настоящего экспортёра нет — урок про форму спана и набор атрибутов. Скормите вывод любому OTLP-совместимому просмотрщику или просто прочитайте глазами.

На что смотреть:

- Trace id общий у всех спанов.
- Связи «родитель — ребёнок» закодированы через `parentSpanId`.
- Обязательные атрибуты `gen_ai.*` заполнены.
- Захват контента по умолчанию выключен; в одном сценарии он включается переменной окружения.

> 🎒 **На пальцах.** Первое, что стоит проверить глазами в выводе: `traceId` у всех спанов одинаковый, а `parentSpanId` у дочерних равен `spanId` родителя. Если хоть где-то `parentSpanId` пустой, спан всплывёт в интерфейсе отдельным сиротой — и водопад развалится на несвязанные полоски.

## Ship It

Этот урок даёт `outputs/skill-otel-genai-instrumentation.md`. По кодовой базе агента навык выдаёт план инструментирования: где добавить спаны, какие атрибуты заполнить и в какие экспортёры целиться.

> 🎒 **На пальцах.** План инструментирования нужен ровно потому, что спаны легко наставить не там. Обвесили только вызовы LLM — увидите 3 секунды из 30 и снова будете гадать. Полезное правило: спан ставится на каждую границу, за которой время может застрять, — сеть, диск, чужой процесс.

## Exercises

1. Запустите `code/main.py`. Посчитайте спаны и определите, какие из них CLIENT, а какие INTERNAL.

2. Включите захват контента (через переменную окружения) и убедитесь, что появились события `gen_ai.content.prompt` и `gen_ai.content.completion`. Отметьте последствия для персональных данных.

3. Добавьте метрику выполнения инструмента `gen_ai.tool.execution.duration` и отдавайте по одному замеру гистограммы на каждый вызов.

4. Пробросьте traceparent из родительского спана агента в поле `_meta.traceparent` запроса к MCP. Проверьте, что MCP-сервер увидел бы тот же trace id.

5. Прочитайте спецификацию семантических соглашений OTel GenAI. Найдите один перечисленный там атрибут, который код этого урока НЕ отдаёт. Добавьте его.

> 🎒 **На пальцах.** Во втором задании обратите внимание не на сам факт появления событий, а на их размер. Промпт на 4000 токенов — это примерно 16 КБ текста в каждом спане; при 100 запросах в минуту вы льёте в бэкенд около 96 МБ в час только промптами. Поэтому захват контента чаще включают выборочно — на проценте трафика.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| OTel | «OpenTelemetry» | Открытый стандарт для трейсов, метрик и логов |
| GenAI semconv | «Семантические соглашения GenAI» | Стабильные имена атрибутов для спанов LLM, инструментов и агентов |
| `gen_ai.*` | «Пространство имён атрибутов» | Все атрибуты GenAI носят этот префикс |
| Span | «Замер операции» | Единица работы со временем начала, конца и набором атрибутов |
| Trace | «Родословная спанов» | Дерево спанов с общим trace id |
| SpanKind | «CLIENT / SERVER / INTERNAL» | Подсказка о направлении спана |
| OTLP | «OpenTelemetry Line Protocol» | Формат передачи данных в экспортёры |
| Opt-in content | «Захват промптов и ответов» | По умолчанию выключен; включается переменной окружения |
| traceparent | «Заголовок W3C» | Переносит контекст трейса между сервисами |
| Exporter | «Отправлялка под конкретный бэкенд» | Компонент, который отсылает спаны в Jaeger / Datadog и прочие |
