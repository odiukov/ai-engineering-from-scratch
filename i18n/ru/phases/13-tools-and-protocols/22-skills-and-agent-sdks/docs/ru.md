# Навыки и агентные SDK — Anthropic Skills, AGENTS.md, OpenAI Apps SDK

> MCP говорит «какие инструменты есть». Навыки говорят «как сделать задачу». Стек 2026 года укладывает оба слоя друг на друга. Agent Skills от Anthropic (открытый стандарт, декабрь 2025) поставляются как SKILL.md с постепенным раскрытием. Apps SDK от OpenAI — это MCP плюс метаданные виджетов. AGENTS.md (уже в 60 000+ репозиториев) лежит в корне репозитория как контекст агента на уровне проекта. Этот урок называет, что покрывает каждый слой, и собирает минимальный бандл SKILL.md + AGENTS.md, который переезжает между агентами.

**Type:** Learn
**Languages:** Python (stdlib, SKILL.md parser and loader)
**Prerequisites:** Phase 13 · 07 (MCP server)
**Time:** ~45 minutes

## Learning Objectives

- Различать три слоя: AGENTS.md (контекст проекта), SKILL.md (переиспользуемое умение), MCP (инструменты).
- Написать SKILL.md с YAML-фронтматтером и постепенным раскрытием.
- Загружать навыки в рантайм агента прямо из файловой системы.
- Собрать навык вместе с MCP-сервером и AGENTS.md так, чтобы один пакет работал в Claude Code, Cursor и Codex.

## The Problem

Инженер выжимает процесс написания release notes в многошаговый промпт: «Прочитай последние смёрженные PR. Сгруппируй по областям. Опиши каждый. Напиши запись в чейнджлог в стиле команды. Отправь черновик в Slack». И кладёт это в документ Notion для команды.

Теперь он хочет пользоваться этим процессом из Claude Code, Cursor и Codex CLI. Каждый агент грузит инструкции по-своему: у Claude Code слэш-команды, у Cursor правила, у Codex `.codex.md`. Инженер копирует процесс трижды и поддерживает три копии.

AGENTS.md и SKILL.md вместе это лечат:

- **AGENTS.md** лежит в корне репозитория. Каждый совместимый агент читает его при старте сессии. «Как устроен этот проект? Какие тут договорённости? Какой командой запускать тесты?»
- **SKILL.md** — переносимый бандл: YAML-фронтматтер (name, description) плюс тело в markdown плюс опциональные ресурсы. Агенты с поддержкой навыков грузят их по имени, когда нужно.
- **MCP** (Phase 13 · 06-14) отвечает за инструменты, которые навык вызывает.

Три слоя, один переносимый артефакт.

> 🎒 **На пальцах.** Считайте затраты: три копии процесса — это три места, где надо поправить одну и ту же опечатку, и рано или поздно копии разъезжаются. Один SKILL.md — один файл на всех агентов. Как один рецепт в семейной книге вместо трёх бумажек на трёх кухнях.

## The Concept

### AGENTS.md (agents.md)

Появился в конце 2025-го, к апрелю 2026-го прижился в 60 000+ репозиториев. Один файл в корне репозитория. Формат:

```markdown
# Project: my-service

## Conventions
- TypeScript with strict mode.
- Use Pydantic for models on the Python side.
- Tests run with `pnpm test`.

## Build and run
- `pnpm dev` for local dev server.
- `pnpm build` for production bundle.
```

Агенты читают это при старте сессии и подстраивают своё поведение под проект. В 2026 году AGENTS.md поддерживает каждый кодовый агент: Claude Code, Cursor, Codex, Copilot Workspace, opencode, Windsurf, Zed.

> 🎒 **На пальцах.** Обратите внимание, насколько файл скучный: соглашения и команды запуска, никакой магии. Именно поэтому он и работает. Строка про `pnpm test` избавляет вас от диалога «а как тут гонять тесты?» на каждой новой сессии — это записка новому сотруднику, приклеенная к монитору.

### SKILL.md format

Agent Skills от Anthropic (выпущены как открытый стандарт в декабре 2025):

```markdown
---
name: release-notes-writer
description: Write a changelog entry for the latest merged PRs following this project's style.
---

# Release notes writer

When invoked, run these steps:

1. List PRs merged since the last tag. Use `gh pr list --base main --state merged`.
2. Group by label: feature, fix, chore, docs.
3. For each PR in each group, write one line: `- <title> (#<num>)`.
4. Draft the release notes and stage them in CHANGELOG.md.

If the user says "ship", run `git tag vX.Y.Z` and `gh release create`.

## Notes

- Never include commits without a PR.
- Skip "chore" entries from the public changelog.
```

Фронтматтер объявляет личность навыка. Тело — это промпт, который показывают модели, когда навык загружается.

> 🎒 **На пальцах.** Разберите файл на две части: четыре строки метаданных сверху и остальное — обычная инструкция человеку. Поле `description` — это то, по чему агент решает, брать навык или нет, поэтому оно важнее всего тела. Как обложка книги: по ней выбирают, а читают уже внутренности.

### Progressive disclosure

Навык может ссылаться на подресурсы, которые агент подтягивает только при необходимости. Пример:

```
skills/
  release-notes-writer/
    SKILL.md
    style-guide.md
    template.md
    scripts/
      generate.sh
```

SKILL.md говорит «правила стиля смотри в style-guide.md». Агент подтягивает style-guide.md только когда навык реально работает. Так промпт не распухает от деталей, которые модели могут и не понадобиться.

> 🎒 **На пальцах.** Прикиньте на токенах: SKILL.md весит 300 токенов, а style-guide.md — 2000. Если навык загружается в каждой сессии, а стиль нужен раз в десять запусков, ленивая загрузка экономит 1800 токенов девять раз из десяти. Это как оглавление вместо всей книги в кармане.

### Filesystem discovery

Рантаймы агентов сканируют известные директории на файлы SKILL.md:

- `~/.anthropic/skills/*/SKILL.md`
- Project `./skills/*/SKILL.md`
- `~/.claude/skills/*/SKILL.md`

Загрузка идёт по имени папки и по полю `name` во фронтматтере. Claude Code, Anthropic Claude Agent SDK и SkillKit (кросс-агентный) следуют одному и тому же шаблону.

> 🎒 **На пальцах.** Три пути — это три области видимости: общая для всех проектов, локальная для этого репозитория и личная для вашего Claude Code. Положили навык в `./skills/` — он уехал вместе с репозиторием и достался коллегам. Положили в домашнюю папку — остался только у вас.

### Anthropic Claude Agent SDK

`@anthropic-ai/claude-agent-sdk` (TypeScript) и `claude-agent-sdk` (Python) грузят навыки при старте сессии и выставляют их как вызываемых «агентов» внутри рантайма. Цикл агента отправляет управление в навык, когда пользователь его позвал.

> 🎒 **На пальцах.** Ключевое слово тут — «вызываемых». Навык перестаёт быть текстом, который вы копируете в чат, и становится функцией с именем. Разница как между инструкцией на бумаге и кнопкой на пульте: второе можно вызвать из кода.

### OpenAI Apps SDK

Запущен в октябре 2025-го; построен прямо на MCP. Объединяет прежние Connectors и Custom GPT Actions от OpenAI в одну поверхность для разработчика. Приложение на Apps SDK — это:

- MCP-сервер (инструменты, ресурсы, промпты).
- Плюс метаданные виджетов для интерфейса ChatGPT.
- Плюс опциональный ресурс MCP Apps `ui://` для интерактивных поверхностей.

Тот же протокол, богаче UX.

> 🎒 **На пальцах.** Разложите три пункта: первый вы уже умеете писать, второй и третий — это только про то, как результат выглядит внутри ChatGPT. То есть Apps SDK не новый протокол, а MCP плюс оформление. Как та же кухня, но с витриной в зале.

### Cross-agent portability via SkillKit

Инструменты вроде SkillKit и похожие слои кросс-агентной раздачи переводят один SKILL.md в родной формат каждого из 32+ ИИ-агентов (Claude Code, Cursor, Codex, Gemini CLI, OpenCode и так далее). Один источник правды; много потребителей.

> 🎒 **На пальцах.** Считайте руками: 32 агента — это 32 формата правил, и вручную это 32 файла на каждый навык. При десяти навыках получается 320 файлов, которые надо держать в синхроне. Как один текст, переведённый на 32 языка: править имеет смысл только оригинал.

### The three-layer stack

| Layer | File | Loaded when | Purpose |
|-------|------|-------------|---------|
| AGENTS.md | корень репозитория | при старте сессии | договорённости на уровне проекта |
| SKILL.md | директория навыков | когда навык позвали | переиспользуемый процесс |
| MCP server | внешний процесс | когда нужны инструменты | вызываемые действия |

Все три слоя складываются: агент читает AGENTS.md при старте сессии, пользователь зовёт навык, инструкции навыка содержат вызовы MCP-инструментов, агент отправляет их через MCP-клиент.

```figure
t3-skill-layers
```

> 🎒 **На пальцах.** Смотрите на колонку Loaded when — она и объясняет, зачем слоёв три. AGENTS.md платит токенами всегда, SKILL.md только когда его позвали, MCP-сервер вообще живёт снаружи и токенов не ест до вызова. Три разные цены за три разных вида знания.

## Use It

`code/main.py` даёт парсер и загрузчик SKILL.md на стандартной библиотеке. Он находит навыки в `./skills/`, разбирает YAML-фронтматтер и тело в markdown, а на выходе отдаёт словарь с ключами по именам навыков. Затем симулирует цикл агента, который зовёт `release-notes-writer` по имени.

На что смотреть:

- YAML-фронтматтер разбирается минимальным парсером на стандартной библиотеке (без зависимости от `pyyaml`).
- Тело навыка хранится дословно; агент подставляет его в системный промпт при вызове.
- Постепенное раскрытие показано через функцию `read_subresource`, которая подтягивает упомянутые файлы по требованию.

> 🎒 **На пальцах.** Обратите внимание на слово «дословно»: загрузчик не переписывает тело навыка, а просто приклеивает его к системному промпту. Значит, качество навыка — это качество вашего текста, а не хитрость кода. Загрузчик тут курьер, а не редактор.

## Ship It

Этот урок даёт `outputs/skill-agent-bundle.md`. По описанию процесса навык собирает готовый бандл SKILL.md + AGENTS.md + чертёж MCP-сервера, переносимый между агентами.

> 🎒 **На пальцах.** Заметьте изящность: навык, который производит навыки. Один раз описали процесс словами — получили три файла в правильных форматах, вместо часа копания в документации трёх стандартов.

## Exercises

1. Запустите `code/main.py`. Добавьте второй навык в `skills/` и убедитесь, что загрузчик его подхватил.

2. Напишите AGENTS.md для репозитория этого курса. Включите команды тестов, соглашения по стилю и ментальную модель Phase 13.

3. Перенесите многошаговый процесс из внутренних документов вашей команды в SKILL.md. Проверьте, что он грузится в Claude Code.

4. Переведите навык в родные форматы правил Cursor и Codex руками. Посчитайте разницу между форматами — это и есть та поверхность перевода, которую автоматизирует SkillKit.

5. Прочитайте пост Anthropic про Agent Skills. Найдите одну возможность Claude Agent SDK, которую загрузчик из этого урока не закрывает. (Подсказка: вызов агента из агента.)

> 🎒 **На пальцах.** Четвёртое задание отрезвляет. Один и тот же навык на 40 строк превращается в три файла с разными заголовками, разными полями метаданных и разными местами хранения — и это только три агента из 32. Посчитав диффы руками, вы навсегда поймёте, зачем нужен один источник правды.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| SKILL.md | «Файл навыка» | YAML-фронтматтер плюс тело в markdown, который грузит рантайм агента |
| AGENTS.md | «Контекст агента в корне репозитория» | Файл с договорённостями проекта, читается при старте сессии |
| Progressive disclosure | «Ленивая загрузка подресурсов» | Тело навыка ссылается на файлы, которые подтягиваются только при надобности |
| Frontmatter | «YAML-блок сверху» | Метаданные (name, description) между разделителями `---` |
| Claude Agent SDK | «Рантайм навыков от Anthropic» | `@anthropic-ai/claude-agent-sdk`, грузит навыки и раздаёт управление |
| OpenAI Apps SDK | «MCP плюс метаданные виджета» | Поверхность разработчика от OpenAI: MCP плюс крючки в интерфейс ChatGPT |
| Skill discovery | «Сканирование файловой системы» | Обойти известные директории в поисках SKILL.md, ключ — имя |
| Cross-agent portability | «Один навык на многих агентов» | Перевод одного SKILL.md в 32+ агента инструментами вроде SkillKit |
| Agent Skill | «Переносимое умение» | Переиспользуемый шаблон задачи, живущий вне понятия «инструмент» из MCP |
| Apps SDK | «MCP плюс интерфейс ChatGPT» | Connectors и Custom GPTs, сведённые к одному MCP |

> 🎒 **На пальцах.** Две строки таблицы отвечают на два разных вопроса. MCP-инструмент отвечает «что я умею вызвать» — например, `create_pull_request`. Agent Skill отвечает «в каком порядке это вызывать и зачем». Молоток и инструкция по сборке шкафа: без второго первый бесполезен.
