# Вызов функций в деталях — OpenAI, Anthropic, Gemini

> Три передовых провайдера сошлись на одном и том же цикле вызова инструментов в 2024 году, а потом разошлись во всём остальном. OpenAI использует `tools` и `tool_calls`. Anthropic — блоки `tool_use` и `tool_result`. Gemini — `functionDeclarations` и сопоставление по уникальным id. Этот урок кладёт три формата рядом, чтобы код, который работает у одного провайдера, не рассыпался при переносе.

**Type:** Build
**Languages:** Python (stdlib, schema translators)
**Prerequisites:** Phase 13 · 01 (the tool interface)
**Time:** ~75 minutes

## Learning Objectives

- Назвать три различия в форме полезных нагрузок вызова функций у OpenAI, Anthropic и Gemini (объявление, вызов, результат).
- Перевести одно объявление инструмента во все три провайдерских формата и предсказать, где разойдутся ограничения строгого режима.
- Использовать `tool_choice` у каждого провайдера, чтобы заставить, запретить или разрешить модели выбирать вызовы инструментов.
- Знать жёсткие лимиты каждого провайдера (число инструментов, глубина схемы, длина аргументов) и подписи ошибок, которые каждый из них выдаёт при нарушении лимита.

## The Problem

Форма запроса с вызовом функций различается у разных провайдеров. Три конкретных примера из продовых стеков 2026 года:

**OpenAI Chat Completions / Responses API.** Вы передаёте `tools: [{type: "function", function: {name, description, parameters, strict}}]`. В ответе модели лежит `choices[0].message.tool_calls: [{id, type: "function", function: {name, arguments}}]`, где `arguments` — строка JSON, которую нужно разобрать самому. Строгий режим (`strict: true`) принудительно соблюдает схему через ограниченное декодирование.

**Anthropic Messages API.** Вы передаёте `tools: [{name, description, input_schema}]`. Ответ приходит как `content: [{type: "text"}, {type: "tool_use", id, name, input}]`. Поле `input` уже разобрано (это объект, а не строка). Отвечаете новым сообщением с ролью `user`, внутри которого блок `{type: "tool_result", tool_use_id, content}`.

**Google Gemini API.** Вы передаёте `tools: [{functionDeclarations: [{name, description, parameters}]}]` (вложено внутрь `functionDeclarations`). Ответ приходит как `candidates[0].content.parts: [{functionCall: {name, args, id}}]`, где `id` уникален начиная с Gemini 3 — для сопоставления параллельных вызовов. Отвечаете через `{functionResponse: {name, id, response}}`.

> 🎒 **На пальцах.** Три абзаца выше — это одна и та же посылка в трёх разных упаковках. У OpenAI аргументы приезжают строкой, и вам нужен `json.loads`; у Anthropic и Gemini — уже готовым объектом, и лишний разбор сломает код. Только на этом одном различии портированные интеграции падают чаще всего.

Цикл один и тот же. Разные имена полей, разная вложенность, разные соглашения «строка против объекта», разные механизмы сопоставления. Команда, которая написала погодного агента на OpenAI, платит два дня за перенос на Anthropic и ещё день на Gemini — только за водопровод.

Этот урок собирает транслятор, который сводит три формата к одному каноническому объявлению инструмента и разводит их по краям системы. Phase 13 · 17 обобщает тот же паттерн в LLM-шлюз.

> 🎒 **На пальцах.** Три дня на перенос — это цена того, что вы написали код прямо под формат провайдера. Транслятор переворачивает арифметику: вы держите одно каноническое объявление и три маленькие функции-переводчика, и добавление четвёртого провайдера стоит один день, а не три. Ровно так же работает драйвер принтера: приложение печатает «текст», а различия железа прячет драйвер.

## The Concept

### The common structure

Каждому провайдеру нужны пять вещей:

1. **Tool list.** Имя, описание и входная схема для каждого инструмента.
2. **Tool choice.** Заставить вызвать конкретный инструмент, запретить инструменты или отдать решение модели.
3. **Call emission.** Структурированный вывод с именем инструмента и аргументами.
4. **Call id.** Сопоставить ответ с нужным вызовом (важно для параллельных).
5. **Result injection.** Сообщение или блок, который привязывает результат к вызову.

> 🎒 **На пальцах.** Эти пять пунктов — как обязательные графы на бланке посылки: что отправляем, кому можно, что вложено, номер отслеживания, куда приклеить квитанцию. Провайдеры спорят только о том, в каком углу бланка эти графы напечатаны. Если в вашей абстракции нет пункта 4, вы просто ещё не пробовали параллельные вызовы.

### Shape diffs, field by field

| Aspect | OpenAI | Anthropic | Gemini |
|--------|--------|-----------|--------|
| Declaration envelope | `{type: "function", function: {...}}` | `{name, description, input_schema}` | `{functionDeclarations: [{...}]}` |
| Schema field | `parameters` | `input_schema` | `parameters` |
| Response container | `tool_calls[]` в сообщении ассистента | `content[]` с типом `tool_use` | `parts[]` с типом `functionCall` |
| Arguments type | JSON строкой | разобранный объект | разобранный объект |
| Id format | `call_...` (генерирует OpenAI) | `toolu_...` (Anthropic) | UUID (Gemini 3+) |
| Result block | роль `tool`, `tool_call_id` | `user` с `tool_result`, `tool_use_id` | `functionResponse` с совпадающим `id` |
| Force-a-tool | `tool_choice: {type: "function", function: {name}}` | `tool_choice: {type: "tool", name}` | `tool_config: {function_calling_config: {mode: "ANY"}}` |
| Forbid tools | `tool_choice: "none"` | `tool_choice: {type: "none"}` | `mode: "NONE"` |
| Strict schema | `strict: true` | схема и есть контракт (соблюдается всегда) | `responseSchema` на уровне запроса |

> 🎒 **На пальцах.** В таблице 9 строк различий, и почти каждая — это одна строчка кода в трансляторе. Посмотрите на строку Schema field: у OpenAI и Gemini поле называется `parameters`, у Anthropic — `input_schema`; это буквально переименование одного ключа. А вот строка Id format показывает, что придумывать id самому не нужно ни у одного из трёх — его генерирует провайдер.

### Limits you will actually hit

- **OpenAI.** 128 инструментов на запрос. Глубина схемы 5. Строка аргументов не больше 8192 байт. Строгий режим требует: никаких `$ref`, никаких пересекающихся `oneOf`/`anyOf`/`allOf`, каждое свойство перечислено в `required`.
- **Anthropic.** 64 инструмента на запрос. Глубина схемы формально не ограничена, но на практике предел около 10. Флага строгого режима нет; схема выступает контрактом, и модель обычно ему следует.
- **Gemini.** 64 функции на запрос. Типы схемы — подмножество OpenAPI 3.0 (небольшое расхождение с JSON Schema 2020-12). Параллельные вызовы получили уникальные id начиная с Gemini 3.

> 🎒 **На пальцах.** Лимиты кажутся щедрыми, пока вы не подключили три MCP-сервера: 20 инструментов на сервер — и вы уже на 60, то есть у Anthropic до потолка 64 остаётся четыре штуки. Требование строгого режима «каждое свойство в `required`» тоже коварное: опциональных полей в строгом режиме OpenAI попросту нет, необязательность приходится изображать через `type: ["string", "null"]`.

### `tool_choice` behavior

Три режима поддерживают все, только называют по-разному.

- **Auto.** Модель сама выбирает: инструмент или текст. По умолчанию.
- **Required / Any.** Модель обязана вызвать хотя бы один инструмент.
- **None.** Модель не должна вызывать инструменты.

Плюс по одному режиму, уникальному для каждого провайдера:

- **OpenAI.** Заставить вызвать конкретный инструмент по имени.
- **Anthropic.** Заставить вызвать конкретный инструмент по имени; флаг `disable_parallel_tool_use` отделяет одиночный вызов от множественного.
- **Gemini.** `mode: "VALIDATED"` прогоняет каждый ответ через валидатор схемы независимо от намерения модели.

> 🎒 **На пальцах.** Auto, Required и None — это «решай сам», «обязательно позвони» и «не звони вообще». Практическая польза от None недооценена: на финальном ходу, когда все данные уже собраны, режим None гарантирует, что модель напишет ответ пользователю, а не уйдёт в ещё один вызов. Именно так лечат агентов, которые «зависают» на 15-м вызове того же инструмента.

### Parallel calls

Параметр `parallel_tool_calls: true` у OpenAI (по умолчанию) выдаёт несколько вызовов в одном сообщении ассистента. Вы выполняете их все и отвечаете пакетным сообщением с ролью tool, где по одной записи на каждый `tool_call_id`. Anthropic исторически делала одиночные вызовы; `disable_parallel_tool_use: false` (по умолчанию начиная с Claude 3.5) включает множественные. Gemini 2 разрешала параллельные вызовы, но не давала стабильных id; Gemini 3 добавила UUID, и ответы вне порядка сопоставляются чисто.

> 🎒 **На пальцах.** Параллельные вызовы — это отправить трёх курьеров сразу вместо очереди из трёх. Если один вызов API идёт 400 мс, то три подряд — 1,2 секунды, а три разом — те же 400 мс. И вся сложность сводится к одному: не потеряйте `tool_call_id`, иначе вы вернёте модели погоду Лондона под номером Токио.

### Streaming

Все трое поддерживают потоковую передачу вызовов инструментов. Формат на проводе отличается:

- **OpenAI.** Дельта-чанки `tool_calls[i].function.arguments` приходят по частям. Вы накапливаете их до `finish_reason: "tool_calls"`.
- **Anthropic.** События block-start / block-delta / block-stop. Частичные аргументы несут чанки `input_json_delta`.
- **Gemini.** `streamFunctionCallArguments` (новое в Gemini 3) выдаёт чанки с полем `functionCallId`, чтобы несколько параллельных вызовов могли перемежаться.

Phase 13 · 03 глубоко копает параллельность и сборку потока. Этот урок сосредоточен на форме объявления и одиночного вызова.

> 🎒 **На пальцах.** Стриминг аргументов — это как получать адрес доставки по буквам по телефону: пока фраза не кончилась, JSON невалиден, и парсить его бессмысленно. Отсюда правило: копите чанки в буфер и разбирайте один раз в конце. У Gemini поле `functionCallId` в каждом чанке нужно ровно потому, что два параллельных вызова диктуют свои адреса одновременно, и без метки буквы смешаются.

### Errors and repair

Ошибки невалидных аргументов тоже выглядят по-разному.

- **OpenAI (non-strict).** Модель возвращает `arguments: "{bad json}"`, ваш разбор JSON падает, вы вкладываете сообщение об ошибке и вызываете модель снова.
- **OpenAI (strict).** Валидация происходит во время декодирования; невалидный JSON невозможен, но может появиться `refusal`.
- **Anthropic.** В `input` могут попасть неожиданные поля; схема носит рекомендательный характер. Валидируйте у себя на сервере.
- **Gemini.** Особенность OpenAPI 3.0: `enum` на полях объекта молча игнорируется, проверяйте сами.

> 🎒 **На пальцах.** Общий вывод из четырёх пунктов простой: доверять чужой валидации нельзя нигде, кроме строгого режима OpenAI. Пример с Gemini совсем наглядный: вы объявили `units` с `enum: ["celsius", "fahrenheit"]`, модель прислала `"kelvin"`, и никто, кроме вашего кода, этого не заметит. Одна проверка на вашей стороне закрывает все четыре случая сразу.

### The translator pattern

Каноническое объявление инструмента в вашем коде выглядит так (форму выбираете вы):

```python
Tool(
    name="get_weather",
    description="Use when ...",
    input_schema={"type": "object", "properties": {...}, "required": [...]},
    strict=True,
)
```

Три крошечные функции переводят его в три провайдерские формы. Обвязка в `code/main.py` делает ровно это, а потом прогоняет фальшивый вызов инструмента через форму ответа каждого провайдера. Сети не требуется — этот урок учит формам, а не HTTP.

Продовые команды заворачивают такой транслятор в `AbstractToolset` (Pydantic AI), `UniversalToolNode` (LangGraph) или `BaseTool` (LlamaIndex). Phase 13 · 17 собирает шлюз, который выставляет API в форме OpenAI перед любым из трёх провайдеров.

```figure
function-call-args
```

> 🎒 **На пальцах.** Одно объявление плюс три переводчика — это 1 + 3 = 4 куска кода вместо трёх независимых интеграций, которые придётся править синхронно при каждом изменении инструмента. Заметьте, что три названных фреймворка изобрели ровно эту же абстракцию под тремя разными именами: если крупные библиотеки сошлись на паттерне, спорить с ним не стоит.

## Use It

`code/main.py` определяет один канонический датакласс `Tool` и три транслятора, которые выдают JSON объявления для OpenAI, Anthropic и Gemini. Потом он разбирает вручную собранный ответ провайдера каждой из трёх форм в один и тот же канонический объект вызова — и это показывает, что под кожей семантика одинаковая. Запустите и сравните три объявления рядом.

Куда смотреть:

- Три блока объявления различаются только оболочкой и именами полей.
- Три блока ответа различаются тем, где лежит вызов (на верхнем уровне в `tool_calls`, блоком в `content[]`, записью в `parts[]`).
- Одна функция `canonical_call()` вытаскивает `{id, name, args}` из всех трёх форм ответа.

> 🎒 **На пальцах.** Смысл упражнения — увидеть, что 3 разных ответа дают 1 одинаковый объект `{id, name, args}`. Как только `canonical_call()` написана, вся остальная логика агента не знает и не должна знать, какой провайдер отвечал. Это и есть та единственная точка, которую придётся править, когда в 2027-м появится четвёртый провайдер.

## Ship It

Этот урок производит `outputs/skill-provider-portability-audit.md`. Получив интеграцию с вызовом функций под одного провайдера, навык выдаёт аудит переносимости: на какие лимиты провайдера она опирается, какие поля надо переименовать и что сломается при переносе на каждого из остальных.

> 🎒 **На пальцах.** Аудит переносимости — как проверка чемодана перед поездкой: влезет ли в габариты, нужен ли переходник для розетки. Практический выход обычно короткий: два переименования полей (`parameters` → `input_schema`), одно место с `json.loads` и один упёртый лимит вроде 64 инструментов. Дешевле узнать это сейчас, чем в день, когда бизнес попросит «а давайте на Gemini, там дешевле».

## Exercises

1. Запустите `code/main.py` и убедитесь, что три провайдерских JSON-объявления сериализуют один и тот же лежащий под ними объект `Tool`. Измените канонический инструмент, добавив параметр с enum, и подтвердите, что особенность OpenAPI приходится обрабатывать только транслятору Gemini.

2. Добавьте парсер `ListToolsResponse` для каждого провайдера, который вытаскивает список инструментов, возвращаемый моделью после вызова `list_tools` или обнаружения. У OpenAI родного аналога нет — отметьте эту асимметрию.

3. Реализуйте преобразование `tool_choice`: отобразите канонический `ToolChoice(mode="force", tool_name="x")` во все три провайдерские формы. Затем отобразите `mode="any"` и `mode="none"`. Сверьтесь с таблицей различий из урока.

4. Выберите одного из трёх провайдеров и прочитайте его руководство по вызову функций от начала до конца. Найдите в спецификации схемы одно поле, которого нет у двух других. Кандидаты: `strict` у OpenAI, `disable_parallel_tool_use` у Anthropic, `function_calling_config.allowed_function_names` у Gemini.

5. Напишите тестовый вектор: вызов инструмента, аргументы которого нарушают объявленную схему. Прогоните его через валидатор каждого провайдера (годится stdlib-валидатор из урока 01 в роли заменителя) и запишите, какие ошибки сработали. Задокументируйте, какого провайдера вы выбрали бы в прод за строгость.

> 🎒 **На пальцах.** Начните с третьего задания: три режима × три провайдера — это девять маленьких случаев, и вся таблица различий укладывается в голову за полчаса. Первое задание тоже быстрое и даёт самое запоминающееся наблюдение: из трёх трансляторов правку требует ровно один, и это Gemini с его подмножеством OpenAPI 3.0.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Function calling | "Tool use" | API на уровне провайдера для выдачи структурированных вызовов инструментов |
| Tool declaration | "Tool spec" | Имя + описание + входная полезная нагрузка, типизированная JSON Schema |
| `tool_choice` | "Force / forbid" | Режимы auto / required / none / конкретное имя инструмента |
| Strict mode | "Schema enforcement" | Флаг OpenAI, который ограничивает декодирование так, чтобы вывод совпал со схемой |
| `tool_use` block | "Anthropic's call shape" | Встроенный блок контента с полями id, name, input |
| `functionCall` part | "Gemini's call shape" | Запись в `parts[]`, содержащая name, args и id |
| Arguments-as-string | "Stringified JSON" | OpenAI возвращает аргументы строкой JSON, а не объектом |
| Parallel tool calls | "Fan-out in one turn" | Несколько вызовов инструментов в одном сообщении ассистента |
| Refusal | "Model declines" | Блок отказа вместо вызова, бывает только в строгом режиме |
| OpenAPI 3.0 subset | "Gemini schema quirk" | Gemini использует диалект, похожий на JSON Schema, с мелкими отличиями |
