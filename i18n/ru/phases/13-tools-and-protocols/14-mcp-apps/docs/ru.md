# MCP Apps — интерактивные UI-ресурсы через `ui://`

> Вывод инструмента только текстом ставит потолок на то, что агент может показать. MCP Apps (SEP-1724, официально с 26 января 2026) позволяют инструменту вернуть изолированный интерактивный HTML, который рисуется прямо в переписке в Claude Desktop, ChatGPT, Cursor, Goose и VS Code. Дашборды, формы, карты, 3D-сцены — всё через одно расширение. Этот урок разбирает схему ресурсов `ui://`, MIME-тип `text/html;profile=mcp-app`, протокол postMessage внутри песочницы iframe и ту поверхность атаки, которая появляется, когда серверу разрешают рисовать HTML.

**Type:** Build
**Languages:** Python (stdlib, UI resource emitter), HTML (sample app)
**Prerequisites:** Phase 13 · 07 (MCP server), Phase 13 · 10 (resources)
**Time:** ~75 minutes

## Learning Objectives

- Вернуть из вызова инструмента ресурс `ui://` и выставить правильный MIME и метаданные.
- Объявить связанный с инструментом UI через `_meta.ui.resourceUri`, `_meta.ui.csp` и `_meta.ui.permissions`.
- Реализовать JSON-RPC поверх postMessage в песочнице iframe для связи UI с хостом.
- Применить дефолты CSP и permissions-policy, которые защищают от атак со стороны UI.

## The Problem

Инструмент `visualize_timeline` образца 2025 года умеет вернуть «Вот 14 заметок в хронологическом порядке: ...». Это абзац текста. А пользователь хотел интерактивную временную шкалу. До MCP Apps выбор был такой: клиент-специфичные API для виджетов (артефакты Claude, HTML в Custom GPT от OpenAI) — или вообще никакого интерфейса.

MCP Apps (SEP-1724, вышел 26 января 2026) стандартизируют контракт. Результат инструмента содержит `resource`, у которого URI начинается с `ui://`, а MIME равен `text/html;profile=mcp-app`. Хост рисует его в изолированном iframe с урезанным CSP и без доступа к сети, пока доступ явно не выдан. UI внутри iframe отправляет сообщения хосту через крошечный диалект JSON-RPC поверх postMessage.

Каждый совместимый клиент (Claude Desktop, ChatGPT, Goose, VS Code) рисует один и тот же ресурс `ui://` одинаково. Один сервер, один HTML-бандл, универсальный интерфейс.

> 🎒 **На пальцах.** Сравните два ответа на один вопрос: строка «14 заметок в порядке дат» и настоящая шкала, где заметки можно двигать мышкой. Раньше вторую версию пришлось бы писать трижды — под Claude, под ChatGPT, под Cursor. Теперь пишете один HTML-файл, и все три клиента показывают его одинаково.

## The Concept

### The `ui://` resource scheme

Инструмент возвращает:

```json
{
  "content": [
    {"type": "text", "text": "Here is your notes timeline:"},
    {"type": "ui_resource", "uri": "ui://notes/timeline"}
  ],
  "_meta": {
    "ui": {
      "resourceUri": "ui://notes/timeline",
      "csp": {
        "defaultSrc": "'self'",
        "scriptSrc": "'self' 'unsafe-inline'",
        "connectSrc": "'self'"
      },
      "permissions": []
    }
  }
}
```

> 🎒 **На пальцах.** Разберите блок по частям: в `content` лежат две вещи — текст для модели и указатель на картинку для человека. А `_meta.ui` — это паспорт интерфейса: где взять HTML, что ему разрешено (`csp`) и чего он просит дополнительно (`permissions`, здесь пустой список). Модель читает текст, пользователь смотрит UI.

Затем хост вызывает `resources/read` по URI `ui://notes/timeline` и получает:

```json
{
  "contents": [{
    "uri": "ui://notes/timeline",
    "mimeType": "text/html;profile=mcp-app",
    "text": "<!doctype html>..."
  }]
}
```

> 🎒 **На пальцах.** Обратите внимание: это два отдельных шага, а не один. Инструмент вернул только адрес (`ui://notes/timeline`), сам HTML пришёл вторым запросом. Так дешевле: если хост уже показывал эту шкалу и держит бандл в кэше, второй запрос вообще не поедет по сети.

### Iframe sandbox

Хост рисует HTML внутри изолированного `<iframe>`, где:

- `sandbox="allow-scripts allow-same-origin"` (или строже, если так объявил сервер)
- Объявленный сервером CSP применяется через заголовки ответа.
- Никаких cookies, никакого localStorage с origin хоста.
- Доступ к сети ограничен тем, что перечислено в `connectSrc` внутри CSP.

> 🎒 **На пальцах.** Песочница — это стеклянная переговорка внутри офиса: сидящий внутри видит свои бумаги, но не может дотянуться до сейфа в коридоре. Четыре пункта выше и есть стены этой комнаты. Уберите третий пункт — и чужой HTML прочитает ваши токены из localStorage.

### postMessage protocol

Iframe общается с хостом через `window.postMessage`. Крошечный диалект JSON-RPC 2.0:

Всегда прибивайте `targetOrigin` к точному origin собеседника, а на приёмной стороне сверяйте `event.origin` со списком разрешённых, прежде чем что-либо обрабатывать. Никогда не используйте `"*"` ни на одном конце этого канала — внутри летят вызовы инструментов и чтения ресурсов.

```js
// iframe to host  (pin to host origin)
window.parent.postMessage({
  jsonrpc: "2.0",
  id: 1,
  method: "host.callTool",
  params: { name: "notes_update", arguments: { id: "note-14", title: "..." } }
}, "https://host.example.com");

// host to iframe  (pin to iframe origin)
iframe.contentWindow.postMessage({
  jsonrpc: "2.0",
  id: 1,
  result: { content: [...] }
}, "https://iframe.example.com");

// receiver on both sides
window.addEventListener("message", (event) => {
  if (event.origin !== "https://expected-peer.example.com") return;
  // safe to process event.data
});
```

> 🎒 **На пальцах.** Звёздочка вместо origin — это как крикнуть пароль на весь вагон вместо того, чтобы шепнуть его одному человеку. Любая другая страница, открытая в том же браузере и подписанная на сообщения, получит ваш `host.callTool` вместе с аргументами. Три строки в примере выше — проверка `event.origin` — стоят дешевле любого разбора инцидента.

Методы на стороне хоста, доступные для вызова из UI:

- `host.callTool(name, arguments)` — вызывает инструмент сервера.
- `host.readResource(uri)` — читает ресурс MCP.
- `host.getPrompt(name, arguments)` — забирает шаблон промпта.
- `host.close()` — закрывает интерфейс.

Каждый вызов всё равно идёт через протокол MCP и наследует права сервера.

> 🎒 **На пальцах.** Ключевая мысль в последней фразе: кнопка в вашем HTML не может больше, чем сам MCP-сервер. Нажатие «Сохранить» превращается в обычный `tools/call` через хост, с теми же согласованиями и теми же ограничениями. UI — это просто удобная морда к четырём уже знакомым методам, а не отдельный канал власти.

### Permissions

Список `_meta.ui.permissions` запрашивает дополнительные возможности:

- `camera` — доступ к камере пользователя (нужен для интерфейсов «отсканируй документ»).
- `microphone` — голосовой ввод.
- `geolocation` — местоположение.
- `network:*` — более широкий доступ к сети, чем даёт один `connectSrc`.

Каждое разрешение — это отдельный вопрос, который пользователь видит до того, как UI нарисуется.

> 🎒 **На пальцах.** Ровно как разрешения у мобильного приложения: фонарику камера не нужна, и если он её просит — это повод насторожиться. Timeline-шкале не нужно ничего, поэтому в примере выше `permissions: []`. Пустой список — самый сильный аргумент в пользу вашего UI при ревью.

### Security risks

HTML в iframe остаётся HTML. Новая поверхность атаки:

- **Prompt-injection via UI.** Вредоносный UI сервера может показать текст, похожий на системное сообщение, и обмануть пользователя. Хост при отрисовке обязан визуально отличать интерфейс сервера от собственного интерфейса.
- **Exfiltration via `connectSrc`.** Если CSP разрешает `connect-src: *`, интерфейс может отправить данные куда угодно. По умолчанию должно быть строго.
- **Clickjacking.** Интерфейс перекрывает элементы хоста. Хосты обязаны запрещать игры с z-index и следить за прозрачностью.
- **Steal focus.** Интерфейс забирает фокус клавиатуры и перехватывает следующее сообщение. Хост обязан это пресекать.

Phase 13 · 15 разбирает всё это подробно в рамках безопасности MCP; здесь мы только знакомимся.

> 🎒 **На пальцах.** Самая коварная из четырёх — первая: сервер рисует серую плашку «Система: подтвердите доступ к почте», и пользователь верит, потому что выглядит как настоящее окно приложения. Защита не в вашем HTML, а в том, что хост обводит чужой UI рамкой и подписывает источник. Поэтому не пытайтесь мимикрировать под интерфейс хоста — вас за это и забанят.

### `ui/initialize` handshake

После загрузки iframe отправляет `ui/initialize` через postMessage:

```json
{"jsonrpc": "2.0", "id": 0, "method": "ui/initialize",
 "params": {"theme": "dark", "locale": "en-US", "sessionId": "..."}}
```

Хост отвечает своими возможностями и токеном сессии. UI использует этот токен сессии в каждом последующем вызове хоста.

> 🎒 **На пальцах.** Три параметра в запросе — это ответ на вопрос «в какой обстановке меня показывают»: тема `dark`, локаль `en-US`, идентификатор сессии. Первые два нужны, чтобы ваша шкала не светила белым фоном в тёмной теме. Третий — чтобы хост понимал, от какого именно окна пришёл вызов, и мог отклонить чужой.

### AppRenderer / AppFrame SDK primitives

SDK ext-apps даёт два удобных примитива:

- `AppRenderer` (на стороне сервера) — оборачивает компонент React / Vue / Solid и выдаёт ресурс `ui://` с правильным MIME и метаданными.
- `AppFrame` (на стороне клиента) — принимает ресурс, монтирует iframe и посредничает в postMessage.

Можно пользоваться ими, а можно писать HTML и JSON-RPC руками.

> 🎒 **На пальцах.** Это ровно та же пара, что у любого протокола: одна сторона упаковывает, другая распаковывает. `AppRenderer` избавляет от ручного выставления MIME-строки `text/html;profile=mcp-app`, `AppFrame` — от ручной сверки origin. В этом уроке мы пишем руками именно затем, чтобы понимать, что SDK делает за вас.

## Use It

`code/main.py` расширяет сервер заметок инструментом `visualize_timeline`, который возвращает ресурс `ui://notes/timeline`, плюс обработчиком `resources/read` по этому URI, отдающим маленький, но полноценный HTML-бандл со SVG-шкалой. HTML собирается шаблонами из стандартной библиотеки — никакой системы сборки. postMessage только намечен в JS-комментариях, потому что стандартная библиотека не умеет управлять браузером.

На что смотреть:

- `_meta.ui` в ответе инструмента несёт resourceUri, CSP и permissions.
- HTML рисуется без доступа к сети; все данные вшиты внутрь.
- JS вызывает `host.callTool` через `window.parent.postMessage` (описано, но в этой демке на стандартной библиотеке ничего не делает).

> 🎒 **На пальцах.** Второй пункт — главный урок этого кода: данные вшиты в HTML, поэтому файл открывается двойным щелчком и рисует шкалу даже без интернета. Как только вы захотите подгружать данные запросом, вам придётся расширять `connectSrc` — и вот тут начинается разговор про безопасность. Инлайн данных бесплатно закрывает целый класс проблем.

## Exercises

1. Запустите `code/main.py` и посмотрите на выданный HTML. Откройте этот HTML прямо в браузере, убедитесь, что SVG рисуется. Потом набросайте контракт postMessage, по которому интерфейс вызывал бы `host.callTool("notes_update", ...)`.

2. Ужмите CSP: уберите `'unsafe-inline'` и перейдите на политику скриптов с nonce. Что при этом меняется в коде генерации HTML?

3. Добавьте второй UI-ресурс `ui://notes/editor` с формой для правки заметки на месте. Когда пользователь отправляет форму, iframe вызывает `host.callTool("notes_update", ...)`.

4. Проведите аудит поверхности атаки вашего интерфейса. Где вредоносный сервер может подсунуть свой контент? От чего песочница iframe защищает, а от чего нет?

5. Прочитайте спецификацию SEP-1724 и найдите одну возможность SDK для MCP Apps, которую эта игрушечная реализация не использует. (Подсказка: синхронизация состояния на уровне компонентов.)

> 🎒 **На пальцах.** Второе задание — самое поучительное. Убрали `'unsafe-inline'`, и любой `<script>` без правильного nonce браузер молча выкинет: страница откроется, но SVG останется пустым. Значит генератор HTML теперь обязан на каждый ответ придумывать случайный nonce и вписывать его и в заголовок CSP, и в тег скрипта. Одна строчка политики — два изменения в коде.
