# Капстоун — собираем полную экосистему инструментов

> Phase 13 разобрала каждую деталь по отдельности. Этот капстоун сплетает их в одну систему продакшен-формы: MCP-сервер с инструментами, ресурсами, промптами, задачами и UI, OAuth 2.1 на входе, шлюз с RBAC, клиент к нескольким серверам, вызов A2A-субагента, трассировка OTel в коллектор, детект отравления инструментов в CI и бандл AGENTS.md + SKILL.md. К концу урока вы сможете защитить каждое архитектурное решение.

**Type:** Build
**Languages:** Python (stdlib, end-to-end ecosystem harness)
**Prerequisites:** Phase 13 · 01 through 21
**Time:** ~120 minutes

## Learning Objectives

- Собрать MCP-сервер, который выставляет инструменты, ресурсы, промпты и задачу с приложением `ui://`.
- Поставить перед сервером шлюз OAuth 2.1, который следит за RBAC и за прибитыми хэшами.
- Написать клиент к нескольким серверам, который трассирует всё насквозь атрибутами OTel GenAI.
- Отдать часть работы A2A-субагенту и убедиться, что непрозрачность сохранена.
- Упаковать весь стек через AGENTS.md + SKILL.md, чтобы им могли управлять другие агенты.

## The Problem

Выпускаем систему «изучить и отчитаться»:

- Пользователь просит: «сделай выжимку по трём самым цитируемым статьям 2026 года с arXiv про агентные протоколы».
- Система: ищет на arXiv через MCP; отдаёт пересказ статей специализированному агенту-писателю через A2A; сводит результаты; рисует интерактивный отчёт как ресурс MCP Apps `ui://`; пишет каждый шаг в OTel.

Здесь всплывают все примитивы из Phase 13. Это не игрушка: боевые системы-ассистенты для исследований, вышедшие в 2026-м у Anthropic (продукт Claude Research), OpenAI (GPT на Apps SDK) и у сторонних команд, имеют ровно такую форму.

> 🎒 **На пальцах.** Пересчитайте один запрос пользователя в шаги системы: один поиск, три пересказа, одна сборка, один отчёт — шесть операций, и все шесть надо не потерять, если что-то упадёт на четвёртой. Как заказ в ресторане: гость произнёс одну фразу, а на кухне за ней стоят шесть человек и одна очередь.

## The Concept

### Architecture

```
[user] -> [client] -> [gateway (OAuth 2.1 + RBAC)] -> [research MCP server]
                                                      |
                                                      +- MCP tool: arxiv_search (pure)
                                                      +- MCP resource: notes://recent
                                                      +- MCP prompt: /research_topic
                                                      +- MCP task: generate_report (long)
                                                      +- MCP Apps UI: ui://report/current
                                                      +- A2A call: writer-agent (tasks/send)
                                                      |
                                                      +- OTel GenAI spans
```

> 🎒 **На пальцах.** Проследите путь пальцем: пользователь никогда не разговаривает с MCP-сервером напрямую, между ними всегда шлюз. Именно поэтому у пользователя нет ключей провайдера, а у вас есть единственное место, где можно что-то запретить. Как ресепшн в бизнес-центре: гость не бродит по этажам, ему выдают пропуск.

### Trace hierarchy

```
agent.invoke_agent
 ├── llm.chat (kick off)
 ├── mcp.call -> tools/call arxiv_search
 ├── mcp.call -> resources/read notes://recent
 ├── mcp.call -> prompts/get research_topic
 ├── a2a.tasks/send -> writer-agent
 │    └── task transitions (opaque internals)
 ├── mcp.call -> tools/call generate_report (task-augmented)
 │    └── tasks/status polling
 │    └── tasks/result (completed, returns ui:// resource)
 └── llm.chat (final synthesis)
```

Один trace id. У каждого span правильные атрибуты `gen_ai.*`.

> 🎒 **На пальцах.** Посчитайте по дереву: одиннадцать span на один запрос пользователя. Когда ответ пришёл за 40 секунд, вы по этому дереву увидите, что 34 из них съел `a2a.tasks/send`, а не поиск. Без общего trace id вы бы смотрели одиннадцать несвязанных логов и гадали.

### Security posture

- OAuth 2.1 + PKCE с resource indicator, который прибивает audience к шлюзу.
- Шлюз держит credentials верхнего уровня; пользователь их никогда не видит.
- RBAC: у `alice` есть `research:read` и `research:write`, она может звать все инструменты. У `bob` есть только `research:read`, вызвать `generate_report` он не может.
- Прибитый манифест описаний: любой сервер, у которого поменялись хэши инструментов, отключается.
- Аудит по Rule of Two: ни один инструмент не совмещает недоверенный ввод, чувствительные данные и действие с последствиями.

> 🎒 **На пальцах.** Пять пунктов — это пять независимых замков, и злоумышленнику надо вскрыть все. Возьмите четвёртый: если сервер тихо переписал описание инструмента с «читает заметки» на «читает заметки и отправляет их на почту», хэш изменился и сервер отвалился до первого вызова. Как пломба на счётчике: сама ничего не защищает, но показывает, что кто-то лазил.

### Rendering

Финальная задача `generate_report` возвращает блоки контента плюс ресурс `ui://report/current`. Хост клиента (Claude Desktop и подобные) рисует интерактивный дашборд в песочнице внутри iframe. На дашборде есть отсортированный список статей, число цитирований и кнопка, которая вызывает `host.callTool('summarize_paper', {arxiv_id})` для любой статьи, на которую щёлкнул пользователь.

> 🎒 **На пальцах.** Обратите внимание, что кнопка не делает запрос сама, а просит хост позвать инструмент. Значит, все правила шлюза и RBAC действуют и на клик мышкой — интерфейс не открывает обходную дорожку. Как кнопка вызова лифта: нажимает гость, а решение о доступе на этаж принимает система.

### Packaging

Всё это поставляется так:

```
research-system/
  AGENTS.md                     # project conventions
  skills/
    run-research/
      SKILL.md                  # the top-level workflow
  servers/
    research-mcp/               # the MCP server
      pyproject.toml
      src/
  agents/
    writer/                     # the A2A agent
  gateway/
    config.yaml                 # RBAC + pinned manifest
```

Пользователи разворачивают это через `docker compose up`. Те, кто сидит в Claude Code, Cursor, Codex или opencode, управляют системой, вызывая навык `run-research`.

> 🎒 **На пальцах.** Смотрите на верхние две строки дерева: AGENTS.md и `skills/run-research/SKILL.md` — это единственное, что читает человек или агент, чтобы начать. Остальные четыре папки — реализация, в которую можно не заглядывать. Как инструкция к стиральной машине против её схемы электрики.

## Use It

`code/main.py` сшивает паттерны предыдущих уроков в одно запускаемое демо. Всё на стандартной библиотеке, всё в одном процессе, чтобы можно было прочитать от начала до конца. Он прогоняет полный поток сценария «изучить и отчитаться»: рукопожатие со шлюзом, симуляция OAuth 2.1, объединённый tools/list, generate_report как задача, вызов A2A к писателю, возврат ресурса ui://, отправка span в OTel.

> 🎒 **На пальцах.** Фраза «всё в одном процессе» — главное решение этого демо. В бою тут было бы четыре сетевых сервиса и четыре точки отказа, а здесь всё читается как один файл на Python. Как разрезанный пополам двигатель в музее: ездить нельзя, зато видно каждую деталь.

На что смотреть:

- Один trace id на всех переходах.
- Политика шлюза не даёт второму пользователю писать.
- Жизненный цикл задачи идёт working → completed и возвращает и текст, и контент ui://.
- Внутреннее состояние вызова A2A непрозрачно для оркестратора.
- AGENTS.md и SKILL.md — единственные файлы, которые нужны другому агенту, чтобы воспроизвести процесс.

> 🎒 **На пальцах.** Третий пункт стоит проверить руками. Задача выдаёт два вида контента сразу: текст для модели и `ui://` для человека. Если вы отдадите модели html дашборда, она потратит на него тысячи токенов и ничего не поймёт; разделение здесь не косметика, а экономия.

## Ship It

Этот урок даёт `outputs/skill-ecosystem-blueprint.md`. По продуктовой потребности (исследование, суммаризация, автоматизация) навык выдаёт архитектуру целиком: какие примитивы MCP, какие проверки на шлюзе, какие вызовы A2A, какая телеметрия, какая упаковка.

> 🎒 **На пальцах.** Пять вопросов в конце — это и есть весь капстоун, свёрнутый в анкету. Заполнив её для своей задачи, вы за десять минут получите то, на что в этом уроке ушло два часа. Как типовой проект дома: планировка меняется, а список инженерных систем один и тот же.

## Exercises

1. Запустите `code/main.py`. Обратите внимание на единственный trace id и на то, как вкладываются span. Посчитайте, сколько примитивов из Phase 13 задействует демо.

2. Расширьте демо: добавьте второй бэкенд-MCP-сервер (например, `bibliography`) и убедитесь, что шлюз сливает его инструменты в то же пространство имён.

3. Замените фальшивого A2A-писателя на настоящего, запущенного в отдельном процессе. Используйте стенд из урока 19.

4. Добавьте шаг вычистки PII в шлюзе роутинга между оркестратором и LLM. Убедитесь, что почтовые адреса из запроса пользователя затираются.

5. Напишите AGENTS.md для коллеги, который будет поддерживать эту систему. Он должен читаться меньше пяти минут и давать всё нужное, чтобы управлять капстоуном из Cursor или Codex.

> 🎒 **На пальцах.** Начните со второго задания — оно проверяет самое хрупкое место. Два сервера легко приносят одинаковое имя инструмента, например `search`, и шлюз обязан развести их префиксом, иначе вызов уйдёт не туда. Как два Иванова в одном классе: без фамилии учитель зовёт не того.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Capstone | «Интеграционное демо Phase 13» | Сквозная система, использующая каждый примитив |
| Research and report | «Тот самый сценарий» | Паттерн «найти, пересказать, отрисовать» |
| Ecosystem | «Все части вместе» | Сервер плюс клиент плюс шлюз плюс субагент плюс телеметрия плюс упаковка |
| Trace hierarchy | «Один trace id» | Span каждого перехода делят одну трассу; родитель и ребёнок связаны через span id |
| Gateway-issued token | «Транзитивная авторизация» | Клиент видит только токен шлюза; credentials верхнего уровня держит шлюз |
| Merged namespace | «Все инструменты одним плоским списком» | Слияние нескольких серверов на шлюзе, префикс при коллизии |
| Opacity boundary | «Вызов A2A прячет внутренности» | Рассуждения субагента не видны оркестратору |
| Three-layer stack | «AGENTS.md + SKILL.md + MCP» | Контекст проекта плюс процесс плюс инструменты |
| Defense-in-depth | «Несколько слоёв защиты» | Прибитые хэши, OAuth, RBAC, Rule of Two, журнал аудита |
| Spec compliance matrix | «Что мы выпустили из того, что требует спека» | Чеклист соответствия результатов требованиям версии 2025-11-25 |

> 🎒 **На пальцах.** Две строки таблицы легко спутать. Merged namespace — про удобство: десять инструментов с трёх серверов выглядят одним списком. Opacity boundary — про границу ответственности: субагент отдаёт результат, но не даёт заглянуть, как он его получил. Первое склеивает, второе намеренно разделяет.
