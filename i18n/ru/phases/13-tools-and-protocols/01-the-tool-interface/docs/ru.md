# Интерфейс инструментов — зачем агентам структурированный ввод-вывод

> Языковая модель выдаёт токены. Программа совершает действия. Разрыв между тем и другим закрывает интерфейс инструментов: контракт, который позволяет модели запросить действие, а хосту — выполнить его. Любой стек 2026 года — вызов функций у OpenAI, Anthropic и Gemini, `tools/call` в MCP, части задачи в A2A — это разные способы закодировать один и тот же цикл из четырёх шагов. Этот урок даёт циклу имя и показывает минимальную машинерию, чтобы его запустить.

**Type:** Learn
**Languages:** Python (stdlib, no LLM)
**Prerequisites:** Phase 11 (LLM completion APIs)
**Time:** ~45 minutes

## Learning Objectives

- Объяснить, почему LLM, которая умеет только генерировать текст, сама по себе не может совершить действие в реальном мире.
- Нарисовать цикл вызова инструмента из четырёх шагов (describe → decide → execute → observe) и назвать хозяина каждого шага.
- Описать инструмент как три части: имя, входная схема JSON Schema и детерминированная функция-исполнитель.
- Отличать чистые инструменты от инструментов с побочными эффектами и объяснить, почему это деление важно для безопасности.

## The Problem

LLM выдаёт распределение вероятностей по следующему токену. Это вся её поверхность вывода. Спросите чат-модель «какая сейчас погода в Бангалоре» — она напишет правдоподобное предложение, но не сможет дозвониться до погодного API. Предложение окажется верным либо случайно, либо с опозданием на три дня.

Закрыть этот разрыв — и есть задача интерфейса инструментов. Программа-хост — ваш агентский рантайм, Claude Desktop, ChatGPT, Cursor или самописный скрипт — объявляет модели список вызываемых инструментов. Модель, решив, что нужно действие, выдаёт структурированную полезную нагрузку с именем инструмента и его аргументами. Хост разбирает эту нагрузку, реально запускает инструмент и подаёт результат обратно. Цикл крутится, пока модель не решит, что вызовы больше не нужны.

Первая версия этого контракта вышла в июне 2023 года как параметр «functions» у OpenAI. Anthropic ответила блоками `tool_use` в Claude 2.1. Gemini добавила `functionDeclarations` через несколько месяцев. Сегодня все провайдеры выставляют одну и ту же форму: на входе список инструментов, типизированный JSON Schema, на выходе вызов инструмента в виде JSON. Model Context Protocol (ноябрь 2024) обобщил контракт так, чтобы один реестр инструментов обслуживал любую модель. A2A (апрель 2026, v1.0) надстроил тот же примитив для делегирования от агента к агенту.

Цикл из четырёх шагов — инвариант под всем этим. Всё остальное в фазе 13 — надстройки над ним.

> 🎒 **На пальцах.** Модель — это диспетчер по рации: он умеет только говорить. Он не может сам поднять шлагбаум, но может сказать в эфир «поднять шлагбаум номер 3», и это сделает человек на месте. Интерфейс инструментов — это правила радиообмена: какие команды существуют, в каком порядке слов их произносить и куда возвращать ответ. Обратите внимание на даты: контракт устоялся за два с половиной года, с июня 2023 до апреля 2026, и с тех пор форма не менялась.

## The Concept

### Step one: describe

Хост объявляет каждый инструмент через три поля.

- **Name.** Стабильный машинночитаемый идентификатор. `get_weather`, а не «weather thing».
- **Description.** Краткое описание на человеческом языке, один абзац. «Использовать, когда пользователь спрашивает текущие условия в конкретном городе. Не использовать для исторических данных.»
- **Input schema.** Объект JSON Schema (draft 2020-12), описывающий аргументы инструмента.

Модель получает этот список. Современные провайдеры сериализуют объявления в системный промпт по своему внутреннему шаблону, так что вам как вызывающей стороне достаётся только структурированная форма.

> 🎒 **На пальцах.** Три поля — как карточка блюда в меню: название, описание «когда это заказывают» и список того, что нужно уточнить у гостя. Название `get_weather` — это артикул, по нему заказ находят однозначно; «weather thing» — это как «ну то, вкусненькое». Заметьте: строка `Do not use for historical data` — тоже часть описания, отрицания в брифе работают ничуть не хуже утверждений.

### Step two: decide

Получив сообщение пользователя и список доступных инструментов, модель выбирает одно из трёх поведений.

1. **Answer directly** — ответить текстом. Никакого вызова инструмента.
2. **Call one or more tools** — вызвать один или несколько инструментов. Модель выдаёт структурированные объекты вызова. При `parallel_tool_calls: true` (по умолчанию у OpenAI и Gemini, по желанию у Anthropic) модель может выдать несколько вызовов за один ход.
3. **Refuse** — отказаться. Строгий режим структурированных ответов может выдать типизированный блок `refusal` вместо вызова.

В полезной нагрузке вызова инструмента три устойчивых поля: `id` вызова, `name` инструмента и объект `arguments` в JSON. Идентификатор нужен, чтобы хост мог сопоставить пришедший позже результат с конкретным вызовом, — это важно, когда параллельные вызовы возвращаются не в том порядке.

> 🎒 **На пальцах.** Три варианта поведения — это как официант с блокнотом: ответить сам («вода бесплатно»), унести заказ на кухню или сказать «этого мы не готовим». Поле `id` — номер заказа на чеке: если вы отправили два вызова `get_weather` подряд и ответы вернулись перепутанными, только по `id` понятно, где Токио, а где Лондон. Без него на двух параллельных вызовах вы гарантированно перепутаете результаты.

### Step three: execute

Хост получает вызов, проверяет аргументы по объявленной схеме и запускает исполнитель. Невалидные аргументы означают, что модель выдумала поле или использовала неверный тип — очень частый режим отказа у слабых моделей. Продовые хосты делают на невалидных аргументах одно из трёх: падают сразу и показывают ошибку модели, ремонтируют JSON ограниченным парсером или повторяют запрос к модели, вложив ошибку валидации в промпт.

Сам исполнитель — обычный код. Python, TypeScript, shell-команда, запрос к базе. Он выдаёт результат: обычно строку, но допустим любой JSON или структурированный блок контента (текст, изображение или ссылка на ресурс в MCP). Результат обязан быть сериализуемым.

> 🎒 **На пальцах.** Валидация — это турникет перед исполнителем: аргумент `city: 42` не проходит, потому что в схеме заявлена строка. Три стратегии из абзаца выше — это «не пустить и объяснить», «поправить билет за пассажира» и «отправить обратно к кассе за новым». В проде чаще всего первое: ошибку возвращают модели, и она на следующем ходу присылает `city: "Bengaluru"` сама.

### Step four: observe

Хост добавляет результат инструмента в диалог (как сообщение с ролью `tool` и совпадающим `id`) и снова вызывает модель. Теперь у модели вывод инструмента лежит в контексте, и она может выдать финальный ответ или запросить новые вызовы. Так продолжается, пока модель не перестанет выдавать вызовы или пока хост не упрётся в предохранитель по числу итераций.

> 🎒 **На пальцах.** Шаг observe — это момент, когда вы даёте начитанному человеку записку с цифрой 24 °C, и он наконец отвечает по делу. Ключевая деталь: модель не «помнит» результат — он лежит в контексте как обычное сообщение, и на каждом ходу вы отправляете всю переписку заново. Убрали сообщение с ролью `tool` из истории — модель снова не знает погоду.

### The trust split

Инструменты бывают двух видов, и разница важна для безопасности.

- **Pure.** Только чтение, детерминированные, без побочных эффектов. `get_weather`, `search_docs`, `get_current_time`. Такие можно вызывать спекулятивно.
- **Consequential.** Меняют состояние, тратят деньги, трогают данные пользователя. `send_email`, `delete_file`, `execute_trade`. Такие обязаны быть под замком.

«Правило двух» от Meta (2026) для безопасности агентов гласит: один ход может совмещать максимум два из трёх — недоверенный ввод, чувствительные данные, необратимое действие. Интерфейс инструментов — то место, где вы это правило применяете: отклоняете вызовы, требуете подтверждения пользователя или повышаете уровень доступа. Полная глава про безопасность — Phase 13 · 15, политики прав на уровне агента — Phase 14 · 09.

> 🎒 **На пальцах.** Разница как между «посмотреть баланс» и «перевести деньги»: первое можно нажимать сто раз без последствий, второе — один раз и навсегда. Правило двух считается буквально: письмо от незнакомца (недоверенный ввод) + доступ к вашей почте (чувствительные данные) + право отправлять письма (необратимое действие) — это три из трёх, значит один из пунктов надо убрать. Уберите третий — и худшее, что случится, это прочитанная зря почта.

### Where the loop lives

| Context | Who describes | Who decides | Who executes |
|---------|---------------|-------------|--------------|
| Single-turn function calling (OpenAI/Anthropic/Gemini) | Разработчик приложения | LLM | Разработчик приложения |
| MCP | MCP-сервер | LLM через MCP-клиент | MCP-сервер |
| A2A | Публикатор Agent Card | Вызывающий агент | Вызываемый агент |
| Web browser (function-calling agent) | Расширение браузера / WebMCP | LLM | Рантайм браузера |

Везде те же четыре шага. Меняются названия колонок, структура — нет.

> 🎒 **На пальцах.** Четыре строки таблицы — это четыре разных мира, и во всех трёх колонках «кто» меняется, а глаголы остаются те же. Во встроенном вызове функций описываете и исполняете вы сами; в MCP обе эти роли уезжают на сервер, и вы остаётесь только с решением модели. Именно поэтому один MCP-сервер погоды работает и в Claude Desktop, и в Cursor: он взял на себя два столбца из трёх.

### Why not just prompt the model to emit JSON?

«Попроси модель ответить в JSON» — это паттерн до эпохи вызова функций. На передовых моделях он ломается примерно в 5-15 % случаев, а на маленьких — намного чаще. Типичные поломки: пропущенные фигурные скобки, лишние запятые, выдуманные поля, неверные типы. Дальше нужен проход ремонта JSON, повтор запроса или декодер с ограничениями.

Родной вызов функций лучше по трём причинам. Первая: провайдер обучает модель на точной форме вызова целиком, поэтому доля валидного JSON поднимается до 98-99 % в строгом режиме. Вторая: полезная нагрузка вызова лежит в отдельном слоте протокола, а не внутри свободного текста, — поэтому вызов инструмента никогда не протечёт в видимый пользователю ответ. Третья: провайдеры принудительно соблюдают схему через ограниченное декодирование (strict mode у OpenAI, `tool_use` у Anthropic, `responseSchema` у Gemini). Такой вывод гарантированно проходит валидацию.

Phase 13 · 02 разбирает три провайдерских API рядом друг с другом. Phase 13 · 04 глубоко копает структурированные ответы.

> 🎒 **На пальцах.** 5-15 % отказов звучит терпимо, пока не посчитать: на 1000 запросов это от 50 до 150 упавших ответов, каждый со своим повтором и лишними токенами. Строгий режим с 98-99 % оставляет 10-20 поломок на те же 1000 — в семь раз меньше работы по ремонту. Плюс вторая причина стоит отдельного внимания: без отдельного слота протокола ваш пользователь однажды увидит в чате сырой `{"name": "delete_file"...}`.

### Circuit breakers

Цикл завершается, когда модель перестаёт выдавать вызовы или когда хост упирается в максимальное число ходов. Продовые хосты ставят этот предел между 5 и 20 ходами. За этой границей вы почти наверняка в цикле, из которого модель не выйдет сама. У Claude Code по умолчанию 20, у OpenAI Assistants — 10, у режима агента в Cursor — 25.

Альтернатива — цикл без границ — раз в полгода всплывает в постмортемах «агент за ночь потратил 400 долларов на вызовы API». Не выпускайте в прод без предела.

Phase 14 · 12 подробно разбирает восстановление после ошибок и самолечение; Phase 17 — продовые ограничения по частоте запросов.

> 🎒 **На пальцах.** Предохранитель — это лимит на карте у подростка: не запрещает покупать, но не даёт уйти в минус на 400 долларов за ночь. Три реальных значения из абзаца выше — 20, 10 и 25 — показывают порядок величин: если ваша задача не решается за 25 ходов, дело не в лимите, а в том, что модель ходит по кругу. Начните с 10 и поднимайте по замерам, а не наоборот.

## Use It

`code/main.py` крутит цикл из четырёх шагов без всякой LLM. Фальшивая функция-«решатель» имитирует модель, сопоставляя сообщение пользователя с шаблонами; исполнитель, валидатор схемы и обвязка шага observe — настоящие. Запустите и посмотрите всю хореографию запросов и ответов с печатью промежуточного состояния, а потом, в одном из следующих уроков, замените фальшивый решатель на реального провайдера.

Куда смотреть:

- Реестр инструментов хранит по три поля на инструмент: имя, описание, схему и ссылку на исполнитель.
- Валидатор — минимальное подмножество JSON Schema (типы, required, enum, min/max), написанное только на stdlib. Более полный будет в Phase 13 · 04.
- Цикл ограничен пятью итерациями. Продовым агентам нужен ровно такой предохранитель.

> 🎒 **На пальцах.** Замена реальной модели на функцию с `if "weather" in message` — это тренировка на симуляторе: рулевое, педали и приборы настоящие, а вместо трассы — экран. Так вы отлаживаете четыре шага, не платя ни за один токен и не ловя случайность LLM. Обратите внимание на несоответствие: в тексте сказано «три поля», а перечислено четыре — имя, описание, схема и исполнитель; исполнитель обычно не считают, потому что модель его не видит.

## Ship It

Этот урок производит `outputs/skill-tool-interface-reviewer.md`. Получив черновик определения инструмента (имя + описание + схема + набросок исполнителя), навык проверяет его на пригодность для цикла: стабильно ли машинночитаемое имя, является ли описание полноценным брифом по применению, корректно ли схема использует JSON Schema 2020-12 и явно ли проведена классификация pure против consequential.

> 🎒 **На пальцах.** Это как чек-лист техосмотра для инструмента: четыре пункта, каждый отвечает на вопрос «что сломается в проде, если этого нет». Забыли классификацию pure/consequential — и `delete_file` однажды вызовется спекулятивно, без подтверждения. Прогоните через навык хотя бы два своих инструмента: почти всегда описание оказывается слишком коротким.

## Exercises

1. Добавьте в `code/main.py` четвёртый инструмент `get_stock_price(ticker)`. Напишите его описание так: «Use when the user asks for a current stock price by ticker. Do not use for historical prices or market summaries.» Запустите обвязку и убедитесь, что фальшивый решатель направляет запросы с упоминанием тикеров в новый инструмент.

2. Сломайте валидатор схемы. Передайте вызов, в объекте `arguments` которого нет обязательного поля, и убедитесь, что хост отклоняет его до исполнения. Затем передайте вызов с лишним неизвестным полем. Решите: хост должен отклонить или проигнорировать? Обоснуйте выбор через аргумент о безопасности.

3. Классифицируйте каждый инструмент в обвязке как pure или consequential. Добавьте флаг `consequential: true` в те записи реестра, которым он нужен, и измените цикл так, чтобы он печатал строку «would confirm with user» всякий раз, когда выбран необратимый инструмент. Это и есть форма подтверждающего шлюза, который нужен любому продовому хосту.

4. Нарисуйте цикл из четырёх шагов на бумаге и заполните таблицу с колонками провайдеров для вашего любимого клиента (Claude Desktop, Cursor, ChatGPT или самописный стек). Сверьтесь с MCP-вариантом из Phase 13 · 06.

5. Прочитайте руководство OpenAI по вызову функций от начала до конца. Найдите одно поле, которое есть в запросе, но отсутствует в цикле из четырёх шагов в том виде, как он изложен здесь. Объясните, что оно добавляет и почему оно удобно, но не обязательно.

> 🎒 **На пальцах.** Начните с третьего задания — оно самое полезное за самое короткое время. Из трёх инструментов в обвязке необратимых, скорее всего, ноль, и это уже урок: чистые инструменты — норма, а необратимые — исключение, которое надо помечать вручную. Второе задание тоже стоит сделать: разница между «отклонить лишнее поле» и «проигнорировать» — это разница между хостом, который поймает опечатку модели, и хостом, который её молча проглотит.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Tool | "A thing the model can call" | Тройка: имя + вход, типизированный JSON Schema + функция-исполнитель |
| Function calling | "Native tool use" | Поддержка на уровне API провайдера: модель выдаёт структурированные вызовы инструментов вместо прозы |
| Tool call | "The model's request to act" | Полезная нагрузка JSON с полями `id`, `name`, `arguments`, которую выдаёт модель |
| Tool result | "What the tool returned" | Вывод исполнителя, завёрнутый в сообщение с ролью `tool` и совпадающим id |
| Parallel tool calls | "Many calls at once" | Несколько объектов вызова в одном ходу модели: независимые и упорядочиваемые по id |
| Strict mode | "Guaranteed JSON" | Ограниченное декодирование, которое заставляет вывод модели проходить валидацию по объявленной схеме |
| Pure tool | "Read-only tool" | Без побочных эффектов, безопасно вызывать повторно |
| Consequential tool | "Action tool" | Меняет внешнее состояние, требует шлюза, аудита или подтверждения пользователя |
| Four-step loop | "The tool-call cycle" | Четыре шага: describe → decide → execute → observe |
| Host | "Agent runtime" | Программа, которая держит реестр инструментов, вызывает модель и запускает исполнитель |
