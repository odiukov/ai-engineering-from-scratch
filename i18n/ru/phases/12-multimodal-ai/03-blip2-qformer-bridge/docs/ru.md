# От CLIP к BLIP-2 — Q-Former как мост между модальностями

> CLIP выравнивает картинку и текст, но не умеет писать подписи, отвечать на вопросы и вести диалог. BLIP-2 (Salesforce, 2023) решил это маленьким обучаемым мостом: 32 обучаемых запроса через cross-attention смотрят на признаки замороженного ViT, а затем встают прямо во входной поток замороженной LLM. 188M параметров моста соединили 11B LLM с ViT-g/14. Любой adapter-based VLM вплоть до 2026 года — MiniGPT-4, InstructBLIP, родня LLaVA — его потомок. В этом уроке мы разбираем архитектуру Q-Former, объясняем его двухэтапное обучение и собираем игрушечную версию, которая подаёт визуальные tokens в замороженный текстовый декодер.

**Type:** Build
**Languages:** Python (stdlib, cross-attention + learnable-query demo)
**Prerequisites:** Phase 12 · 02 (CLIP), Phase 7 (Transformers)
**Time:** ~180 minutes

## Learning Objectives

- Объяснить, почему обучаемое горлышко между замороженным энкодером изображений и замороженной LLM выигрывает у end-to-end дообучения по цене и стабильности.
- Реализовать блок cross-attention, где фиксированный набор обучаемых запросов смотрит на внешние признаки изображения.
- Пройти двухэтапный претрейн BLIP-2: сначала представления (ITC + ITM + ITG), потом генерация (LM loss с замороженным декодером).
- Сравнить Q-Former с более простым MLP-проектором из LLaVA и обосновать, когда какой вариант побеждает.

> 🎒 **На пальцах.** Держите в голове три цифры на весь урок: 256 патчей на входе, 32 запроса на выходе, 188M обучаемых параметров при 8B общих. Сжатие в 8 раз по tokens и 2.4% обучаемых весов — это и есть вся идея BLIP-2.

## The Problem

У вас есть замороженный ViT, который выдаёт 256 patch-tokens размерности 1408 на картинку. И замороженная 7B LLM, которая ждёт эмбеддинги tokens размерности 4096. Очевидный мост — линейный слой из 1408 в 4096 — работает, но подача всех 256 patch-tokens в контекст LLM стоит 256 лишних tokens на изображение. На батче из 32 картинок это 8192 tokens, съеденных одной только визуальной модальностью.

Вопрос BLIP-2: можно ли сжать 256-токенное представление картинки в куда меньшее число tokens (скажем, 32), сохранив достаточно информации, чтобы LLM подписывала картинку, отвечала на вопросы и рассуждала о ней? И можно ли обучить этот мост, не трогая замороженные бэкбоны, чтобы цена обучения равнялась цене одних только параметров моста?

Ответ: Q-Former. 32 обучаемых вектора-«запроса», которые через cross-attention смотрят на patch-tokens ViT и выдают 32-токенную выжимку изображения для LLM. Итого 188M параметров. Обучается на contrastive-, matching- и generative-задачах ещё до того, как в дело вступит LLM.

> 🎒 **На пальцах.** Это как пересказать 256-страничную книгу на 32 карточках, чтобы читатель понял сюжет. Считаем экономию: 256 tokens против 32 — на батче из 32 картинок 8192 против 1024, разница в 7168 tokens контекста, которые остались свободны под текст.

## The Concept

### Learnable queries

Главный трюк Q-Former: вместо того чтобы текстовые tokens LLM смотрели на патчи изображения, вводим новый набор из 32 обучаемых векторов-запросов `Q` и даём смотреть на патчи *им*. Запросы — это параметры модели: они выучиваются при обучении, и одни и те же 32 запроса используются для любой картинки.

После cross-attention каждый запрос держит сжатую выжимку изображения — «опиши главный объект», «опиши фон», «посчитай объекты» и так далее. Буквально по семантическим ярлыкам запросы не специализируются — они выучивают то кодирование, которое роняет итоговые лоссы.

> 🎒 **На пальцах.** Запросы — это 32 постоянных вопроса, которые модель задаёт каждой картинке; не картинка выбирает вопросы, а модель один раз выучила их на все случаи. Обратите внимание: параметров тут всего 32 × 768 ≈ 25 тысяч чисел, а работы они делают на весь мост.

### Architecture

Q-Former — маленький трансформер (12 слоёв, ~100M параметров) с двумя путями:

1. Путь запросов: 32 вектора-запроса проходят self-attention (между собой), затем cross-attention по patch-tokens замороженного ViT, затем FFN.
2. Путь текста: текстовый энкодер в стиле BERT делит веса self-attention и FFN с путём запросов. Cross-attention для текстового пути отключён.

Во время обучения работают оба пути. Запросы и текст взаимодействуют через общий self-attention — значит, запросы могут опираться на текст в задачах, где это нужно (ITM, ITG). Во время инференса, когда результат передаётся VLM, идут только запросы, и на выходе получается 32 визуальных tokens.

> 🎒 **На пальцах.** Два пути — как один и тот же кабинет, куда по очереди заходят два посетителя: мебель (веса self-attention и FFN) общая, но окно на улицу (cross-attention) открывают только запросам. На инференсе текстовый посетитель вообще не приходит, и из 12 слоёв выходят ровно 32 вектора.

### Two-stage training

BLIP-2 претренится в два этапа:

Этап 1: обучение представлений (без LLM). Три лосса:
- ITC (image-text contrastive): contrastive в стиле CLIP между спуленными query-tokens и текстовым CLS-token.
- ITM (image-text matching): бинарный классификатор — эта пара «картинка — текст» совпадает? С добычей hard-negative.
- ITG (image-grounded text generation): причинная LM-голова по тексту с обусловливанием на запросы. Заставляет запросы кодировать то, из чего можно сгенерировать текст.

Обучается только Q-Former. ViT заморожен. LLM не участвует.

Этап 2: обучение генерации. Присоединяем замороженную LLM (OPT-2.7B, Flan-T5-XL и тому подобное). Проецируем 32 выхода запросов в размерность эмбеддингов LLM маленьким линейным слоем. Ставим их перед текстовым промптом. Обучаем только эту линейную проекцию и Q-Former на LM loss по склеенной последовательности «промпт + картинка + подпись».

После этапа 2 Q-Former вместе с проекцией и есть полный визуальный адаптер. На инференсе: картинка → ViT → Q-Former → линейная проекция → приписывается перед текстом → замороженная LLM выдаёт ответ.

> 🎒 **На пальцах.** Порядок как у переводчика на новой работе: сначала выучить предметную область (этап 1, три лосса без начальника), потом научиться говорить так, чтобы понимал именно этот начальник (этап 2, LM loss с конкретной LLM). Из-за этого при смене LLM переделывать нужно только этап 2 — а это одна линейная матрица 768 × 4096.

### Parameter economics

BLIP-2 с ViT-g/14 (1.1B, заморожен) + OPT-6.7B (6.7B, заморожен) + Q-Former (188M, обучается) = 8B всего, 188M обучаемых. Один Q-Former — это ~2.4% параметров всей сборки. Цена обучения соответствующая: дни на горстке A100 против недель для end-to-end.

Качество: BLIP-2 сравнивается с Flamingo-80B на zero-shot VQA или обходит его, будучи в 50 раз меньше. Мост работает.

> 🎒 **На пальцах.** 2.4% — это как перекрасить только дверные ручки, а дом выглядит новым. Считаем: 188M из 8B, при этом на zero-shot VQA результат не хуже модели в 50 раз крупнее — 80B против 8B.

### InstructBLIP and the instruction-aware Q-Former

InstructBLIP (2023) добавляет Q-Former ещё один вход: сам текст инструкции. На шаге cross-attention запросы теперь видят и патчи изображения, и инструкцию. Запросы могут специализироваться под инструкцию («посчитай машины», «опиши настроение») вместо того, чтобы выучивать одну фиксированную выжимку. Отсюда прирост на бенчмарках с отложенными задачами.

> 🎒 **На пальцах.** Разница как между «сфотографируй комнату» и «сфотографируй комнату, я ищу свои ключи»: во втором случае кадр будет другим. Те же 32 запроса, но их содержимое теперь зависит от вопроса, а не одинаково для всех вопросов.

### MiniGPT-4 and the projector-only approach

MiniGPT-4 оставил Q-Former, но обучал только выходную линейную проекцию, заморозив всё остальное. Дёшево, только платите качеством — запросы там чужие, от BLIP-2, а не ваши. Годится для быстрых итераций, но это не лучшая архитектура.

> 🎒 **На пальцах.** Это как взять чужой конспект и переписать только заголовки: быстро, но мысли внутри остались чужими. Обучаемых параметров тут остаётся один слой на несколько миллионов вместо 188M — отсюда и скорость, и потолок по качеству.

### Why LLaVA went simpler

LLaVA (2023, урок 12.05) заменила Q-Former обычным двухслойным MLP, который проецирует каждый patch-token ViT в пространство LLM — 576 tokens на картинку при сетке 24x24, и все они уходят в LLM. Сжатие хуже, зато LLM смотрит на сырые патчи. Тогда это было спорным решением; к концу 2023 года оно стало доминирующим, потому что данные визуальных инструкций (LLaVA-Instruct-150k) доказали: MLP можно обучить так, что сигнала сохраняется достаточно. Плата за это: контекст LLaVA забивается быстрее, но зато подход естественно масштабируется на много картинок и видео.

К 2026 году поле разделилось: Q-Former выживает там, где важен бюджет tokens (длинное видео, много картинок); MLP-проектор доминирует там, где в приоритете качество на token.

> 🎒 **На пальцах.** 576 против 32 — это 18-кратная разница в цене картинки для контекста. При контексте 128k восемь кадров LLaVA съедают 4608 tokens, а восемь кадров BLIP-2 — всего 256; зато у LLaVA каждый патч виден LLM целиком.

### Gated cross-attention: Flamingo, the ancestor

Flamingo (урок 12.04) появился раньше BLIP-2 и использовал ту же идею cross-attention, но на каждом слое замороженной LLM, а не одним мостом. BLIP-2 показал, что можно сжать всё до входного слоя и всё равно работать. Gemini и Idefics совмещают оба подхода: перемешанные входные tokens плюс опциональный gated cross-attention для few-shot в контексте.

> 🎒 **На пальцах.** Flamingo подмешивает картинку на каждом этаже здания, BLIP-2 — только в вестибюле на входе. Второе дешевле: у Flamingo обучаемых весов около 10B, у BLIP-2 — 188M, то есть в 50 раз меньше.

### The 2026 descendants

- Q-Former: BLIP-2, InstructBLIP, MiniGPT-4 и большинство видео-языковых моделей — ради бюджета tokens.
- Perceiver resampler: вариант Flamingo (урок 12.04); семейство Idefics, Eagle, OmniMAE.
- MLP-проектор: LLaVA, LLaVA-NeXT, LLaVA-OneVision, Cambrian-1.
- Attention pool: VILA, PaliGemma.

Все четыре варианта рабочие. Решающий вопрос один: вы ограничены бюджетом tokens или качеством на token?

> 🎒 **На пальцах.** Четыре потомка — это четыре ответа на один вопрос «сколько tokens отдать картинке». Q-Former и Perceiver говорят «мало и фиксированно» (32 и 64), MLP говорит «все» (576), attention pool — «усредним по сетке».

## Use It

`code/main.py` собирает cross-attention в стиле Q-Former на одном stdlib:

1. Имитируем 256 patch-tokens изображения (размерность 128).
2. Создаём 32 обучаемых запроса (размерность 128).
3. Считаем scaled-dot-product cross-attention (Q из запросов, K/V из патчей).
4. Проецируем в размерность LLM (512) линейным слоем.
5. Выдаём 32 визуальных tokens, готовых для LLM.

Вся математика на чистом Python (вложенные циклы по векторам). Игрушка, но формы правильные. Матрица весов внимания печатается, так что видно, из каких патчей тянул каждый запрос.

> 🎒 **На пальцах.** Матрица внимания тут ровно 32 × 256 = 8192 числа, и каждая из 32 строк суммируется в 1 после softmax. Смотрите на строку как на рецепт: «этот запрос взял 30% от патча 17, 12% от патча 200 и по чуть-чуть от остальных».

## Ship It

Этот урок производит `outputs/skill-modality-bridge-picker.md`. По целевой конфигурации VLM (число tokens энкодера изображений, бюджет контекста LLM, ограничения деплоя, целевое качество) он рекомендует Q-Former, MLP или Perceiver resampler с коротким обоснованием и оценкой числа параметров для каждого моста.

> 🎒 **На пальцах.** По сути это калькулятор с одним главным входом — сколько tokens вы готовы отдать одной картинке. Ответ «32» ведёт к Q-Former, ответ «576» — к MLP, а ответ «зависит от разрешения» — к Perceiver resampler.

3. Сравните число параметров: Q-Former (12 слоёв, скрытая размерность 768) против двухслойного MLP-проектора (1408 → 4096, два слоя). При каком масштабе LLM 188M-мостик Q-Former отбивается эффективностью обучения?

4. Прочитайте раздел 3.2 статьи BLIP-2 (arXiv:2301.12597) о том, как инициализируется Q-Former. Объясните, почему инициализация из BERT-base (а не случайная) ускоряет сходимость.

5. Для 10-минутного видео при 1 FPS, прореженного до 60 кадров, посчитайте цену в tokens на кадр для (Q-Former → 32 tokens/кадр) и для (MLP-проектор → 576 tokens/кадр). Что влезет в контекстное окно LLM на 128k tokens?

> 🎒 **На пальцах.** Задание 5 считается в одну строку: 60 × 32 = 1920 tokens против 60 × 576 = 34 560 tokens. Оба влезают в 128k, но у MLP на видео уходит четверть окна, а у Q-Former — полтора процента; на часовом видео MLP уже не влезет вовсе.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Q-Former | «Трансформер запросов» | Маленький трансформер с 32 обучаемыми векторами-запросами, которые через cross-attention смотрят на признаки замороженного ViT |
| Learnable queries | «Soft prompt для зрения» | Фиксированный набор параметров, играющий роль стороны query в cross-attention; выучивается для каждой модели и общий для всех входов |
| Cross-attention | «Q отсюда, K/V оттуда» | Внимание, где query, key и value берутся из разных источников; так запросы тянут информацию из патчей ViT |
| ITC | «Image-text contrastive» | Лосс в стиле CLIP между спуленными запросами Q-Former и текстовым CLS |
| ITM | «Image-text matching» | Бинарный классификатор на парах с добытыми hard-negative; заставляет запросы различать тонкие несовпадения |
| ITG | «Image-grounded text generation» | Причинный LM-лосс, где текст генерируется с обусловливанием на запросы; заставляет запросы кодировать декодируемое в текст содержание |
| Two-stage pretraining | «Сначала представления, потом генерация» | Этап 1 обучает один Q-Former (ITC/ITM/ITG); этап 2 присоединяет замороженную LLM и обучает только проекцию плюс Q-Former |
| Frozen backbone | «Не дообучать» | Веса энкодера изображений и LLM зафиксированы; обучается только мост |
| Projection head | «Линейный слой в размерность LLM» | Последний линейный слой, переводящий выход Q-Former в размерность эмбеддингов LLM |
| Perceiver resampler | «Версия Flamingo» | Похожий cross-attention с обучаемыми запросами, применяемый Flamingo на каждом слое, а не одним мостом |
