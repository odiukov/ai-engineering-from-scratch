# Собираем голосового ассистента — капстоун шестой фазы

> Всё из уроков 01-11, сшитое в одну систему. Соберите голосового ассистента, который слушает, думает и отвечает голосом. В 2026 году это уже инженерная задача, а не исследовательская — но именно детали интеграции решают, поедет оно в продакшен или нет.

**Type:** Build
**Languages:** Python
**Prerequisites:** Phase 6 · 04, 05, 06, 07, 11; Phase 11 · 09 (Function Calling); Phase 14 · 01 (Agent Loop)
**Time:** ~120 minutes

## The Problem

Собрать сквозного ассистента:

1. Захватывает звук с микрофона (16 кГц, моно).
2. Определяет начало и конец речи пользователя.
3. Транскрибирует потоково.
4. Отдаёт транскрипт в LLM, которая умеет вызывать инструменты (таймер, погода, календарь).
5. Стримит текст от LLM в TTS.
6. Проигрывает аудио пользователю.
7. Замолкает, если пользователь перебил на середине ответа.

Цель по latency: первый байт аудио от TTS не позже чем через 800 мс после того, как пользователь договорил, — и это на CPU ноутбука. Цель по качеству: ни одного потерянного слова, никаких галлюцинаций на тишине, никаких утечек клонированного голоса, ни одного успешного prompt injection.

> 🎒 **На пальцах.** Семь пунктов — это семь мест, где всё может сломаться. Бюджет в 800 мс делится между ними: примерно 500 мс съедает hangover у VAD (ждём, точно ли человек договорил), и на STT, LLM и первый кусок TTS остаётся всего около 300 мс. Поэтому дальше в уроке всё будет про то, как не ждать целиком, а начинать следующий этап на полуслове.

## The Concept

![Voice assistant pipeline: mic → VAD → STT → LLM+tools → TTS → speaker](../assets/voice-assistant.svg)

### The seven components

1. **Audio capture.** Микрофон → 16 кГц моно → чанки по 20 мс. Обычно `sounddevice` в Python или нативные AudioUnit/ALSA/WASAPI в продакшене.
2. **VAD (Lesson 11).** Silero VAD с порогом старта 0.3 (собственный дефолт Silero — 0.5; порог 0.3 покупает вам первое слово ценой нескольких ложных стартов — см. failure mode 1), минимальная речь 250 мс, hangover тишины 500 мс. Даёт сигналы «начало» и «конец».
3. **Streaming STT (Lesson 4-5).** Whisper-streaming, Parakeet-TDT или Deepgram Nova-3 (API). Частичные и финальные транскрипты.
4. **LLM with tool calling.** GPT-4o / Claude 3.5 / Gemini 2.5 Flash. JSON-схема для инструментов. Токены стримом.
5. **Streaming TTS (Lesson 7).** Kokoro-82M (самая быстрая открытая) или Cartesia Sonic (коммерческая). Запускать TTS после первых 20 токенов от LLM.
6. **Playback.** Вывод в динамик; для узких каналов кодируйте в opus.
7. **Interruption handler.** Если VAD сработал, пока играет TTS, — остановить воспроизведение, отменить LLM, перезапустить STT.

> 🎒 **На пальцах.** Это конвейер, как на кухне ресторана: официант принимает заказ (микрофон), повар готовит (LLM), раздача отдаёт блюдо (TTS). Обратите внимание на пункт 5: TTS стартует уже после 20 токенов, а не после всего ответа. При типичной скорости LLM в 50 токенов в секунду это 20 / 50 = 0.4 с — вот откуда берётся шанс уложиться в 800 мс.

### The three failure modes you will hit

1. **First-word clip.** VAD включился на такт позже. «Эй» пользователя пропало. Ставьте порог старта 0.3, а не 0.5.
2. **Mid-response interrupt confusion.** LLM продолжает генерировать после того, как её перебили; ассистент говорит поверх пользователя. Свяжите VAD → отмена LLM.
3. **Silence hallucination.** Whisper выдаёт «Спасибо за просмотр» на тишине во время прогрева. Всегда гейтите вход через VAD.

> 🎒 **На пальцах.** Все три беды — про время, а не про качество моделей. Первая: слово «эй» длится около 200 мс, то есть 10 чанков по 20 мс, и если VAD раздумывает 5 чанков, половина слова уже потеряна. Третья особенно обидна: модель обучалась на ютюб-субтитрах и на тишине честно вспоминает самую частую фразу из титров.

## Build It

### Step 1: mic capture with chunking (pseudocode)

```python
import sounddevice as sd

def mic_stream(chunk_ms=20, sr=16000):
    q = queue.Queue()
    def cb(indata, frames, time, status):
        q.put(indata.copy().flatten())
    with sd.InputStream(channels=1, samplerate=sr, blocksize=int(sr * chunk_ms/1000), callback=cb):
        while True:
            yield q.get()
```

> 🎒 **На пальцах.** `blocksize=int(sr * chunk_ms/1000)` — это 16000 * 20 / 1000 = 320 отсчётов в одном чанке. Колбэк `cb` вызывается драйвером звука в отдельном потоке и просто кидает копию данных в очередь; сам генератор потом достаёт их через `q.get()`. Очередь тут не для красоты: если делать обработку прямо в колбэке, звук начнёт заикаться.

### Step 2: VAD-gated turn capture

```python
def capture_turn(stream, vad, chunk_ms=20, pre_roll_ms=300, silence_ms=500):
    pre = collections.deque(maxlen=max(1, pre_roll_ms // chunk_ms))
    buf, triggered, silent = [], False, 0
    for chunk in stream:
        if vad(chunk):
            if not triggered:
                buf = list(pre)      # pre-roll only — `chunk` is appended below
                triggered = True
            buf.append(chunk)
            silent = 0
        elif triggered:
            buf.append(chunk)
            silent += chunk_ms
            if silent >= silence_ms:
                return np.concatenate(buf)
        else:
            pre.append(chunk)        # rolling pre-roll while nobody is talking
    # stream ended before the hangover elapsed — return what we have, not None
    return np.concatenate(buf) if triggered else None
```

Три детали, которые кусаются на практике: длину pre-roll-очереди надо считать от *того же* `chunk_ms`, с которым работает микрофон (иначе микрофон на 10 мс молча урежет ваш pre-roll вдвое), триггерный кадр нельзя учитывать дважды (он попадает в `buf` либо через `pre`, либо через `append`, но никогда через оба), и `mic_stream` отдаёт float-массивы — их надо склеивать через `np.concatenate`, а не через `b"".join`.

> 🎒 **На пальцах.** `pre` — это кольцевой буфер на `300 // 20 = 15` чанков, то есть 300 мс звука «из прошлого». Когда VAD наконец говорит «речь», мы берём весь этот буфер целиком — так спасается обрезанное первое слово. Заметьте, что `pre.append(chunk)` живёт в ветке `else`, то есть буфер набивается только пока никто не говорит: если бы он обновлялся на каждом кадре, триггерный кадр попал бы в `buf` дважды — один раз внутри `list(pre)` и второй раз через `buf.append(chunk)`, и в записи появился бы продублированный 20-мс фрагмент. Счётчик `silent` растёт на `chunk_ms` за кадр и на 25-м тихом кадре подряд достигает 500 мс: turn закончен. А последняя строка нужна для случая, когда поток кончился раньше hangover'а — без неё функция вернула бы `None`, и уже записанная реплика молча потерялась бы.

### Step 3: streaming STT → LLM → TTS

```python
async def turn(audio):
    transcript = await stt.transcribe(audio)
    async for token in llm.stream(transcript):
        async for audio in tts.stream(token):
            await speaker.play(audio)
```

> 🎒 **На пальцах.** Обратите внимание на два вложенных `async for` — это и есть суть стриминга. Мы не ждём весь ответ LLM, чтобы начать синтез, и не ждём весь синтез, чтобы начать проигрывание. Как эстафета: бегун стартует, когда палочка уже в воздухе, а не когда предыдущий добежал до скамейки.

### Step 4: tool calling inside the LLM loop

```python
tools = [
    {"name": "get_weather", "parameters": {"location": "string"}},
    {"name": "set_timer", "parameters": {"seconds": "int"}},
]

async for chunk in llm.stream(user_text, tools=tools):
    if chunk.type == "tool_call":
        result = dispatch(chunk.name, chunk.args)
        continue_streaming(result)
    if chunk.type == "text":
        await tts.stream(chunk.text)
```

> 🎒 **На пальцах.** LLM не выполняет `get_weather` сама — она выдаёт кусок с `type == "tool_call"`, а `dispatch` уже дёргает вашу питоновскую функцию и возвращает результат обратно в поток. Заметьте `continue` после вызова: этот кусок не идёт в TTS, потому что озвучивать JSON вслух пользователю не надо. В TTS попадает только `chunk.type == "text"`.

### Step 5: interruption handling

```python
tts_task = asyncio.create_task(tts_loop())
while True:
    chunk = await mic.get()
    if vad(chunk):
        tts_task.cancel()
        await speaker.stop()
        await new_turn()
        break
```

> 🎒 **На пальцах.** `tts_task.cancel()` — это и есть barge-in одной строкой. Пока ассистент говорит, микрофон продолжает слушать, и первый же речевой чанк убивает задачу синтеза. Важен порядок: сначала отменяем генерацию, потом глушим динамик, и только затем начинаем новый turn — иначе в колонку успеет уйти уже отрендеренный хвост фразы.

## Use It

Смотрите `code/main.py` — там рабочая симуляция, которая связывает все семь компонентов на модельных заглушках, так что форму пайплайна видно даже без железа. Для настоящей реализации замените заглушки на:

- `silero-vad` (`pip install silero-vad`)
- `deepgram-sdk` или `openai-whisper`
- `openai` (`gpt-4o`) или `anthropic`
- `kokoro` или `cartesia`
- `sounddevice` для ввода-вывода

> 🎒 **На пальцах.** Заглушки нужны не для лени, а чтобы отладить стыки. Все семь компонентов общаются через простые типы — массивы аудио, строки, токены, — поэтому заменять их можно по одному. Сначала поставьте настоящий VAD, убедитесь, что тайминги сходятся, и только потом трогайте STT.

## Pitfalls

- **Logging PII forever.** Аудио целого turn — это персональные данные почти в любой юрисдикции. Хранение 30 дней, шифрование на диске.
- **No barge-in.** Пользователи будут перебивать. Ваш ассистент обязан замолкать.
- **TTS that blocks.** Синхронный TTS блокирует event loop. Используйте async или отдельный поток.
- **No tool-call error handling.** Инструменты падают. LLM должна получить обратно ошибку, попробовать ещё раз и потом аккуратно деградировать.
- **Overzealous hallucination filters.** Перефильтруете — ассистент будет твердить «я не могу с этим помочь». Недофильтруете — скажет что угодно. Калибруйте на отложенной выборке.
- **No wake-word option.** Постоянно включённый микрофон — риск по приватности. Добавьте гейт по ключевому слову (Porcupine или openWakeWord).

> 🎒 **На пальцах.** Третий пункт ловит почти всех новичков. Синтез одной фразы занимает, скажем, 300 мс процессорного времени; если вызвать его обычным `tts.speak(text)` внутри асинхронного цикла, на эти 300 мс замирает всё — включая чтение микрофона. То есть barge-in из пятого шага перестаёт работать ровно тогда, когда он нужен.

## Exercises

1. **Easy.** Запустите `code/main.py`. Он симулирует один полный turn от начала до конца на заглушках и печатает latency по этапам.
2. **Medium.** Замените заглушку STT на настоящую модель Whisper и прогоните заранее записанный `.wav`. Замерьте WER и сквозную задержку.
3. **Hard.** Добавьте вызов инструментов: реализуйте `get_weather` (любой API) и `set_timer`. Пропустите LLM через инструменты и проверьте, что на фразу «поставь таймер на 5 минут» срабатывает нужная функция, а голосовой ответ это подтверждает.

> 🎒 **На пальцах.** Подсказка ко второму заданию: считайте задержку не одним числом, а по этапам, как это делает `main.py`. Скорее всего у вас получится что-то вроде «VAD 500 мс, STT 400 мс, LLM 600 мс, TTS 250 мс» — сумма далеко за 800 мс. Дальше начинается самое полезное: посмотреть, какие из этих этапов можно запускать внахлёст, а не по очереди.

## Key Terms

| Term | What people say | What it actually means |
|------|-----------------|-----------------------|
| Turn | Круг «пользователь плюс ассистент» | Одна речь пользователя в границах VAD плюс один ответ LLM-TTS. |
| Barge-in | Перебивание | Пользователь заговорил, пока ассистент говорит; ассистент замолкает. |
| Wake word | «Эй, ассистент» | Детектор короткого ключевого слова; Porcupine, Snowboy, openWakeWord. |
| End-pointing | Конец turn | Решение по VAD плюс минимальной тишине, что пользователь договорил. |
| Pre-roll | Буфер до речи | Держим 200-400 мс аудио до срабатывания VAD, чтобы не отрезать первое слово. |
| Tool call | Вызов функции | LLM выдаёт JSON; рантайм вызывает функцию; результат возвращается в тот же цикл. |
