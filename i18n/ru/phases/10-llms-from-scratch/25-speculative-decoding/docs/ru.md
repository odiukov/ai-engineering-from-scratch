# Speculative decoding и EAGLE

> Чтобы фронтирная LLM выдала один токен, нужен полный forward pass по миллиардам параметров. И этот проход чудовищно избыточен: почти всегда модель поменьше угадывает следующие 3-5 токенов правильно, а большой модели остаётся лишь *проверить* догадку. Когда догадка верна, вы получили 5 токенов по цене одного. Speculative decoding (Leviathan et al. 2023) сделал это математически точным, а EAGLE-3 (2025) поднял долю принятия до ~4.5 токена на одну проверку — ускорение в 4-5 раз при том же распределении на выходе.

**Type:** Build
**Languages:** Python (with numpy)
**Prerequisites:** Phase 10 Lesson 12 (Inference Optimization), Phase 10 Lesson 04 (Pre-training Mini-GPT)
**Time:** ~75 minutes

## The Problem

Пропускная способность декодирования у модели класса 70B на H100 обычно 40-80 токенов в секунду. Каждый токен требует полного forward pass с чтением всех весов модели из HBM. Уменьшить модель нельзя — изменится выход. Увеличить размер батча сверх памяти тоже нельзя. Вы в тупике — если только не научитесь выдавать больше одного токена за проход.

Авторегрессивная генерация выглядит принципиально последовательной: `x_{t+1} = sample(p(· | x_{1:t}))`. Но возможность для параллелизма тут есть. Если бы у вас был дешёвый предсказатель, который говорит «следующие 4 токена, скорее всего, [a, b, c, d]», вы могли бы проверить все 5 позиций за **один forward pass большой модели** и принять самый длинный совпавший префикс.

Leviathan, Kalai, Matias (2023, «Fast Inference from Transformers via Speculative Decoding») сделали это точным при помощи хитрого правила принятия/отказа, которое сохраняет распределение целевой модели. То же самое распределение на выходе, только в 2-4 раза быстрее.

> 🎒 **На пальцах.** Ключ в слове «избыточен». На декодировании GPU почти всё время не считает, а ждёт: она тащит из памяти десятки гигабайт весов ради одного-единственного токена. Прогнать через те же веса сразу 5 токенов стоит практически столько же — вот эту дармовую ёмкость speculative decoding и утилизирует.

## The Concept

### The Two-Model Setup

- **Target model** `M_p`: большая, медленная, качественная модель, сэмплы которой вам на самом деле нужны. Распределение: `p(x)`.
- **Draft model** `M_q`: маленькая, быстрая модель похуже. Распределение: `q(x)`. В 5-30 раз меньше.

За один шаг:

1. Draft-модель авторегрессивно предлагает `K` токенов: `x_1, x_2, ..., x_K ~ q`.
2. Target-модель делает ОДИН forward pass сразу по всем `K+1` позициям параллельно и выдаёт `p(x_k)` для каждого предложенного токена.
3. Принимаем или отвергаем каждый токен слева направо по правилу модифицированного rejection sampling, описанному ниже. Принимаем самый длинный совпавший префикс.
4. Если какой-то токен отвергнут, сэмплируем ему замену из скорректированного распределения и останавливаемся. Иначе сэмплируем один бонусный токен из `p(· | x_1...x_K)`.

Если черновик угадал идеально, вы получаете K+1 токен за один проход target-модели. Если черновик ошибся уже на первой позиции — только 1 токен.

> 🎒 **На пальцах.** Разберите крайние случаи при `K = 4`. Всё угадано — 5 токенов за один большой проход. Ошибка на первом токене — 1 токен, и вы вдобавок впустую прогнали 4 шага черновика. Именно поэтому качество draft-модели решает всё: между «5 за проход» и «1 за проход» разница в пять раз.

### The Exactness Rule

Speculative decoding **доказуемо эквивалентен по распределению сэмплированию из p**. Правило отказа:

```
For each drafted token x_t:
    r ~ Uniform(0, 1)
    if r < p(x_t) / q(x_t):
        accept x_t
    else:
        sample replacement from residual: (p - q)+ / ||(p - q)+||_1
        stop
```

где `(p - q)+` обозначает положительную часть поточечной разности. Когда черновик и target согласны (`p ≈ q`), принятие происходит почти всегда. Когда они расходятся, остаточное распределение строится так, что итоговый сэмпл всё равно ровно из `p`.

**Greedy case.** При сэмплировании с temperature=0 достаточно проверить `argmax(p) == x_t`. Совпало — принимаем; не совпало — выдаём `argmax(p)` и останавливаемся.

> 🎒 **На пальцах.** Возьмите конкретные числа: черновик уверен в токене на `q = 0.5`, а target даёт ему `p = 0.9`. Отношение `p/q = 1.8`, значит `r < 1.8` выполняется для любого `r` из отрезка от нуля до единицы — принимаем всегда. Обратный случай `q = 0.8, p = 0.2` даёт отношение 0.25 — примем лишь в четверти случаев, а в остальных сэмплируем замену из остатка.

> 🎒 **На пальцах.** Слово «доказуемо» тут не для красоты: остаточное распределение `(p - q)+` подобрано ровно так, чтобы суммарная вероятность выдать каждый токен совпадала с `p` точь-в-точь. То есть вы не размениваете качество на скорость — выход неотличим от честного сэмплирования из большой модели, что мы и проверим в первом задании.

### Expected Speedup

Если доля принятия у draft-модели на уровне отдельного токена равна `α`, то ожидаемое число токенов на один forward pass target-модели:

```
E[tokens] = (1 - α^{K+1}) / (1 - α)        # K = draft length, α in [0, 1]
```

При `α = 0.8, K = 4`: `(1 - 0.8^5)/(1 - 0.8) = 3.36` токена за проход. Один проход target-модели стоит примерно `cost_q * K + cost_p` (K шагов черновика плюс одна проверка). Если `cost_p >> cost_q * K`, то ускорение по пропускной способности составляет `3.36× / 1 = 3.36×`.

Единственный по-настоящему значимый параметр — это `α`, а он целиком определяется тем, насколько черновик согласован с target-моделью. Хороший черновик решает всё.

> 🎒 **На пальцах.** Формула — это просто сумма геометрической прогрессии: чтобы дожить до k-го токена, надо выиграть подряд k раз с вероятностью α. Подставьте `α = 0.5, K = 4` и получите всего 1.94 токена за проход, а `α = 0.9` даёт 4.1. Разница между посредственным и хорошим черновиком — это разница между «почти не ускорились» и «ускорились вчетверо».

### Training the Draft: Distillation

Случайная маленькая модель — плохой черновик. Стандартный рецепт — дистиллировать её из target-модели:

1. Берём маленькую архитектуру (~1B под target на 70B, ~500M под target на 7B).
2. Прогоняем target-модель по большому текстовому корпусу и сохраняем её распределения следующего токена.
3. Обучаем черновик по KL-дивергенции против распределения target-модели (а не против истинных токенов).

Результат: `α` обычно 0.6-0.8 на коде и 0.7-0.85 на обычном разговорном тексте. Ускорения в продакшене 2-3 раза.

> 🎒 **На пальцах.** Третий пункт — самый важный и самый неочевидный. Черновик учат не «писать правильный текст», а «ошибаться там же, где ошибается большая модель». Обучение на истинных токенах дало бы модель, которая расходится с target на всех спорных местах, а именно на них и падает α.

### EAGLE: Tree Drafting + Feature Reuse

Li, Wei, Zhang, Zhang (2024, «EAGLE: Speculative Sampling Requires Rethinking Feature Uncertainty») заметили в стандартном speculative decoding две неэффективности:

1. Черновик делает K последовательных шагов, каждый — полным стеком. Но черновик мог бы переиспользовать признаки (скрытые состояния) target-модели с последней проверки: target уже посчитал богатые представления, которые черновик выводит заново с нуля.
2. Черновик выдаёт линейную цепочку. Если бы он выдавал *дерево* кандидатов (в каждом узле несколько догадок), один forward pass target-модели мог бы проверить сразу несколько путей-кандидатов через древовидную маску внимания и выбрать самую длинную принятую ветку.

Что меняет EAGLE-1:
- Вход черновика — финальное скрытое состояние target-модели на позиции t, а не сырые токены.
- Архитектура черновика — один декодерный слой трансформера, а не отдельная маленькая модель.
- Выход — дерево из K = 4-8 кандидатов на каждом уровне, глубина 4-6.

EAGLE-2 (2024) добавляет динамическую топологию дерева: дерево становится шире там, где черновик не уверен, и остаётся узким там, где уверен. Это поднимает `α_effective`, не увеличивая стоимость проверки.

EAGLE-3 (Li et al. 2025, «EAGLE-3: Scaling up Inference Acceleration of Large Language Models via Training-Time Test») убирает жёсткую привязку к признакам верхнего слоя и обучает черновик новым лоссом «симуляции на тесте»: черновик учится на выходах, соответствующих распределению target-модели во время инференса, а не на распределении teacher forcing. Доля принятия растёт с 0.75 (EAGLE-2) до 0.82 (EAGLE-3), а среднее число токенов на проверку — с 3.0 до 4.5.

> 🎒 **На пальцах.** Обычный черновик видит только текст — как человек, который читает написанное и пытается угадать вашу следующую мысль. EAGLE читает скрытое состояние target-модели, то есть подглядывает прямо в её черновые размышления, и потому попадает чаще. Второй трюк ещё проще: вместо одной догадки на каждом шаге черновик выдаёт три, а проверка всё равно стоит один проход.

> 🎒 **На пальцах.** Посчитайте выгоду EAGLE-3 в лоб: 4.5 токена на проверку против 3.0 у EAGLE-2 — это ещё +50 % пропускной способности при том же железе. Достигнуто это одной сменой лосса при обучении черновика: раньше его учили на «идеальных» текстах, а теперь на том, что реально выдаёт target-модель на инференсе, включая её собственные шероховатости.

### Tree Attention Verification

Когда черновик выдаёт дерево, target-модель проверяет его за один forward pass с помощью **древовидной маски внимания** — каузальной маски, которая кодирует топологию дерева, а не просто линию. Каждый токен видит только своих предков по дереву. Проверка по-прежнему один проход и одно матричное умножение; топологическая маска стоит лишь нескольких лишних записей в KV-кэше.

```
        root
       /    \
      a      b
     / \    / \
    c  d   e   f
```

Если `a, b` — конкурирующие кандидаты на первый токен, а `c, d, e, f` — кандидаты на второй, то все шесть позиций проверяются за один forward pass. На выходе — самый длинный префикс вдоль любого из принятых путей.

> 🎒 **На пальцах.** В картинке выше шесть узлов, но обычная цепочка той же глубины дала бы всего два токена. Дерево из шести узлов покрывает четыре разных продолжения длины два, и достаточно, чтобы угадало хотя бы одно. Маска нужна затем, чтобы `c` видел только `a` и корень, но не видел `b`: иначе ветки перемешаются и проверка станет бессмысленной.

### When It Wins, When It Doesn't

**Wins:**
- Чат и автодополнение на предсказуемом тексте (код, обиходный английский, структурированный вывод). Здесь `α` высокая.
- Ситуации, где на декодировании GPU простаивает (фаза, упирающаяся в память). Древовидный черновик занимает свободные FLOPs.

**Loses / no win:**
- Сильно стохастические выходы (творческий текст при высокой температуре). `α` падает к `1/|vocab|`.
- Батчевая выдача при очень высокой параллельности — батчинг и так забивает FLOPs, места под проверку дерева не остаётся.
- Совсем маленькие target-модели, где черновик уже не сильно меньше.

В продакшене обычно сообщают об ускорении по часам в 2-3 раза на чате, 3-5 раз на генерации кода и почти нулевом на творческом письме.

> 🎒 **На пальцах.** Обратите внимание на второй пункт «проигрышей» — он неочевиден. Speculative decoding живёт за счёт простаивающих FLOPs, а большой батч их уже занял. Поэтому при обслуживании сотни пользователей одновременно спекуляция может не дать ничего, зато при одном пользователе с длинным ответом она даёт максимум.

## Build It

`code/main.py`:

- Эталонная функция `speculative_decode(target, draft, prompt, K, temperature)`, которая реализует точное правило отказа и проверяет, что распределение target-модели сохраняется (эмпирическая KL < 0.01 против обычного сэмплирования из target).
- Черновик в стиле EAGLE, который строит дерево глубины K с ветвлением по top-p.
- Построитель древовидной маски внимания, выдающий правильный каузальный паттерн для проверяющей модели.
- Стенд для измерения доли принятия, который гоняет оба варианта на крошечной языковой модели (дистиллируем GPT-2-small из target GPT-2-medium).

```python
def speculative_step(p_target, q_draft, K, temperature=1.0):
    """One round of speculative decoding. Returns list of accepted tokens."""
    # 1. Draft K tokens
    draft_tokens = []
    q_probs = []
    state = draft_state_init()
    for _ in range(K):
        probs = softmax(q_draft(state) / temperature)
        t = np.random.choice(len(probs), p=probs)
        draft_tokens.append(t)
        q_probs.append(probs[t])
        state = draft_step(state, t)

    # 2. Target computes p at every drafted position + 1 extra
    p_probs_all = target_forward_batched(p_target, draft_tokens, temperature)

    # 3. Accept/reject left-to-right
    accepted = []
    for k, tok in enumerate(draft_tokens):
        r = np.random.uniform()
        if r < p_probs_all[k][tok] / q_probs[k]:
            accepted.append(tok)
        else:
            residual = np.maximum(p_probs_all[k] - q_probs[k], 0)
            residual /= residual.sum()
            accepted.append(np.random.choice(len(residual), p=residual))
            return accepted
    # 4. All K accepted → sample bonus token from target
    accepted.append(np.random.choice(len(p_probs_all[-1]), p=p_probs_all[-1]))
    return accepted
```

> 🎒 **На пальцах.** Проследите за возвратами из функции: при отказе на шаге `k` идёт немедленный `return`, и весь хвост черновика выбрасывается. Строка `residual /= residual.sum()` — это та самая нормировка `(p - q)+`, без неё сумма вероятностей не равна единице и `np.random.choice` просто упадёт с ошибкой.

> 🎒 **На пальцах.** Обратите внимание на `target_forward_batched`: это единственный дорогой вызов во всей функции, и он ровно один на весь цикл. Всё остальное — K дешёвых шагов черновика и немного арифметики. Вот и вся экономика метода в одной функции.

## Use It

- **vLLM** и **SGLang** поставляются с полноценным speculative decoding. Флаги: `--speculative_model`, `--num_speculative_tokens`. Поддержка EAGLE-2/3 включается флагом `--spec_decoding_algorithm eagle`.
- **NVIDIA TensorRT-LLM** нативно поддерживает деревья Medusa и EAGLE.
- **Reference draft models**: `Qwen/Qwen3-0.6B-spec` (черновик для Qwen3-32B), `meta-llama/Llama-3.2-1B-Instruct-spec` (черновик для 70B).
- **Medusa heads** (Cai et al. 2024, «Medusa: Simple LLM Inference Acceleration Framework with Multiple Decoding Heads»): вместо draft-модели к самой target-модели добавляют K параллельных предсказательных голов. Разворачивать проще, доля принятия чуть ниже, чем у EAGLE.

> 🎒 **На пальцах.** Практический порядок действий такой: сперва попробуйте готовый черновик из списка выше — это две строки в команде запуска и ускорение вдвое за вечер. Medusa требует дообучить target-модель, EAGLE — обучить специальный черновик под неё; это недели работы ради перехода с 2 раз к 4. Начинайте с дешёвого варианта и меряйте свою `α` до того, как вкладываться.

## Key Terms

| Term | What people say | What it actually means |
|------|-----------------|------------------------|
| Target model | "The big model" | Медленная качественная модель, сэмплы которой вам нужны (распределение p) |
| Draft model | "The speculator" | Маленький быстрый предсказатель (распределение q); в 5-30 раз меньше |
| K / draft length | "Look-ahead" | Число спекулятивных токенов на одну проверку |
| α / acceptance rate | "Hit rate" | Вероятность на токен, что предложение черновика будет принято |
| Exact rejection rule | "The accept test" | Сравнение r < p/q, которое сохраняет распределение target-модели |
| Residual distribution | "Corrected p-q" | (p - q)+ / ||(p - q)+||_1 — распределение, из которого сэмплируют при отказе |
| Tree drafting | "Branching speculation" | Черновик выдаёт дерево кандидатов, которое проверяется за один проход с древовидной маской внимания |
| Tree attention mask | "Topological mask" | Каузальная маска, кодирующая топологию дерева: каждый узел видит только своих предков |
| Medusa heads | "Parallel heads" | K дополнительных предсказательных голов на самой target-модели; отдельной draft-модели нет |
| EAGLE feature reuse | "Hidden-state draft" | На вход черновику идёт последнее скрытое состояние target-модели, а не сырые токены, что позволяет его ужать |
| Test-time simulation loss | "EAGLE-3 training" | Обучение черновика на выходах, соответствующих распределению target-модели на инференсе, а не teacher forcing |
