# Native Sparse Attention — разреженный attention от DeepSeek (NSA)

> На 64 тысячах токенов attention съедает 70-80 % задержки декодинга. План починить это есть у каждой лаборатории открытых моделей. NSA от DeepSeek (лучшая статья ACL 2025) — тот план, который прижился: три параллельные ветки attention — сжатые крупнозернистые токены, выборочно сохранённые мелкозернистые токены и скользящие окна для локального контекста — соединённые обучаемым гейтом. Он согласован с железом (дружелюбен к ядрам), обучается нативно (работает в претрейне, а не прикручивается на инференсе) и на декодинге 64k идёт быстрее FlashAttention, при этом не уступая полному attention по качеству. В этом уроке мы строим все три ветки целиком и показываем, почему такая разреженность дифференцируема от начала до конца.

**Type:** Build
**Languages:** Python (stdlib)
**Prerequisites:** Phase 7 · 12 (KV cache, flash-attention), Phase 7 · 15 (attention variants), Phase 10 · 16 (differential attention)
**Time:** ~60 minutes

## Learning Objectives

- Назвать три ветки attention в NSA и то, что ловит каждая из них.
- Объяснить, почему NSA «нативно обучаем» там, где прежние методы разреженного attention работали только на инференсе.
- Посчитать экономию вычислений NSA против полного attention на контексте 64k как функцию от размера блока сжатия и top-k выборки.
- Реализовать объединение трёх веток на stdlib Python на короткой синтетической последовательности и убедиться, что веса гейта ведут себя разумно.

## The Problem

Полный attention на длине последовательности N стоит `O(N^2)` времени и `O(N)` KV-кэша на слой. На 64 тысячах токенов цифры по вычислениям и пропускной способности памяти катастрофические. Теоретическая оценка, измеренная в статье про NSA: на 64k attention отвечает за 70-80 % всей задержки декодинга. Всё, что ниже по течению — TTFT, токены в секунду, стоимость за миллион токенов — определяется стоимостью attention.

> 🎒 **На пальцах.** 70-80 % — это значит, что даже если вы бесплатно ускорите весь остальной трансформер в бесконечное число раз, модель станет быстрее максимум в 4 раза. Всё остальное — MLP, нормировки, эмбеддинги — вместе занимает всего пятую часть времени. Оптимизировать надо там, где горит, а на длинном контексте горит именно attention.

Разреженный attention — очевидный ответ. Прежние попытки делятся на две корзины. Разреженность с фиксированным шаблоном (скользящее окно, strided, блочно-локальная) выбрасывает информацию и проваливается на задачах дальнего поиска. Разреженность на этапе инференса (обрезка KV-кэша, H2O, StreamingLLM) применяется к модели, предобученной на плотном attention, и отыгрывает лишь долю потенциального ускорения, потому что модель никогда не просили пропускать информацию через разреженный шаблон.

Native Sparse Attention (Yuan et al., DeepSeek + PKU + UW, лучшая статья ACL 2025, arXiv:2502.11089) делает и то и другое: шаблон разреженности, который модель выучивает во время претрейна, реализованный как согласованный с ядрами алгоритм, реально дающий экономию вычислений на инференсе. Через два года NSA или его прямой потомок будет attention по умолчанию в каждой передовой long-context модели.

> 🎒 **На пальцах.** Разница между двумя корзинами примерно как между «спроектировать дом с лестницей» и «прорубить лестницу в готовом доме». Обрезка KV-кэша выкидывает токены, на которые модель училась опираться, — отсюда и потери качества. NSA учит модель с самого начала жить на разреженности, и тогда выброшенные токены ей просто не нужны.

## The Concept

### Three parallel branches

Для каждого запроса NSA прогоняет attention три раза, по трём разным представлениям KV-кэша:

1. **Compressed branch.** Токены группируются в блоки размера `l` (обычно 32 или 64). Каждый блок сжимается в один суммарный токен маленькой обучаемой MLP. Запрос идёт по этим сжатым токенам и получает крупнозернистую картину всей последовательности.

2. **Selected branch.** По оценкам attention из сжатой ветки находятся top-k блоков, самых релевантных текущему запросу. Мелкозернистые (несжатые) токены из этих блоков загружаются, и запрос идёт по всем ним. Считайте attention сжатой ветки сигналом маршрутизации для этого выбора.

3. **Sliding-window branch.** Запрос смотрит на последние `W` токенов (обычно 512) ради локального контекста. Эта ветка ловит богатые структурой короткие связи (синтаксис, локальная кореференция), которые две другие могут пропустить.

Выходы трёх веток объединяются обучаемым гейтом на каждую позицию:

```
out = g_cmp * out_cmp + g_sel * out_sel + g_win * out_win
```

`g_cmp, g_sel, g_win` — веса гейта, выданные маленькой MLP по запросу. Они не обязаны суммироваться в 1 — они могут взвешивать ветки независимо.

> 🎒 **На пальцах.** Три ветки — это три масштаба зрения одновременно: карта страны (сжатая), увеличительное стекло на нескольких важных районах (выбранная) и то, что прямо под ногами (окно). Гейт решает, чему верить на этом конкретном токене: дописывая закрывающую скобку, модель почти всё вложит в `g_win`, а отвечая на вопрос по документу из начала контекста — в `g_sel`.

### Why this is "natively trainable"

Шаг выбора (top-k блоков) дискретен. Дискретные операции рвут поток градиента. Прежние работы по разреженному attention либо пропускали backprop через выбор (что ограничивало обучение), либо использовали непрерывные релаксации, которые не давали настоящей разреженности на инференсе.

NSA обходит это: attention сжатой ветки САМ ПО СЕБЕ является дифференцируемым крупнозернистым attention по всей последовательности. Операция top-k просто переиспользует лучшие оценки attention из сжатой ветки, чтобы решить, какие мелкозернистые блоки загрузить. Градиенты текут через оценки сжатой ветки (которые влияют И на выход сжатой ветки, И на логику выбора), а вклад выбранных блоков в итоговый выход тоже дифференцируем. Недифференцируемая операция `top_k` не делает ничего в прямом графе вычислений — она лишь управляет тем, какие блоки поднимутся из памяти.

Именно поэтому NSA можно использовать в претрейне от начала до конца. Модель учится маршрутизировать информацию через три ветки совместно, порождая разреженный шаблон, который на инференсе действительно даёт обещанное ускорение.

> 🎒 **На пальцах.** Хитрость здесь в том, что `top_k` работает не как вычисление, а как адрес: он выбирает, что читать из памяти, но сам в формулу выхода не входит. Сравните с обрезкой KV-кэша, где выброшенный токен просто исчезает и градиент до него не доходит. Здесь же оценки, по которым делался выбор, живут в сжатой ветке — и через них градиент спокойно доходит до логики маршрутизации.

### Hardware-aligned kernel

Ядро NSA спроектировано под иерархию памяти современных GPU. Ядро загружает запросы группами GQA (внешний цикл), подтягивает соответствующие разреженные KV-блоки на группу (внутренний цикл) и считает attention на SRAM. Поскольку каждая группа запросов видит одни и те же выбранные блоки (выбор идёт на группу запросов, а не на отдельную голову), загрузки KV размазываются по всей группе. Арифметическая интенсивность остаётся высокой.

В статье приводятся Triton-ядра, работающие в 9 раз быстрее FlashAttention на декодинге 64k, причём коэффициент ускорения растёт с длиной последовательности. Прямое и обратное ядра предоставлены оба.

> 🎒 **На пальцах.** Ключевое слово — «на группу, а не на голову». Если бы каждая из 32 голов выбирала свои 16 блоков, пришлось бы поднять из памяти до 512 разных блоков. При 4 группах GQA это 64 блока — в восемь раз меньше трафика при том же числе голов. Экономия здесь идёт не от математики, а от того, что соседние головы читают одно и то же.

### The compute budget

Пусть `N` — длина последовательности, `l` — размер блока сжатия, `k` — число блоков в top-k выборке, `w` — скользящее окно, `b` — размер выбранного блока (обычно равен `l`).

- Compressed branch: `O(N/l)` ключей на запрос, то есть `O(N * N / l)` всего.
- Selected branch: `O(k * b)` ключей на запрос, то есть `O(N * k * b)`.
- Sliding branch: `O(w)` ключей на запрос, то есть `O(N * w)`.

Итого: `O(N * (N/l + k*b + w))`.

При `N = 64k, l = 64, k = 16, b = 64, w = 512`: стоимость на запрос — `1000 + 1024 + 512 = 2536 keys`. У полного attention — `64000 keys`. Сокращение вычислений в 25 раз.

При `N = 128k, l = 64, k = 16, b = 64, w = 512`: стоимость на запрос — `2000 + 1024 + 512 = 3536 keys`. У полного attention — `128000 keys`. Сокращение в 36 раз. Выигрыш растёт с длиной последовательности, и в этом весь смысл.

> 🎒 **На пальцах.** Посмотрите, почему выигрыш растёт: при удвоении контекста с 64k до 128k растёт только сжатая ветка (1000 → 2000), а выбранная и оконная остаются ровно теми же (1024 и 512). Полный attention при этом удваивается целиком. Отсюда и 25× против 36× — чем длиннее контекст, тем большая часть работы NSA остаётся постоянной.

### How does it compare

| Method | Differentiable | Real inference speedup | Long-range recall |
|--------|---------------|----------------------|-------------------|
| Только скользящее окно | да | да | проваливается |
| Strided / блочно-разреженный | да | да | частично |
| Обрезка KV (H2O, StreamingLLM) | неприменимо (работает на инференсе) | да | частично |
| MoBA (Moonshot) | частично | да | хорошо |
| NSA | да (нативно) | да (9× на 64k) | не уступает полному attention |

MoBA (Moonshot, arXiv:2502.13189) вышел одновременно и берёт похожий подход «три лучше одного», применяя принцип MoE к блокам attention. NSA и MoBA — две архитектуры, которые надо знать для long-context претрейна образца 2026 года.

> 🎒 **На пальцах.** Читайте таблицу по последней колонке — там и стоит вся ценность. Ускорение умеют давать все строки, но только у NSA стоит «не уступает полному attention» в дальнем поиске, и только у него «да» в первой колонке. Ускорение без качества уже было и не взлетело.

## Build It

`code/main.py` реализует три ветки на короткой синтетической последовательности и показывает:

- MLP сжатия (ради наглядности взят простой mean-pool; настоящая NSA использует обучаемую MLP).
- Выбор top-k блоков по оценкам сжатой ветки.
- Sliding-window attention по последним `w` токенам.
- Объединение через гейт.
- Распечатку числа операций в сравнении с полным attention.

### Step 1: compress tokens into blocks

```python
def compress(K, l):
    n = len(K)
    n_blocks = (n + l - 1) // l
    out = []
    for b in range(n_blocks):
        start, end = b * l, min((b + 1) * l, n)
        block = K[start:end]
        summary = [sum(row[d] for row in block) / len(block) for d in range(len(K[0]))]
        out.append(summary)
    return out
```

> 🎒 **На пальцах.** Вся функция делает одно: усредняет каждый блок из `l` токенов покомпонентно и отдаёт один вектор вместо `l`. При 1024 токенах и `l = 32` из тысячи ключей остаётся 32 — именно во столько раз дешевеет сжатая ветка. Строка `min((b + 1) * l, n)` нужна для хвоста: последний блок может оказаться короче, и делить надо на `len(block)`, а не на `l`.

### Step 2: compressed-branch attention

Считаем softmax-attention запроса против сжатых ключей. Оценки сжатой ветки заодно служат сигналом для выбора top-k.

> 🎒 **На пальцах.** Это и есть самый экономный трюк NSA: одна и та же величина работает и как ответ, и как указатель. Считать отдельную «сеть маршрутизации» не нужно — оценки, которые и так посчитаны, говорят, куда смотреть подробнее. Один расчёт, две работы.

### Step 3: top-k block selection

Берём индексы `k` сжатых блоков с наибольшими оценками. Загружаем исходные несжатые токены из этих блоков и считаем attention по ним.

> 🎒 **На пальцах.** Это как поиск по книге: сперва пробегаете оглавление (сжатые блоки), выбираете четыре главы, а потом читаете эти главы построчно. При `k = 4` и `b = 32` подробно читается 128 токенов из 1024 — восьмая часть текста. Остальные 896 токенов вообще не поднимаются из памяти.

### Step 4: sliding-window attention

Берём последние `w` токенов и считаем по ним обычный attention.

### Step 5: gate + combine

Маленькая MLP по запросу выдаёт три веса гейта. Итоговый выход — взвешенная сумма выходов трёх веток.

> 🎒 **На пальцах.** Гейт — это крошечная сеть, которая по одному вектору запроса выдаёт три числа. Заметьте, что суммироваться в единицу они не обязаны: модель вправе сказать «здесь важна только локальная ветка, остальные глуши» и выдать что-то вроде 0.05, 0.1, 0.9. В отличие от softmax, тут нет обязательства раздать всё внимание целиком.

### Step 6: compute counting

Печатаем число ключей, просмотренных на один запрос, для каждой ветки и суммарно. Сравниваем с `N` (полный attention). На синтетике из 1024 токенов при `l = 32, k = 4, w = 128` NSA видит `32 + 128 + 128 = 288` ключей на запрос против 1024 у полного attention — в 3.5 раза меньше.

> 🎒 **На пальцах.** Разберите 288 по слагаемым: 32 — это сжатые блоки (1024/32), 128 — выбранные токены (4 блока по 32), ещё 128 — окно. На игрушечной длине выигрыш скромный (3.5×), потому что накладные расходы трёх веток заметны. Именно поэтому в реальных конфигах контекст берут от 64k, где та же арифметика даёт 25×.

## Use It

NSA уже работает в собственном пайплайне long-context претрейна DeepSeek. Статус интеграции в публичных стеках инференса на апрель 2026:

- **DeepSeek internal**: нативно, опубликованные веса используют NSA или его наследника DSA (Deepseek Sparse Attention).
- **vLLM**: экспериментальная поддержка NSA в разработке для весов DeepSeek-V3.x.
- **SGLang**: бенчмарки NSA опубликованы; продакшен-путь следует за vLLM.
- **llama.cpp / CPU**: не поддерживается; накладные расходы на разбиение ядра не окупаются на пропускной способности CPU.

Когда тянуться за NSA:

- Претрейн или продолженное обучение с прицелом на контекст от 64k и с серьёзным бюджетом вычислений.
- Инференс собственных long-context чекпоинтов DeepSeek. Их веса нативно рассчитаны на NSA.

Когда не стоит:

- Вы обслуживаете уже обученную модель с плотным attention. Прикрутить NSA без продолженного обучения нельзя.
- Контекст меньше 16k. Накладные расходы трёх веток съедают экономию.
- Интерактивный чат с батчем 1. Декодинг выигрывает по задержке, но только на длинных контекстах.

> 🎒 **На пальцах.** Главное ограничение — «нельзя прикрутить к готовым весам», и вытекает оно прямо из идеи. Модель, обученная на плотном attention, рассчитывает увидеть все токены; включите ей NSA — и она не найдёт того, на что привыкла опираться. NSA надо закладывать до старта обучения, как фундамент, а не как перепланировку.

## Key Terms

| Term | What people say | What it actually means |
|------|----------------|------------------------|
| Compressed branch | "Coarse view" | Attention по усреднённым по блокам ключам; даёт глобальный контекст за O(N/l) ключей на запрос |
| Selected branch | "Top-k blocks" | Мелкозернистый attention по `k` блокам с наивысшими оценками сжатой ветки |
| Sliding window | "Local context" | Attention по последним `W` токенам ради коротких связей |
| Native trainability | "Pre-train with the sparsity on" | Шаблон разреженности выучивается во время претрейна, а не прикручивается на инференсе |
| Compression block size l | "Group size for coarse view" | Сколько токенов сливается в один суммарный; типично 32-64 |
| Top-k | "Blocks to keep" | Число сжатых блоков, чьи несжатые токены будут прочитаны; типично 16 |
| Sliding window W | "Local attention radius" | Обычно 512; меньше — страдает локальная связность, больше — впустую тратятся вычисления |
| Branch gate | "How to mix the three" | Выход MLP на каждую позицию, взвешивающий вклады трёх веток |
| Hardware alignment | "Kernel-friendly sparsity" | Шаблон разреженности выбран так, чтобы реальное GPU-ядро действительно дало теоретическое ускорение |
| DSA | "NSA's successor" | Deepseek Sparse Attention — архитектура, пришедшая после NSA в линейке DeepSeek |
